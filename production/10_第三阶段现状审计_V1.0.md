## 1. 结论摘要

**关系系统从零开始，但周边管道 80% 已就位。**

| 维度 | 现状 | 结论 |
|---|---|---|
| 英雄稳定标识 | `HeroId`（record struct）＋ `HeroDefinition.Id`＋存档字符串化 | ✅ 可直接用（A6 债已清） |
| 关系模型 / 关系存储 | **零**。`src/` 无任何关系类型、方向键、存储或读写入口 | ❌ 必须新建（M1） |
| 关系触发规则 | **零**。仅在 `DecisionFlow` 留了恒 1 的 `B` 因子槽 | ❌ 必须新建（M3） |
| 自主决策接入点 | `DecisionFlow` S1–S6、性格权重、前置校验、可复现随机源齐全 | ✅ 可复用（M2） |
| 日常行动执行 | `DailyLife` 活动集 + 效果注入 + 完成事件 | 🟡 可扩展（加「社交」活动与效果） |
| 经济行为 | `Trade` / `Stall` / `StallService` / `HeroBehaviorService` 均有测试 | 🟡 `HeroBehaviorService` **未接线**（见 R-01） |
| 事件 → 杂谈 | `EventLog` / `ChronicleFeed` / `ChroniclePolicy` / `Main.Emit` 单一出口 | ✅ 可复用（M5） |
| 存档 | DTO + 版本 0,2 + 整份校验 + 原子写 | 🟡 加关系需升版本（M6，P3-D10） |
| UI | 左栏 Roster/按钮、右栏杂谈；左栏几乎占满 | 🟡 只能加**很小**的关系展示（M6） |
| 关系存档 | 零 | ❌ 必须新建（M6） |
| 玩家干预关系 | 零（符合本阶段非目标） | ✅ 本阶段只读展示 |

**一句话：** 第三阶段不是「补一个数值字段」，而是**新建 `Domain/Relationships` 模块**，并把「社交行为 → 关系变化 → 影响后续行为 → 事件回流 → 存读档」接进既有管道。**没有任何现成关系代码要清理，但也没有任何现成关系代码可复用。**

## 3. 现有能力（可复用，精确到文件:行号）

### 3.1 A · 英雄身份与领域模型

| 能力 | 证据 |
|---|---|

| 静态定义不可变；特质/偏好必须为正有限数（CR-1） | `HeroDefinition.cs:20-102` |
| 运行时状态只经方法修改（唯一写者） | `src/Domain/Heroes/HeroState.cs:18-158` |
