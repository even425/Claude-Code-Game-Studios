## 6. 货币 = 新 key 还是新类型？——**这是 M1 第一条设计决策**

**两个选项的对比**：

| | 选项 A：货币 = `Village.Resources["金币"]` 的新 key | 选项 B：`Wallet` 新类型 |
|---|---|---|
| 写入接口 | `Village.Add` / `TrySpend` 已有 | 要新写 `Wallet` 类 |
| 负数防线 | 已有（I12） | 要在新类里**重写一遍** |
| 存档 | `Resources` 已经是字典，**多一项** | 需新字段、新校验 |
| 跨实体的「转账」 | 同一池里两个 key 互转：A 减 + B 增 = 全有或全无 | 需专门 `Transfer(wallet, wallet)` |
| 英雄有「物品」怎么办 | **不能进 Village**——Village 是村庄的，不是英雄的 | 物品必须挂英雄，需要新结构 |
| **与「材料」的语义** | "材料"和"金币"放一起**是否合理**？`TrySpend`("金币", X) 语义上对，但读 `Snapshot()` 不区分池 | 类型分立，**但要维护两套 I12 防线** |
| 复用代码量 | 100% | 0% |

**【建议】选 A**——理由：Village 已经是通用容器；货币和材料**语义同源**（"可花费的、按量计的"）；让"金币"和"材料"在同一个 `Dictionary` 里**最简单**；**新写一个 `Wallet` 类会得到一个 `Village` 的子集**——零增量价值。

**这意味着 M1 的第一条任务**是：**P2-D01 拍板后**，把 `Resources` 从"装材料"扩成"装货币和材料"，**但保持** `Village` 类本身不变（`Add` / `TrySpend` 已经是通用接口）。

物品**不能进 Village**（英雄不属村庄），所以 `HeroDefinition` / `HeroState` 需要挂一个**`Inventory` 字段**（`Dictionary<ItemId, long>`）。**这是 M1 的第二条任务**。
