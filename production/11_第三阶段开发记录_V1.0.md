### 新增文件

| `src/Domain/Relationships/RelationshipBook.cs` | 唯一写者：`Get` / `ValueOf` / `StageOf` / `Apply`（业务键幂等）/ `Snapshot` / `Restore`（全有或全无） |
| `tests/unit/relationships/RelationshipBookTests.cs` | 18 例：方向性、非法输入、幂等、上下界、快照恢复、阶段派生、目标权重恒正 |

### 关键设计落点

- **有向**（I8）：`(A,B)` 与 `(B,A)` 是两个键，`Apply` 不影响另一方向。
- **范围**：构造期拒绝越界（损坏存档）；运行期 `WithDelta` clamp（+2 累计到边界停在 100）。
- **幂等**：`interactionKey` 重复调用返回 `Applied=false`；边界无变化时 `Changed=false`（不产生事件）。
- **原子恢复**：`Restore` 先校验到临时表，任何一条非法都不替换现状。
- **域层纯净**：不 `using Godot`，由 `DomainLayerPurityTests` 守护。

| `src/Main.cs` | `_rng` 注入 `DailyLife`；`SocialTargetCandidates`（在村、非自己）；`SocialPreferenceWeight`（P3-D05 占位）；`OnSocialCompleted` 写关系；`PublishEvent` 对通用「做完了社交」不产条目 |

### 设计选择（与审计的对应）

- **目标在决策时确定**（R-14）：`BeginAction` 在 `DecisionFlow.Step` 内执行，所以目标解析必须在这一层；放到「完成时」会让 M4 的「关系影响行为选择」失去机械落点。
- **关系只改概率**：`targetWeight` 返回必须为正，`TargetWeight` 最差 0.1；没有「因讨厌而不可选」。
- **默认行为不变**：不传 target 委托时，既有活动 `Target = None`，S1–S6 其余逻辑零改动。
- **性格权重**：`HeroDefinition.PreferenceWeights["社交"]` 按性格占位（莽 1.3 / 贪 1.1 / 傲 0.7），采集/建屋仍取 1 —— 不改既有节奏（P3-D05）。

## 4. M3 / M4 / M5 已落地部分

### M3（社交来源）

`Main.OnSocialCompleted`：
- 目标在完成时**再验一次在村** —— 行动途中随队离开则本次社交失败，不改关系、不发事件。
- 双向各自 `+2`（`RelationshipRules.SocialDelta`），业务键 `social:{from}->{to}@{simTime:0.###}`，A→B 与 B→A 各一条。
- 已到 ±100 时 `Changed=false` → 不产生事件（反装饰）。

**待做：** 同队副本成功后对参与双方应用 `+3`（`dungeon:{runId}:{a}->{b}`）与一条聚合 `SquadBonded` 事件。

### M4（关系影响行为）

- `Main` 注入的 `targetWeight` 与 `SocialTargetTests` 用的是**同一函数** `RelationshipRules.TargetWeight`。
- 证据：`tests/unit/relationships/SocialTargetTests.cs`（3 例）—— 同一随机落点下，关系从 0 变成 +100 后选中的社交对象改变；关系 -100 仍可选；固定随机可复现。

### M5（事件与杂谈）

- 新增事件类型 `HeroSocialized` + 状态键 `relationship.value`。
- 关系变化**事件始终进 `EventLog`**（可追溯）；**杂谈只在阶段跨越时**产生条目（P3-D09）：
  - 0 → 1~19（普通→熟识）：`X和Y说上了话。`
  - ≥20（→亲近）：`X和Y处得像老朋友了。`
  - 负向跨档（本阶段无来源）：`X和Y之间有点不太对。`
- 真机 headless 验证（`--daylen=5 --soak`）：第 2 天出现「沙无和渡澜说上了话。」「铁荼和渡澜说上了话。」，无异常。

**待做：** 副本合作聚合事件；`--events` 自检扩展到关系事件；截图证据。
