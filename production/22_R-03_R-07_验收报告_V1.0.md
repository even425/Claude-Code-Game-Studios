## 3. R-03 验收

| 验收项 | 结果 | 证据 |
|---|---|---|
| 抽样时排除自己开的摊 | ✅ | 单测 `SimulateShopping_OwnStallIsExcluded_BuysFromAnotherStall`：Alice 自己有摊 + Bob 有摊 → 成交且 `Seller == Bob` |
| 村里只有自己的摊 → 原因说清楚 | ✅ | 单测 `SimulateShopping_OnlyOwnStall_ReportsSelfTrade`：`Skipped_PrecheckFailed` + Detail「只有自己开着的摊」+ `SkipReason = OnlyOwnStall` |
| 不再被误报成「背包满 / 钱不够」 | ✅ | 同上（原因独立可辨） |
| 旧的「抽到自己的摊」分支已删 | ✅ | 新规则下它永不命中，留着就是死路径 |
| 摊主顺序稳定（可复现） | ✅ | `ListOpenStalls` 改用 `Snapshot()`（按摊主 Id 排序）—— `Dictionary` 遍历顺序不是契约 |

> **改正一处不准确的旧记录**：`15` §7 原写 R-03「价高且村抽 > 0 时自买自卖会损失村抽」。
> **与代码不符** —— `TryBuy` 在算费前就以 `SameHero` 拒了，自买自卖不会成交、也不会损失村抽。
> 真问题原本是**浪费当天的购物机会**。`15` §7 已改。

## 8. 遗留与边界

**本轮未做（有意）**

- **R-05** 掉落率 / 稀有度 / 正式价格 —— 属内容决策；`ILootProvider` 的占位实现是唯一替换点。
- **R-06** 背包摘要超过 2 种物品 —— 明确不顺手做（开发者拍板）。注意它与本轮的行尾标记**共用同一块 248 像素**，将来做 R-06 时要一并考虑。

**已知限制**

- 每日汇总**不点名**；想知道是谁 → 花名册行尾。
- 行尾标记**跨天即消失** —— 这是有意的：昨天的 unmet 需求不该一直挂着。
- 背包正式容量仍是无限，`BagFull` 今天几乎不会命中（规则已钉死并有单测）。
- 自主购物仍然**一次只看一个摊**（v1 限制），本轮未改。
- 摊主自己的摊**永远不会被自己买到** —— 这是「同一个人不能自买自卖」规则的直接后果，
  且现在有了明确的反馈（不再静默浪费机会）。

## 9. 结论

**R-03 与 R-07 验收通过。**

英雄不会再因为抽到自己的摊而白扔掉当天的购物机会；
玩家也能看见谁想买没买成、卡在哪儿 —— 逐个人标在花名册上，
整体情况每天一条汇总进杂谈，不点名、不刷屏。
