## 4. 功能验收

### 4.1 买得成

| 验收项 | 结果 | 证据 |
|---|---|---|
| 玩家能看见所有在开的摊位 | ✅ | 面板标题「摊位（1）」；行含摊主 / 物品 / 库存 / 单价 |
| 玩家能看见谁能买 | ✅ | 候选行「星航 · 金100 · 可买 5 份」 |
| 一次点击买「尽可能多」 | ✅ | 5 份 × 5 金 = 25 金 |
| 摊主收钱、村金库抽成 | ✅ | 摊主金 100→**124**（净得 24）；村金 0→**1**（`floor(25×5/100)` = 1） |
| 买家扣钱、收货 | ✅ | 买家金 100→**75**；背包 0→**5** |
| 摊位库存递减 | ✅ | 5 → **0** |
| 成交进杂谈 | ✅ | 「星航从鲸屿的摊上买走了石料×5，付25金币（鲸屿得24，村抽1）。」 |

### 4.2 买不成

| 验收项 | 结果 | 证据 |
|---|---|---|
| 售罄的摊买不了 | ✅ | `--market`：「售罄后再买=**StallNotOpen**，状态不变=True」 |
| 失败时状态完全不变 | ✅ | 买家金、背包数、摊位库存均未动 |
| 失败当场有回执 | ✅ | 面板回执行（`StallMarketText.Rejected` 对 `BuyOutcome` 全覆盖） |
| 失败**不进杂谈** | ✅ | 杂谈里只有成交条目，没有失败条目 |

### 4.3 候选筛选的三条纪律

| 纪律 | 结果 | 证据 |
|---|---|---|
| 摊主本人不在候选名单 | ✅ | `--market`：「摊主不在=True」 |
| 买得起 0 份的不列 | ✅ | 单测 `Candidates_ExcludesThoseWhoCannotAffordOne` / `...WhoseBagIsFull` |
| 不在场 / 在工地的人不列 | ✅ | 与自主购物判据一致（`HeroBehaviorService` 的「不在场或正在忙」） |

### 4.4 幂等与结算纪律

| 验收项 | 结果 | 证据 |
|---|---|---|
| 成交只有一条结算路径 | ✅ | 面板 → `StallMarketService` → `StallService.TryBuy`（唯一结算入口，I15 四步提交） |
| 手动购买不误伤业务幂等 | ✅ | 传空 `requestId` —— 玩家每点一次是一次独立交易 |
| 结算失败不留半笔账 | ✅ | 继承 `TryBuy` 的 I15 语义；`SellNotOpen` 分支状态不变已验 |

## 8. 遗留与边界

**本轮未做（有意）**

- **R-03** 自摊规则（自主购物抽到自己的摊位）—— 手动购买的自摊已由 `SameHero` 拒绝且摊主不在候选名单；自主购物的抽摊规则本身仍待设计确认。
- **R-05 / T-007** 掉落率 / 稀有度 / 正式价格 —— 属内容决策；`ILootProvider` 的占位实现是唯一的替换点。
- **R-06** 背包摘要超过 2 种物品的展示。
- **R-07** 自主购物的「未成提示」—— 与本轮「手动失败面板内回执」不冲突，仍独立待排期。

**已知限制**

- 正式背包容量仍是无限（`Inventory.Capacity = 0`），「背包装不下」今天不会真触发；规则已钉死并有单测。
- 摊位**不在地图上可视化**（`VillageView` 无摊位绘制）；面板是纯列表。
- 手动购买**不写新的幂等键** —— 连点两次就是买两次（玩家的明确意图），与自动流程的业务幂等是两条路。
- 候选名单按**显示名**排序；同名英雄会并列（当前村庄 3 人，暂不构成问题）。

## 9. 结论

**R-02 验收通过，R-04 同时完成。**

玩家能看见所有摊位、看见每个人能买几份、点一下就买「尽可能多」；
成交的钱、货、库存、村抽逐项对得上，买不成时状态纹丝不动、当场有回执。

这条链与 R-01 咬合：**物品从副本进背包 → 上架 → 别人买走 → 存读档后归属仍正确。**
村庄经营循环里最关键的那一段，现在**在界面上看得见、点得动**了。
