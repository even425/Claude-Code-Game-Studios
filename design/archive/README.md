## 为什么归档

**开发者决定：「完全作废，一切以总纲为准。」**

这些文件建立在一条已被放弃的设计线上。与现基线（`production/异世界村庄经营与英雄冒险游戏_设计基线_V1.2.md`）直接冲突的机制包括：

| 归档中的机制 | 现状 |
|---|---|
| 地球时区作息（`UtcOffset` / `LocalLoginAt` / `PlayHours` / `LoginAt` / `is_online_at`） | **全作废**——英雄总在场 |
| 村庄空档曲线（3 人村庄平均 11.18 小时空档） | **作废** |
| 缺席 `AbsentDays` 与「死亡停机一天」 | **作废**——死亡后复活，无任何代价 |
| 摸鱼 / 不安 `SlackDays` / `RestlessDays` | **作废** |
| 关系用出厂属性（`coalition_multiplier` 按性格计数） | **作废**——基线 §9.3 明文禁止 |
| 六种材料 `material_id` / `squad_max: 4` / `building_tier_max: 5` | **未确认**——基线未拍板 |

**`registry/entities.yaml` 的效力**（D-002 原文）：

> 编码与设计时**不得**引用其中的公式、常数或实体定义。任何看起来「已经定过」的说法，若只在该注册表中有记载，**一律视为未确认**。

## 保留它的理由

这些文件是**一条完整设计线的实录**，记录了当时对「让开发者逐个念原话 → 多 agent 并行产出 → 交叉审查 → 逐条裁定」这套方法的完整实践。其中有价值的东西：

- **开发者原话的存档** —— 各 GDD 的「开发者原话」栏是本次会话里你说过的话的原始记录
- **失效模式的样本** —— 这条线怎么会在「技术侧越来越专业、创作侧越来越空」的方向上跑偏，是有据可查的
- **三条裁定里记录的教训** —— 「例子是方向不是边界」被违反四次的过程
