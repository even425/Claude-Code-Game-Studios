## 4. 3A：手动交易链路（已完成，D-042）

### 决策

- **唯一交易结算责任入口 = `StallService.TryBuy`**：扣款、发货、库存递减、费用结算都在这里；
  `Settlement.ApplyTrade` 保持零调用，留给未来「英雄 ↔ 英雄」直接交易（Main 未注入 `ITradeSettler`）。
- **业务幂等**：`TryBuy(..., requestId)` 非空时同一键只成交一次；键为空 = 旧行为。
  幂等键集合当前在内存，M4 随存档 0.4 持久化。
- 旧 `BuyFromStall` 保留为包装，既有调用与测试行为不变。
- 提交顺序改为「村金库（唯一可能抛）→ 不可失败赋值」，缩小部分结算窗口。

### 改动

| 文件 | 内容 |
|---|---|
| `src/Application/StallService.cs` | `TryBuy` + `BuyOutcome`（11 种结果）+ `BuyAttempt` + `AppliedRequestIds`；`BuyFromStall` 改为包装 |
| `src/Main.cs` | `--trade` 真机自检：测试配给 → 开摊 → 购买 → 重复请求 → 库存不足 → 余额不足 |

## 5. 3B：英雄自主购物接线（已完成，D-043）

### 决策

- **按游戏日触发一次**：`_Process` 每帧调 `RunDailyShoppingIfNeeded`，但
  `DailyShoppingService.LastRunDay == today` 直接返回；同日只对全体英雄各尝试一次。
- 跳过/失败**不写** `LastShoppingDay`，但也不会同日重试；只有成交才写。
- 不新增随机源：仍走 `Main._rng` → `HeroBehaviorService`。
- **只有成交才发事件** `TradeCompleted`（buyer/seller/item/qty/amount；状态键 hero.wallet/hero.bag，
  村费 >0 时加 village.resource）；跳过/失败不发事件。

### 改动

| 文件 | 内容 |
|---|---|
| `src/Application/DailyShoppingService.cs`（新增） | 按游戏日闸门；`RunDay` 同日第二次返回空 |
| `src/Main.cs` | `_dailyShopping` 接线；`RunDailyShoppingIfNeeded`；`EmitTradeCompleted`；`--shop` 自检 |
| `tests/unit/application/DailyShoppingServiceTests.cs`（新增） | 6 例：同日成交/同日重复空/跨天再买/无摊跳过/今日已购跳过/每英雄一条结果 |

SHOPTEST PASS

全量测试 **435 / 435**，构建 0 错误。

### 边界

未改存档格式（`LastShoppingDay` / requestId 幂等键 / 摊位仍未落盘）；无正式购买 UI；
读档后的“不重复购物 / 摊位一致”属 M4。
