## Summary

每隔一段日子，会有**一辆不属于这个村子、也不属于这个世界的车**停在村口。
它不打仗、不掉东西、不进防护罩。它做一件很具体的事：
**它收材料。**

来的那天，村庄材料池里的石料、泥土、布匹、木料、杂物、铁料都能卖出去，
卖价是外面定的，村长改不了。村民把材料搬到自己**已经登记好的摊位**上卖，
**这是唯一的通道**——村长从每一笔里抽走抽成（`economy-and-stalls.md` F3，一行不改）。

**所以这一天，村长的金库会真正地鼓起来，而抽成率第一次有了着落。**
承裁定 ⑪，金库的两条出口是**召唤收费**与**升级吃钱**——商队是那两条出口的第一笔进账。

**但这一天有一个硬上限，而它才是这个事件真正的内容：**
商队**只停几个钟头**，只收**一定的量**。
摊位号是**先登记先得**（#8 E12 不变），**而登记窗口在开市之前就已经关了**。

于是裁定 ⑰（「玩家不能改写村民作息」）在这里第一次**变成一个痛**：
> **他们不能为商队调整上线时间。所以那些此刻不在线的人，连登记都来不及。**
> 他们不是「错过了一笔买卖」，他们是**这一轮完全不参与**，而且**没有补差价的那一天**。

村长的全部权力只有一个：**这一次，开不开市。** 价格不由他定，摊位号不由他定，
来多少车不由他定。**他能做的只是按一下开关——而那正是裁定 ② 里那个「只以村长身份出面」的人。**

## Overview

某天杂谈里多一条：「听说有商队要过村。」没有日期，也没有方向——但它把接下来几天填满了。

三天后，花名册侧栏多出一行：**「后天 · 上午 · 村口 · 收料」**。
从那一刻起到开市之前，是**登记**的时间：想卖材料的人去领一个摊位号，
**先登记先得**（`economy-and-stalls.md` E12 一字不改）。**登记窗口在开市前半天关闭。**

开市那天上午，商队的车停在村口。摊位上摆着的是**村庄材料池里的东西**——
石料、泥土、布匹、木料、杂物、铁料，六样都能卖（裁定 ⑨）。价格是外面定的，
村长改不了；能改的是**抽成率**，而那是每笔成交时自动发生的（#8 F3）。

卖完一定的量，车就走了。**没有人能拦住它，也没有人能让它多留一会儿。**
没有破口、没有磨损、没有建筑损坏——**这一天唯一会消失的东西是材料**，而材料可以再跑一趟副本挣回来。

## Player Fantasy

**主要服务的 MDA Aesthetics：Discovery（发现）+ Challenge（抉择式挑战），辅以 Narrative。**

- **Challenge 不是操作挑战。** 玩家点不到任何交易按钮。
  挑战是**时机的**：「这一次他们赶得上吗」——但裁定 ⑰ 已经把答案封死了，
  **玩家改不了作息**。所以 Challenge 不来自「安排」，**来自「眼睁睁看完」**。
  这与兽潮的 Challenge（排班式焦虑）**不是同一种东西**。
- **Discovery 是主快感。** 玩家在杂谈里读到「后天上午」，然后在心里数谁上午在线，
  数出来的结果通常不好看——**在线的那几个，往往正好是摊子流水最好的那几个**，
  而他们其中有人会想「材料全卖了，村子还盖不盖」。
  **这条推断链是玩家自己走的，系统一个提示都不给。**
- **Narrative**：商队里的人**也在别的地方「玩游戏」**。
  他们看见这儿有罩子、有摊位、有村长站在旁边抽钱，会问一句——
  而村长**不能说「我是 GM」**（裁定 ②），只能说「我们村就是这样」。
  **这场面是设定本身最锋利的一次兑现。**

**SDT 校验**
- **Autonomy（对村民）**：卖不卖、卖多少、登记不登记，全是他们自己的事（R4）。
  玩家的自主性在**时机的知情**与**开不开市**。
- **Competence（对玩家）**：「谁那个钟点在、谁手里有货」是可积累的知识，
  且**它可以通过杂谈与花名册积累**，验证成功的那一刻是核心快感。
- **Relatedness**：商队来一次，村庄第一次与**村庄以外的人**打交道。
  这是 `game-brief.md`「村庄是活的」从**内部循环**走到**对外**的一步。

**Anti-reference**：不要做成《星露谷》那种「一年一度的节日集市」——
限定天数、限定摊位、限定时间的封闭式活动容器。
**商队不是节日。它是一辆路过的车，它不关心你的节日。**

**Feel Reference**：《Unexplored》/《Dorfromantik》里「有人从你身边路过」的那种静默——
不为你停留，不解释自己，拿走它要拿的，走掉。
**Anti-reference ②**：不要做成《黑暗之光》式的限时折扣弹窗。**限时是真的**（窗口会关），但**它不是营销**。

### § B · 调度：**为什么商队的调度逻辑与兽潮本质不同**

> **编排者要求正面回答这一问。答案是三条，每条都可测。**

### B1 · 兽潮的调度是「**排班**」，商队的调度是「**行程**」

兽潮的钟点**是被村庄挑出来的**（`beasts-and-raids.md` F2）：
排除与上两次近邻的钟点、排除到场者性格构成重复的钟点。
**它的目的很明确——制造变化，让每潮来的人不一样。**
它本质上是一个**排班问题**：谁在、谁不在、怎么让他们错开。

商队**不挑村庄的任何东西**。它停在哪一天、几点，取决于**它自己的行程**：
> **它必须在一个村庄有人卸货的钟点停，因为它要赶路。**

```
CARAVAN_AT = (NextCaravanDay, CARAVAN_HOUR)     CARAVAN_HOUR 固定 ∈ {08..16}
NextCaravanDay = CurrentCaravanDay + CARAVAN_PERIOD
```

**没有候选集，没有排除规则，没有诊断日志。**
因为**它不筛选任何人**——它跟村庄的作息、村庄的强弱、村庄的等级**零相关**。

> **这条是最重要的反退化保证，而它是免费拿到的：**
> 玩家无法通过养强村庄来钓时段，也无法通过削弱村庄来避开时段。
> **商队的钟点对村庄是一块背景板。**（与兽潮 F2 的「反退化」目标相同，达成手段完全相反。）

### B2 · 兽潮的窗口**长且实时**，商队的窗口**短且一次性**

| | 兽潮 | 商队 |
|---|---|---|
| 时长 | `4.5` 村庄小时（3 波 × 1.5） | **`CARAVAN_HOURS = 3`** 村庄小时 |
| 推进 | 每 `0.25` 村庄小时推一次，读数每 tick 刷新 | **开市瞬间一次算完** |
| 错过 = | 必然破口（三处），材料被啃、罩磨损 | **这一轮完全不参与**，没有任何补偿 |
| 可否中途加入 | 可以（每波名单冻结前） | **不可以**（登记窗口在开市前半天就关了） |

**两条后果**：
1. **`tick = 0.25h` 不是通用件。** 商队的 G5、G6 槽位整体退化为「一次性」。
2. **商队的错过是「不在场」而不是「打输」。** 它没有失败态——它只有**空过**。

### B3 · 兽潮的预警是「**猜**」，商队的预警是「**看表**」

| 拍 | 兽潮 | 商队 |
|---|---|---|
| 1 | 「东边的林子不太平」——**不给任何时刻** | 「听说有商队要过村」——**给日子，不给钟点** |
| 2 | 定更：给出**精确钟点**，进花名册侧栏 | 定更：给出**精确钟点 + 收购清单（哪六样、什么价档）** |
| 3 | — | **开市本身就是第三拍** |

**为什么是三拍**：兽潮是「今天/明天」尺度，所以两拍够。
商队的登记窗口要提前关（`REGISTER_CLOSE_HOURS = 6`），
而杂谈条目在 `chronicle.md` 的可见窗口只有 0.8–5.3 天——
**两拍会让人来不及在登记窗口关之前反应过来。**

> **顺带证伪兽潮复用清单 §🔶-3**：那条写「槽位固定，拍数可变——但需要实例② 证实」。
> **实例② 给出的答案是：拍数必须做成参数，而且兽潮的 2 不是默认值，商队的 3 才是更常见的形状。**

### B4 · 时间线上最要紧的一句

> **裁定 ⑰：玩家不能改写村民作息。**
>
> **所以——他们不能为了商队特意调整上线时间。**
> **他们只能眼睁睁错过：有些人连摊位号都来不及领。**

**这条不是缺陷，这是本实例最值得保留的一条设计。**

- 商队的钟点对**每个村民都不一样**：他是东八区来的，那个钟点是他那边的凌晨三点。
- 村庄时钟**对所有人同时推进**（`time-and-schedule.md`），但**谁在那个钟点上是随机的**。
- 所以**同一个商队，对村庄的 A 是「上午的生意」，对 B 是「半夜的噪音」**。

**玩家唯一能做的**：在杂谈与花名册侧栏里看到日子与钟点，然后在心里数谁那个钟点在。
**数出来的结果他改不了。** 这就是「村庄是活的」的第三次兑现。

> ⚠️ **反面的诱惑（我否掉的）**：给玩家一个「提醒村民上线」的按钮。
> 那会直接推翻裁定 ⑰，且把村庄变成一个**会给你发通知的服务**。
> **本文件不做，也建议永不做**（同 `beasts-and-raids.md` OQ-5 的同一条理由）。

### C2 · 本文件采纳**丙**，并把理由写下来

**商队里的人，也以为自己在打游戏。**

> 他们是从**别的村庄**来的人。他们也有作息、也有脾气、也有自己那边几点上线。
> 他们看见这儿有罩子、有摊位、有一个村长站在旁边从每笔里抽钱，
> 他们会问：「这游戏我们服怎么没有这个。」
> 而村长**不能说「我是 GM」**（裁定 ②），只能以村长身份说「我们村就是这样」。

**四条理由，每条都指向「不发明」**：

1. **零新数据模型。** 他们复用 `summoning.md` 的名字 / 世界 / 性格 / `Power` / `Speed` /
   `LoginAt` / `PlayHours`——**一个字都不新增**。
   他们与本村村民的唯一差别是 **`Home = false` 且不驻留**，他们不进名册。
2. **它一次性回答了「他们为什么知道材料值多少钱」。**
   因为**他们那边也有人卖**。**商品目录不是设计师编的，是另一个村庄的市场。**
3. **它让裁定 ⑨「材料 = 全部可卖」第一次有执行者**（洞二）。
4. **它是核心设定最锋利的一次兑现**：这个世界上**不止一个村庄**，
   而只有你知道那些村庄也是真的。

> ⚠️ **本条是【新增】，且它是一个必须由开发者拍板的设定决定** → **OQ-1**。
> **若开发者裁定商队必须是本土人，本文件立刻阻塞在 `native-folk.md` Q9 上**，
> 且必须先推翻它的 AC-15。**本文件不替 #12 做那个决定。**

### § D · 参与（G4）：**本实例打掉「洞一」的地方**

### D1 · 登记窗口：商队把「先登记先得」推到了它会疼的地方

**#8 的规则一个字不改**（E12：登记失败、提示「没有空位」、不排队、不候补）。
**本文件只加一条时间事实：登记窗口在开市前半天关闭。**

```
REGISTER_OPEN_HOURS = CARAVAN_PERIOD_DAYS × 24 − REGISTER_CLOSE_HOURS
REGISTER_CLOSE_HOURS = 6                       （村庄小时）
```

**平时 vs 商队日的差别，全在这半天**：

| | 平时（#8 现状） | 商队日 |
|---|---|---|
| 登记窗口 | **一整天，站着慢慢挑** | **半天** |
| 想登记的人数 | 少数（大部分人不知道有货可卖） | **几乎所有手里有材料的人** |
| 摊位数 | `StallSlots(tier)` = 4 – 14 | **不变**（商队不新增摊位） |
| 结果 | 几乎从不撞满 | **⚠️ 撞满是常态** |

> **这就是稀缺从哪来的。**
> `economy-and-stalls.md` F4 已经把 `StallSlots` 与人口**明确解耦**
> （40 人村庄仍然只有 14 个摊）。**平时这个解耦不疼，因为没人抢。**
> **商队日它开始疼——因为所有人同时想要它。**

### D2 · 落败者可识别：**这就是 `relations.md` R2/S8 需要而 #8 不给的那个事实**

**本文件生产事实，不写规则。** 事实的形状：

```
CaravanRegistration = [ { HeroId, SlotId, RegisteredAt }  ... ]     // 按登记顺序
TurnAwayList        = [ { HeroId, WantedSlot, TurnedAwayBy ∈ SlotId 的占用者 } ... ]
```

> **关键区别**：#8 的现状是「登记失败，提示『没有空位』，不排队、不候补」——
> **落败者当场走人，没有对手方，也没有记录。**
> `relations.md` Q3 指出的正是这个：**「两人抢一个摊位」这个事实在 #8 里根本不存在。**

**本文件给 `relations.md` 的正是那个缺的东西**：
> **谁被挡在外面、是被谁挡的。**
> 这是一个**事实**，它的产生不需要新规则——
> #8 的规则已经决定谁登记上了，**本文件只需要把没排上的人记下来，并且指出「当时那个号位是谁的」。**

**交给 `relations.md` 的写入**（本文件只写，不读）：

| 落败者 → | 得位者 | 成因 `Cause` | 增量 | 依据 |
|---|---|---|---|---|
| `B → A`（B 落败、A 占着那个号位） | — | **比较** | **`ΔChurn +8`** | `relations.md` F3 的 **S8 行，数值一字不改** |
| `Flags` | — | **置 `竞争` 位（0x08）** | — | 同上 |

**本文件不改 `relations.md` 一个字**，只在 § Dependencies 写反向声明。

> ⚠️ **边界（必须说清楚）**：**「怎么决定谁登记上」是 #8 的规则，本文件不写。**
> **「谁落败了、被谁挡的」是本文件的事实，本文件写。**

### D3 · 反退化：**先登记的人拿不到更多**

**如果先登记就多赚，抢摊就变成了一个纯操作题（「永远第一个去点」），那是退化。**

因此**收购配额与登记顺序无关**：

```
ActiveStalls        = 在「开市时刻」已登记的摊位数（此后不再变化）
PerStallQuota       = floor( IntakeQuota / max(1, ActiveStalls) )
SellablePerStall    = min( PerStallQuota, 该摊位的材料数 )
一个摊位的实际成交 = min( SellablePerStall, 该摊位的买家需求 )
```

| 性质 | 为什么 |
|---|---|
| **早登记不占便宜** | 配额按 `ActiveStalls` **均分**，不按顺序先到先得 |
| **晚登记（开市前）不吃亏** | 只要在窗口关之前登记，配额一样 |
| **开市后登记 = 这一轮没有** | 配额在开市瞬间已经算完 |
| **摊位少的人占便宜** | ⚠️ **这是刻意的反向倾斜**：`ActiveStalls` 越少，人均配额越高。它让「大家都去登记」不是无脑最优解（见 F5 验算） |

### D4 · 登记之后仍然可能颗粒无收

**登记 ≠ 成交。** 三种颗粒无收，各自有不同的读法：

| 情形 | 读法 | 依据 |
|---|---|---|
| **摊主当日不在线** | `IsOnlineAt` 为假 → 当日 `Sales = 0`。**槽位保留**（#8 E5 一字不改） | #8 S3 / E5 |
| **摊主手里没材料** | 材料是**村庄材料池**的，不是他个人的（见 E3 与 OQ-4） | `expedition.md` F6 |
| **买家不够** | 摊位的需求来自**村里在线的人**，不是商队 | § E |

> ⚠️ **第一条最狠**：裁定 ⑰ 意味着一个人可以**登记了摊位号，然后整场都不在线。**
> 他占着号、别人领不到、最后一件没卖出去。
> **这不是 bug，这是「村庄是活的」的字面兑现**——已登记为 **OQ-5**（要不要给登记加一个「当日确认」环节）。

### § E · 经济：**本实例打掉「洞二」的地方**

### E1 · 商队只买，不卖（**这是本文件对 C「村长垄断」原话最直接的兑现**）

> 原话 C：「**玩家 ↔ 村长**：武器店服装店，村长垄断。**唯一的印钞机**」

**结论：商队不向村庄零售任何东西。** 三条理由，逐条指向一条已存在的规则：

| 理由 | 依据 |
|---|---|
| 零售商队 = **第三家店**，直接违反 #8 **B4**「商店只有武器店、服装店，**不新增第三家**」 | `economy-and-stalls.md` B4 / 禁止清单 6 |
| 零售商队会**摧毁村长的垄断**——而垄断是村庄唯一的稳定收入 | 原话 C |
| 只做买方 ⇒ **全项目仍然只有一种货币 `¤`**，`Purse` 的**唯一出口仍然是村长的店** | #8 禁止清单 2 / 层② |

> **这条同时把一个诱惑挡在外面**：「让商队卖稀有货」会在一句话里同时踩到
> 禁止清单第 2（第二种货币）、第 4（寄售/拍卖）、第 5（稀有度）三条。
> **不卖，是最省事也最正确的做法。**

### E2 · 商队买什么：**六种材料，一样不多（裁定 ⑨）**

```
收购清单 = [ 石料, 泥土, 布匹, 木料, 杂物, 铁料 ]     ← expedition.md 的六项，一字不改
```

**本文件不新增任何物品、不新增任何品质分级、不新增任何堆叠规则。**
商品目录第一次不是空的——**因为裁定 ⑨ 已经把目录填满了，只是没有人给它定价。**

> ⚠️ **`expedition.md` 的 OQ-1 目前仍未同步裁定 ⑨。**
> 那份文档问的是「六种材料各自喂给什么」，裁定 ⑨ 答的是「**全部可卖**」，
> 但 `expedition.md` 正文里 OQ-1 仍在「需要拍板」状态。

### E3 · 🔴 一个本文件**不裁决**、但必须写出来的语义问题

> **六种材料是村庄公共物资**（`expedition.md`：`Materials[id]` 是村庄级的池子），
> **而摊位成交的钱归摊主**（#8 F3：`Purse[seller] += SellerNet`）。
>
> **那么：摊主卖的是村庄的材料，钱却进了他自己的口袋。**

**这条在 `expedition.md` F4 有一个近亲**：贪私吞（`Pocketed`）——**他已经这么干了，而且是他的性格表现。**
**商队做的是同一件事的合法版本。**

**本文件不裁决所有权。** 三条候选各自的后果不同：

| 候选 | 后果 | 状态 |
|---|---|---|
| **甲 · 材料归村庄**，卖材料的钱归摊主 | 「公物私卖」。合法化了贪私吞，村庄建造直接受损 | **本文件按此实现**，标【新增】 |
| **乙 · 材料卖的钱归村庄**（`VillageCoin.Stall`），摊主只拿抽成以外的… | 摊主没有动机登记 → **G4 的自愿参与当场失效** | 未采纳 |
| **丙 · 摊主卖的是他自己从副本带回的那一份** | 需要「个人材料背包」，而那是**背包系统**——`game-brief.md` Out of scope | **明确排除** |

> **我按甲实现，理由**：它是唯一不需要新系统的选项，且它让「卖材料 vs 盖村子」成为
> **一个真取舍**（见 G7）。**但它是一条需要开发者点头的设定决定** → **OQ-4（高）**。

### E4 · 抽成：一行不改

```
Commission   = StallPrice × rate                 // #8 F3，一字不改
SellerNet    = StallPrice × Commission           // （实际为 StallPrice − Commission）
VillageCoin.Stall += Commission
Purse[seller] += SellerNet
```

**本文件不新增第二档费率、不新增阶梯、不新增按品类差别**（#8 禁止清单 3）。

**因此裁定 ③ 的硬约束 `rate < 0.231` 在商队日同样成立、同样不可越过**：
抽成定高了，摊主照样不摆摊，商队照样空跑。**商队不豁免任何一条。**

### E5 · 村长的权力（**必答问题二**）

> 裁定 ⑪：金库出口两条——**召唤收费 / 升级吃钱**。
> 裁定 ⑰：不能改作息。裁定 ②：只以村长身份出面。

**结论：村长对商队只有一个开关。**

| 问题 | 答案 |
|---|---|
| **定价权在谁手里？** | **商队。** 村长改不了收购价（本文件的 `ArrivalMark` 是外部给的，**不读村庄任何状态**） |
| **摊位号归谁定？** | **村民自己先登记先得。** 村长不能指定 |
| **车什么时候来？** | **它自己的行程。** 村长不能改 |
| **村长能做什么？** | **`refuse_market`：这一次不开市。** 就这一个 |

```
refuse_market == true  →  商队停在村口，什么都不收，车走。
                           不写材料损失、不写抽成、不写竞争关系、不写摊位易主。
```

> **这是一个反转，而且它是有意的：**
> **村庄经济的价格由外面定，村长只有开关。**
> 这正好解释了为什么 `commission_rate` 是 #8 唯一的调节量、
> 而它**从来管不住价带**（#8 F2 说得很清楚：价带是以 `ShopPrice` 为锚的静态区间）。
> **村长管得住的只有两件事：让不让发生，和从每一笔里抽多少。**

**为什么只有开关而没有「减半征收」之类**：那会新增一档费率（禁止清单 3），
而且会立刻产生一个新的逆向操纵空间（玩家用减半来钓商队下一轮多停）。
**一个开关没有调参空间，因此没有退化空间。**

**开关的说法口径**（裁定 ②：只以村长身份，绝不说「我是 GM」）：
> 「这一趟不开。东西先放着。」

### § F · 后果（G7）

### F1 · 三类后果，一条封顶线

| # | 后果 | 方向 | 封顶 / 保底 |
|---|---|---|---|
| **G7-a** | **村庄材料池减少** | ⚠️ 负 | 单次至多 `IntakeQuota` 份（封顶），**`TotalMaterials` 不可能降到 0 以下** |
| **G7-b** | **`VillageCoin.Stall` 进账** | ✅ 正 | **无上限**（`long`，#8 E16）。封顶在单笔不在总额 |
| **G7-c** | **摊位号易主 → 产生「落败者」** | 🔁 双向 | **关系增量受 `DAILY_CAP` 封顶**（`relations.md` F4），**落败不扣任何钱、不降任何摊位号** |

### F2 · 一条绝对保底（三条都写死，否则「没有硬失败」是空话）

```
if refuse_market:                    本次零后果（车直接走）
TotalMaterials_after ≥ 0              （恒成立，扣减本身按 IntakeQuota 封顶）
建筑集合 / VillageTier / ShieldLevel / 名册    永远不变（商队不碰任何建筑）
关系                                  只增 ΔChurn（竞争位），**永不清除既有 Bond**
```

### F3 · 唯一的长期代价：**卖掉了就得再挣**

**材料没了，可以再跑一趟副本。** 承 `economy-and-stalls.md` 层③（材料是封闭的，
村庄建造 `cost = 30 + tier × 25` 是它的 sink）。

**这一条正是商队的取舍所在**（G7 的设计理由）：

> 摊主卖一份铁料，赚一笔钱，村长的抽成也进一笔——
> **但村庄升级要吃的也是这份铁料。**
>
> **玩家会自己撞上这个矛盾**：抽成率调高 → 摊主更愿意卖 → 材料更快变成钱 →
> 村庄升级卡住。**而钱只有两条出路（召唤收费 / 升级吃钱，裁定 ⑪）。**
>
> **这两条链是咬合的，不是并列的。** 这是本实例与兽潮最大的体感差别：
> 兽潮让你损失材料，商队让你**用材料换钱**，而钱能不能变回村庄，取决于你把它花在哪。

### F4 · 一条不能破的底线：**商队不给东西**

| 商队**不**提供 | 依据 |
|---|---|
| 掉落 | `game-brief.md` Out of scope |
| 稀有度 / 品质分级 | #8 禁止清单 5 |
| 强化 / 分解 | 同上 |
| 装备 | #8 只定价，装备归 #7 |
| 新货币 / 代金券 / 以物易物 | #8 禁止清单 2 + E20「材料不是货币」 |
| 拍卖 / 竞价 / 寄售 / 代售 | #8 禁止清单 4 |
| 护盾修复、罩的维护 | `beasts-and-raids.md` § G 明确「本文件只回答兽潮打出来的印子怎么补」——**同一族材料不许被第二个事件占用** |

### § G · 状态与日程（G5 / G2 的具体读数）

### G1 · 商队日的状态机（**五个态，每个态只有一个出口条件**）

```
IDLE ──(挂榜日到达)──> NOTIFIED ──(定更时刻到达)──> REGISTERING
      ──(登记窗口关闭)──> FROZEN ──(开市时刻)──> OPEN
      ──(配额耗尽 或 开市满 CARAVAN_HOURS)──> CLOSED ──(离村)──> IDLE
```

**没有中途加入、没有提前离开、没有「延长」按钮。** 状态机是单向的。

### G2 · 玩家能看见的四行（**全部在花名册侧栏，不新增面板**）

| 行 | 内容 | 更新 |
|---|---|---|

| **钟点** | 「上午 · 村口」 | 定更后 |
| **收购清单** | 六样材料 + 一个价档词（「这个价」「比平时好些」「压得很低」） | 定更后 |
| **登记状态** | 「已登记：N / 摊位 M 个」 | 登记期间实时 |

> ⚠️ **第三行为什么不写数字**：`chronicle.md` R2 + `expedition.md`「结算明细刻意不显示数字」。
> **价档词是三档，不是数字。** 这与兽潮「不写方向以外的数值」是同一条纪律。

### G3 · 进行中：商队**没有读数面板**

**开市之后，界面上只有一个变化：某个摊位旁边的成交记号在动。**
没有剩余量倒计时、没有进度条、没有「还剩 3 份」。

> **这是本实例对框架最实质的一份证词：**
> **G5 槽位是可选的。** 一个「到达即结算」的事件不需要进行中读数，

> **⚠️ 与 #8 一样，本节以 `P`（村内平均单价）为单位**——`BaseValue` 未定（OQ-E2）。

### F0 · 符号表

| 变量 | 类型 | 范围 | 来源 |
|---|---|---|---|
| `t` | float | ≥ 0 | `AbsoluteHour`，与兽潮 / 远征同一口径 |
| `D` | int | 村庄日 | `chronicle.md` 的 `Day` |
| `ActiveStalls` | int | `1 .. StallSlots` | D3 |
| `IntakeQuota` | int | 派生 | F2 |

### F1 · 材料收购价

```
MatPrice[m]  = MatBase × MatWeight[m] × ArrivalMark
MatBase      = 村内平均单价 P 的 1.0 倍（归一化锚，与 #8 同口径）
MatWeight[m] ∈ 六个正数，由 #8 的 BaseValue 表拥有，本文件不写死值
ArrivalMark  ∈ [0.70, 1.60]          本系统唯一的外部价格杠杆
```

| 变量 | 类型 | 范围 | 来源 | 说明 |
|---|---|---|---|---|
| `ArrivalMark` | float | 0.70 – 1.60 | data | **这一趟的行情**。**外部给的** |
| `MatWeight` | float | 6 项，均 > 0 | **#8（待 OQ-E2）** | 材料之间的相对价。**本文件不写死** |

**`ArrivalMark` 的三条性质（都可测）**：

| 性质 | 为什么 |
|---|---|
| **不读村庄任何状态** | 与兽潮 F2 的「反退化」目标相同：它**不读** `ShieldLevel`、**不读**人口、**不读**村庄等级。**养强村庄钓不到好价。** |
| **每次抽样，同一行情内逐 `tick` 冻结** | 与兽潮 F3「兽力恒定」同族：**你不能靠熬时间赢** |
| **行情在挂榜时就公示**（档位词，不是数字） | 玩家知道今天是好价还是压价，但**不能选**。这让「开不开市」（E5）成为一个真决策 |

**`MatWeight` 的默认序是【新增】，且需要拍板（OQ-2）**：

```
粗料（石料、泥土、杂物） → 0.6 – 0.9
中料（木料、布匹）     → 1.0 – 1.4
精料（铁料）           → 1.6 – 2.4
```

**推导依据**：外部买家对材料的估值应当**与加工程度同向**（越接近成品越值钱）。
村庄建造吃的是**总池**（`expedition.md` F6），所以**内部对六种材料无序**——
**「铁料更值钱」这个序只能从「外面怎么看它」推出来，不能从村庄内部推出来。**
→ 这条序一旦落地，会顺带解决一个既有悬空：
`expedition.md` OQ-1 说「村庄升级吃单一总池，还是指定材料？」——
**若商队给六种材料分了价，指定材料升级就有了经济上的动机。**（我不替它答，只指出这条联系。）

### F2 · 收购配额

```
IntakeQuota      = floor( Σ_m Min( MatPrice[m], VillageMaterial[m] ) × IntakeRate )
IntakeRate       ∈ [0.25, 1.00]        默认 0.60
PerStallQuota    = floor( IntakeQuota / Max(1, ActiveStalls) )
```

| 变量 | 类型 | 范围 | 来源 | 说明 |
|---|---|---|---|---|
| `IntakeRate` | float | 0.25 – 1.00 | data | 这一趟最多收走村庄多少比例的存量 |
| `IntakeQuota` | int | ≥ 0 | 计算 | 这一趟的总量上限。**到量即止** |
| `PerStallQuota` | int | ≥ 0 | 计算 | 每个摊位的均分上限（D3 反退化） |

**边界**：`IntakeQuota = 0`（村庄材料池为空）时，商队**照常来、照常停、什么都不收**，
写一条杂谈。**它不会因此改期**——它有行程。

### F3 · 一次成交

```
SettleStall(hero, m):
    Sellable = Min( PerStallQuota − 已成交,  VillageMaterial[m] )
    if Sellable <= 0: return 0
    StallPrice = MatPrice[m]
    Commission = Floor( StallPrice × rate )        // #8 F3，一字不改
    SellerNet  = StallPrice − Commission
    VillageMaterial[m] -= Sellable
    VillageCoin.Stall  += Commission
    Purse[hero]        += SellerNet
    return Sellable
```

> **`Commission` 向下取整 → 一笔小钱可能抽成 0**（#8 E10）。
> **`rate` 越过 0.231 时摊主照样不摆摊**（裁定 ③ / #8 F3b）。**商队不豁免。**

### F4 · 玩家侧的收益链

```
商队日 VillageCoin.Stall 增量
   = Σ_stalls ( Min(PerStallQuota, 材料数) × MatPrice[m] × rate )
   → VillageCoin（summoning.md F10 SummonFee / OQ-E11 升级吃钱）
```

**工作示例（tier 2 村庄：8 个摊位，7 个登记）**：

```
VillageMaterial:  石料 40 · 泥土 30 · 布匹 12 · 木料 20 · 杂物 15 · 铁料 6
MatWeight:        0.8  ·  0.7   · 1.2   · 1.1   · 0.7   · 2.0
ArrivalMark:      1.25（本趟「比平时好些」）
rate = 0.10
ActiveStalls = 7

IntakeQuota   = (40+30+12·1.2+20·1.1+15+6·2.0) × 0.6 = (40+30+14.4+22+15+12)×0.6 = 133.4×0.6 = 80
PerStallQuota = 80 / 7 = 11
若七摊各卖 11 份材料，本趟 VillageCoin.Stall ≈ 80 × 0.10 = 8 份 P
SummonFee(P=20) = 10 + 3×20 = 70 份 ¤   ← 一次商队不够召一个人，但十次够
```

**这个数字必须被承认**：`IntakeRate = 0.60` 之下，
**一次商队不够付一次召唤费。** 这是刻意的——
**若一次商队就能召一个人，村长的钱会变成唯一的成长货币，村庄建造线就被架空了。**
（这也是兽潮 § E2 的同一条教训：按人口配、按村庄等级配会让中后期内容变装饰。）

### F5 · 反退化的算例：`ActiveStalls` 的双向压力

| 村庄行为 | `ActiveStalls` | `PerStallQuota` | 该村庄总上限 | 谁受益 |
|---|---|---|---|---|
| 只有 2 摊登记 | 2 | `80/2 = 40` | 80 | 早登记的人吃满 |
| 5 摊登记 | 5 | `80/5 = 16` | 80 | 中间 |
| **8 摊全登记**（槽位满） | 8 | `80/8 = 10` | 80 | 人多有量，但每人少 |

**读法**：**「让大家全去登记」不是无脑最优解**——
它把总量守在 `IntakeQuota`，只改变**分配**。
唯一的收益是「落败者少」（所以竞争关系少写两条）。
**所以「全登记」的最优解不成立**：摊主要么早登记（吃均分的大头），
要么接受被均分。**这消掉了「永远第一个去点」的退化策略。**

## Tuning Knobs

> 全部住在 `assets/data/caravan.yaml`。**标 ⚠️ 的属于别的系统，本系统只读不写。**

| 参数 | 当前值 | 安全范围 | 类别 | 调大会怎样 | 调小会怎样 |
|---|---|---|---|---|---|
| `caravan_enabled` | **false**（VS 起 true） | bool | gate | — | — |
| `FIRST_CARAVAN_DAY` | **6** | 3 – 15 | gate | 玩家还没认全花名册就有车来 | Vertical Slice 演示时可能一次都遇不到 |
| `CARAVAN_PERIOD` | **9** | 5 – 20 | gate | 商队变成点缀，一年见不到几次 | **⚠️ 太密会让它变成主要玩法**（同兽潮 `RAID_INTERVAL_MIN` 的警告） |
| `CARAVAN_HOUR` | **10** | 8 – 16 | **固定** | — | **⚠️ 调到 0–7 会让大半村民永远赶不上**（E4 的反面） |
| `NOTICE_LEAD_DAYS` | **3** | 2 – 7 | gate | 预警从容 | 两拍变一拍，登记窗口来不及反应（B3） |
| `REGISTER_CLOSE_HOURS` | **6** | 3 – 12 | gate | 登记从容，竞争减少（**洞一的压力下降**） | 竞争极烈 → `Churn` 一天顶满 `DAILY_CAP` |
| `CARAVAN_HOURS` | **3** | 2 – 6 | gate | 摊主更容易赶上 | **窗口太短 → 摊主几乎只能提前备好** |
| `IntakeRate` | **0.60** | 0.25 – 1.00 | curve | 一次收走更多 → 抽成更多，但村庄更容易卡住 | **低于 0.3 时商队变成走过场** |
| `ArrivalMark` 区间 | **0.70 – 1.60** | 0.60 – 2.00 | curve | 行情波动大，开不开市成为真决策 | 行情恒定 → `refuse_market` 变成假选择 |
| `refuse_market` 默认 | **false** | bool | feel | — | 玩家不点，它就是一个永远不动的按钮 |
| ⚠️ `commission_rate` | **0.10** | 0.00 – 0.20（硬上限 0.231） | curve | 村长大进账，但摊主更可能不登记 | 商队流水大、村长没进账 |
| ⚠️ `MatWeight` 六项 | **待 OQ-2** | — | curve | **归 #8 / #7 所有，本系统只读** | — |
| ⚠️ `StallSlots` | 4 – 14 | — | gate | **归 #8 所有，本系统只读。** 它是稀缺性的唯一来源 | — |
| ⚠️ `DayLength` | 75 s | 30 – 180 | gate | **见下** | — |

> **⚠️ 与 `DayLength` 的耦合**：`CARAVAN_PERIOD = 9` 村庄日时，
> 一趟的间隔是 **9 × 75 = 675 秒 ≈ 11 分钟**。拉到 180s 就是 **27 分钟**一趟。
> **`caravan_enabled` 提供总开关**，M0 / M1 的回归测试必须能把它关掉。

**调参顺序**：
1. `caravan_enabled`（先确认关掉时所有回归守卫逐字符不变）
2. `CARAVAN_PERIOD` + `DayLength` 这一对（**先定「多久一趟」**）
3. `CARAVAN_HOUR`（**它单独决定多少人能赶上**，与数值无关）
4. `REGISTER_CLOSE_HOURS`（**它单独决定竞争关系多密** —— 洞一的压力全靠它）
5. `IntakeRate` + `ArrivalMark` 区间（一起调，它们共同决定 F4 的算例）
6. ⚠️ **`MatWeight` 不由本系统调** —— 它归 #8，调它要跑 #8 的 balance-check

## § 复用清单：**哪些可以原样搬走，哪些必须换掉**

> **这是本文件作为实例② 最值钱的一段。**
> 框架抽象阶段应当把它与 `beasts-and-raids.md` 的同名小节**并排读**：
> **两边的答案在八个位置上是相反的 —— 那八个位置就是框架的全部难点。**

### ✅ **可以原样复用（结构 + 纪律，不含数值）**

| # | 内容 | 与兽潮的关系 |
|---|---|---|
| 1 | **§ A 的九槽位表本身**（九个槽位的名称与提问顺序） | **槽位通用，填法不通用。** 本文件逐格标了「原样搬走 / 取值相反 / 可选」 |
| 2 | **文案的六条纪律**（六词零命中 / 内部量名零命中 / 不写数字 / 不用 `{l}` / 署名规则 / 模板收口） | **一字不改**沿用兽潮 § I2。**它对所有事件源成立，与事件类型无关** |
| 3 | **「没有硬失败」的封顶与保底写法**（三重封顶 + 逐条列出的不变量） | 同族写法。商队的保底是 E/F2 的三条 |

### 🔁 **必须换掉（实例专属）**

| # | 内容 | 商队为什么特殊 / 换掉后要重新回答什么 |
|---|---|---|
| 1 | **⚠️ G2 的取值方式** | **兽潮是「变周期 + 筛选钟点」，商队是「固定周期 + 锚定钟点」。** **框架必须把它做成参数，不能硬编成筛选器** —— 否则商队这一类事件会被强行塞进一个它不需要的候选集算法 |
| 2 | **⚠️ G4 的取值方式** | **兽潮是「被卷入」（`Present` 全员），商队是「自愿登记」。** 这正是兽潮复用清单第 1 条点名的「最大的一个变量」—— **现在它有答案了：同一个槽位，两个方向相反的取值。** 框架必须把它做成可插拔的参与者来源 |
| 3 | **🔶 G5 整个槽位可选** | **商队没有进行中读数。** 兽潮的 `tick = 0.25h` 战线读数是**兽潮专属**，**框架不能要求每个事件都有它** |
| 4 | **G6 的结算节奏** | 兽潮逐 tick 推 4.5 小时；**商队一次结算**。框架必须允许「一次性」 |
| 5 | **G3 的拍数** | 兽潮 2 拍；**商队 3 拍**（挂榜 → 定更 → 开市）。**「两拍够用」在实例② 处被证伪** |
| 6 | **G7 的后果物** | 兽潮 = 材料被啃 / 罩磨损 / 停工（**全是负**）；**商队 = 材料变钱（正负混合）**。这是两个方向完全相反的后果结构 |
| 7 | **⚠️ G9 的接口形状** | 兽潮 `RaidAftermath` 是**单向输出**；**商队必须双向**（读经济目录 + 写经济状态）。**框架若只支持单向，会在第二个实例上崩** |
| 8 | **「负反馈的来源」** | 兽潮的压力来自**战斗**（一场一场地打）；**商队的压力来自「稀缺 + 时机」**（一个号位、三小时、一次班）。**框架必须允许完全不同的压力来源** |
| 9 | **「谁触发的」** | 兽潮由**外部威胁**触发；**商队由「村庄自己有没有货」触发**（`IntakeQuota` 依赖 `VillageMaterial[m]`）。**框架不能假设事件总有外敌** |

### 🔶 **通用性仍存疑、必须由框架阶段判决的部分**

| # | 内容 | 存疑在哪 |
|---|---|---|
| 1 | **「时机筛选」是否要做成可选模块？** | 兽潮需要它（`beasts-and-raids.md` §🔶-1），**商队明确不需要**。**实例② 的答案是：必须可选。** 但「可选」之后，框架对缺省值怎么办——**这一条仍未判决** |
| 2 | **框架是否需要「事件冲突仲裁」这一槽位？** | OQ-7：商队与兽潮撞车。本文件登记不裁决，但**框架必须有答案**，否则两个事件各自实现会产生不可预期的交互 |
| 3 | **「外部扰动 → 经济」的接口该放在哪一层？** | **这是本文件与 `beasts-and-raids.md` **OQ-7** 撞上的同一个洞**（那次是「兽潮后物价上涨」，这次是「商队报价」）。**两个实例各自撞上一次同一个洞 → 这个接口应当在框架里定义一次，而不是让每个实例各发明一遍。** 框架阶段必须正面回答 |
