## Summary

本土角色是这个异世界大陆上**本来就有的人**。他们不是酒馆召来的，不带地球时区，没有「上线」这件事——他们住在这儿。文档只交付三件事：**他们承担什么承重功能**（村庄在玩家下线时仍然有事发生、并且覆盖玩家作息填不满的时段）、**他们的数据形状**（哪些字段有、哪些字段一定没有）、**他们与玩家的接口开在哪**（三个问号，本文档不替开发者答）。剧情、人物、动机一律不写。

> **Quick reference** — Layer: `Feature` · Priority: `Alpha` · Key deps: `时间与作息`（覆盖合成）、`召唤系统`（对照基线）、`性格系统`（若复用）、`杂谈`（唯一的叙事出口）

## Overview

村庄目前的人全部来自地球：他们各有各的时区、并且各自**以为自己**有份地球的工作，所以他们的「上线时刻」换算到村庄时钟之后是散的 —— 这是「村庄永远不会天黑」的全部来源，代价是**早期的村庄有结构性空洞**：`--selftest` 实测 3 人时 24 小时里有 11 格没人，10 人才填满。

本土角色补的就是这 11 格，而且不是靠「他们也按时区作息」。**他们没有那份「以为自己在地球有份工作」的作息。他们住在这儿。** 这是一句听起来像风味设定的话，实际上是承重结构：玩家的缺席是**结构性的**（由时区决定，永远存在），本土人的缺席是**事件性的**（生病、出门、被剧情带走）。两种缺席不互相替代。

同时，本土人是**玩家第一次看见这个大陆的入口**。杂谈里现有的「村口来了个生人，没人认得」事件，目前是一个无后果的装饰条目；本土角色一旦落地，那个「生人」就可以是真实的、可被记住的人。这改变了这条事件的含义。

**这个系统当前不产出任何剧情、任何本土人的名字、任何本土人的台词。**

## Player Fantasy（简）

你召来的人会走。你召唤他们的时候就知道他们什么时候会走，因为他们的作息写在花名册上，是你从地球带来的习惯。

**但有些人不走。** 他们不是被召唤的，他们本来就在这里。你不认识他们，也不知道他们为什么在这儿，但他们一直在。

村庄因此在你下线的时候还在过自己的日子 —— 那段日子不是你的任务在跑，是**别人的**。

## Detailed Design

### R1 — 本土人不是召唤来的（最重要的一条，【原话】+【红线】）

**本土人不经过酒馆。**

`design/gdd/summoning.md` R6 定义了召唤的产出物：`HeroAgent` + `WorldName` + `Trait`，六选一的世界原型，以及「先有来处，再有人」的派生链。**本土人不走这条链**：

| | 地球召来的玩家 | 本土角色 |
|---|---|---|
| 入口 | 英雄酒馆，`HeroFactory.Summon()` | **无入口。他已经在这儿了** |
| 来处 | 六个世界原型之一（剑与魔法 / 赛博 / 废土 / 深海 / 妖怪 / 星舰） | **不是那六个。** 本土人是**这个世界**的人——「来处」对他是恒真的，指向脚下 |
| 生成时机 | 玩家点击的那一刻 | **玩家点之前**。见 R6 |
| 是否可被玩家再造 | 能，随时 | **不能**。他不是可再生的资源 |
| 数据形状 | `HeroAgent` | `NativeFolk`（R4），**不是 `HeroAgent` 的子类** |

**为什么必须是两个类型而不是一个类型加一个标记**：召唤来的英雄身上每一个字段都带着「他从地球来」的语义（`UtcOffset` / `LocalLoginAt` / `PlayHours` / `WhereOnEarth`）。本土人没有这些语义 —— 他没有「那边」，他一直在。**把两种人塞进同一个类，就会有代码去读一个对本土人恒为空、且**读不出错**的字段。** 那是最难查的一类 bug。

> **【红线】禁止 `NativeFolk : HeroAgent` 或 `NativeFolk` 复用 `HeroFactory`。** 本土人没有可抽取的世界原型；`HeroFactory.Summon()` 的保底循环（`sum < 60` 重掷）对本土人没有意义 —— 本土人不是 roll 出来的，他是**一直在这儿**的。

### R2 — 本土人承担三个功能，只有三个（【推导】，开发者只说了第一个）

`systems-index.md` #12 的描述是「**不依赖玩家的第二条内容线**」。加上 brief 的补注，本系统可枚举的功能只有下列三条。**超出这三条的想法一律进 Open Questions。**

#### F-A · 村庄不因玩家下线而死（【原话】）

> 「如果只有玩家，玩家不上线时你的村庄是死的。」

这是**功能**，不是氛围：玩家关闭游戏期间，村庄时钟继续走（`time-and-schedule.md` R1），而本土人仍然在村子里，他们的行为不因为「没人按键」而暂停。

**这要求一条具体规则**：`NativeFolk` 的行为更新**不得以 `InputActive` / `AnyPlayerOnline` 为条件**。村庄的推进入口对两类人是同一条路径。

#### F-B · 覆盖玩家作息填不满的时段（【推导】，承重，见 Formulas F1–F3）

`time-and-schedule.md` 的实测覆盖曲线（注意：该表量的是**随机召来的村民**，不是被 `PinOnlineAt` 钉住的开局三人）：

```
  人口  空档   0点————————————————————————————23点   峰值
    3   11    1111··111111·········222     2
    6    3    1111··1111221·1112211322     3
   10    0    122211122234212334421322     4
   20    0    335556655455334568754644     8
   40    0    99878+++++++76457+978+++    14
```

玩家要到 **10 个人**才填满 24 小时。本土人不需要 10 个 —— 他们的在场**不以地球时区为条件**。

> **这不是风味设定。** 如果本土人只是「再多几个村民」，而他们的在场判定仍然走 `IsOnlineAt(LocalLoginAt, PlayHours)`，那他们在覆盖曲线上和玩家是同一种分布，方差一样，空档不会因为他们而减少。**他们必须是一种不同的分布源。** 这是本系统存在的机械理由。

#### F-C · 杂谈的第二个故事源（【原话】+【推导三】）

`design/gdd/personality.md` 把杂谈里没有状态后果的三类事件（闲逛 / 搭手 / **陌生人**）暂时挡在门外，注明「留给后面的模块变成决策点」。**本系统就是那个模块。** 见 R5。

**除这三条之外，本土人不承担别的功能。** 不提供战斗力、不提供材料、不提供钱、不提供任务、不提供建筑。这五项开发者都没有说过。

### R3 — 「他们住在这儿」对数据模型的约束（【推导】，本节是本文档最硬的部分）

`time-and-schedule.md` 的整个作息系统建立在一条语义上：**村民来自地球，他以为自己有一份地球的工作，所以他有上线和下线。** 逐字段拆开：

| 字段 | 语义 | 本土人 | 依据 |
|---|---|---|---|
| `UtcOffset` | 他在地球哪一带 | **无** | 【红线】没有「那边」 |
| `LocalLoginAt` | **他自己那边**几点上线 | **无** | 【红线】他没有「那边」 |
| `PlayHours` | 一次上多久 | **无** | 【红线】他一直在，没有「一次」 |
| `PinnedVillageHour` | 钉在村庄时钟上 | **无** | 【红线】不需要钉；他不需要被钉才在场 |
| `Online` | 是否在窗口内 | **无**（见下） | 【推导】对本土人恒为 true 的字段是噪声 |
| `Diligence`（肝/随手/挂机） | 一次投入多少时间 | **无** | 【红线】投入度的全部语义是「他多久上一次线」。本土人没有上线。**给本土人一个「投入度」是无中生有的一整套新轴。** |
| `AbsentDays` | 缺席剩余天数 | **有** | 他的缺席是事件性的（生病/出门），不是结构性的 |
| `Away` | 外出/远征 | **有**，但语义待定 | 见 Q3 |

> **【红线】`Diligence` 是这条推论里最容易被违反的一个。** `personality.md` 的九宫格 = 3 性格 × 3 投入度。本土人若也套进去，就凭空多出 9 种没人设计过的组合，而**每一种都要重新 playtest**。投入度是**地球作息的产物**，本土人没有这个维度。

### R4 — `NativeFolk` 的数据形状（最小集，逐字段给理由）

当前**没有任何字段被实现**（本文档写作时 `src/` 里不存在本土角色）。下面是接口形状，**每个字段都必须能说出它被哪个消费方读**，说不出就删掉。

| 字段 | 类型 | 谁读它 | 为什么需要 |
|---|---|---|---|
| `Name` | string | 杂谈（R5）、UI 花名册 | 没有名字的人在村庄里不可被指认，杂谈无法写「谁」 |
| `Home` | bool | 覆盖合成（F1） | **【推导】唯一的在场来源。** `Home = true` 表示他住在这个村，不需要任何时间条件 |
| `AwayDays` | int | 覆盖合成、`NativeFolk.Tick` | 他的缺席天数（生病 / 出门）。与玩家的 `AbsentDays` 分开，因为它们由不同的事件源写入 |
| `AwayWhy` | string | 花名册 | 玩家至少要知道今天缺人是为了什么（对齐 `HeroAgent.AbsentWhy` 的做法） |
| `Seen` | bool | `Chronicle.DayStranger` 的归属裁定（Q1） | 「村长见没见过这个人」—— R5 需要它 |
| `Role` | string? | 【未定】 | **未知。** 本土人在村里是否有身份（铁匠/守卫/看门/孩子）会影响杂谈的写法与经济的连接方式。**Q4** |

**明确不在 `NativeFolk` 上的字段**（这是本节的一半价值）：

`Power` / `Speed` / `Grit` —— 开发者没说过本土人有数值。他们能不能干活、干活多快，是 **Q2**。
`WorldName` / `Trait` —— 那是召唤系统的产出，语义是「他从哪个世界来」。本土人的来处是恒真的，写一个字段存它是噪声。
`GrudgeWith` / `SlackDays` / `RestlessDays` —— 那是 `personality.md` 的性格事件状态机。**本土人没有性格事件**（Q3 未裁定前），因此这些状态无写入方。

> **接口约定**：`NativeFolk` **不得**实现 `IsOnlineAt(float hour)`。任何调用方若想用统一接口遍历两类人，必须走 R7 的 `Presence` 抽象，而不是让 `NativeFolk` 谎称自己有作息。

### R5 — 「陌生人」事件：含义已经变了（【推导三】）

当前实现（`src/Chronicle.cs` L275–285）：

```csharp
public static Entry DayStranger(int day)
{
    string tpl = Pick(new[]
    {
        "村口来了个生人，没人认得。他站了很久就走了。",
        "有人看见村外头有人影。一晃就没了。",
        "过路的行商在村口停下问路。村长给了水，人家没停。",
        "夜里村口有敲门声。开门没有人，地上放着个东西，拿走了。",
    });
    return new Entry(day, tpl, null);
}
```

**四条模板，全部无状态**（`Entry` 第三参为 `null`，无行为主体），符合 `personality.md`「三个无后果事件暂时不出现在杂谈里」的处置。

**本土角色一旦落地，这条事件产生三重冲突：**

1. **语义冲突**：村庄里开始有「本地人」之后，「村口来了个生人，没人认得」这句话指的到底是哪一类人？玩家会读到「本土人」，系统写的是「没人认得」。
2. **归属冲突**：`DayStranger` 目前由 `VillageLife` 产出（`src/VillageLife.cs` L32–34 的权重表里有「陌生人」一列，权重对三种性格都是 1）。本系统落地后，**这条事件应该由谁产出？**
3. **一致性冲突**：`game-brief.md` 立了铁律「事件必须改状态，不能只是写一句话」。若本系统接管了「陌生人」，它必须真的产生一个 `NativeFolk`；若不接管，它就必须继续被 `personality.md` 挡在杂谈之外。

**本 GDD 不裁定。** 三条可能的处置列在 Q1。**但在 Q1 裁定之前，`DayStranger` 维持现状**（不出现在杂谈里），因为「四选一的随机文案」是当前唯一不会说假话的选项 —— 一旦本土人在场，「没人认得」就可能是假的，而 `summoning.md` E12 已经因为同类问题（无条件触发「村里第一次见这种」）吃过一次亏。

### R6 — 生成时机：他们在村长之前（【原话】+【推导】，同时是一处待裁定的张力）

**【原话】**：本土人「本来就有」。
**【推导】**：因此他们**不经过任何生成器**。他们不是 `Day == 1` 时被脚本放进去的，而是村庄的**初始状态**的一部分。

> ### ⚠️ 一处必须由开发者裁定的设定张力（不是我能解的）
>
> `design/game-brief.md` 写的是：
>
> > 「**你（玩家）穿越到了异世界大陆。初始只有几间普通草屋。**」
>
> 而本系统要求本土人**在村长到来之前就住在这儿**。
>
> 这两句可以调和，但**调和的方式有好几种，而每一种都是剧情**：
>
> - (a) 草屋是本土人住的 —— 那么「初始只有几间草屋」描述的是**村长的认知**，不是村庄的实况。村长是外来者，他初来时看到的是三间草屋和一个已经在住人的村庄。
> - (b) 草屋是空的，本土人是后来才聚过来的 —— 那么他们需要一个**聚集事件**，而这个事件本身就是剧情。
> - (c) 草屋原本属于本土人，他们搬走了 —— 需要解释为什么搬走。剧情。
>
> **三种都是世界观的根。** `world-builder` 不替开发者选。见 **Q5**（最高优先级）。
>
> **在 Q5 裁定之前，本系统不写死村庄初始人口。** 这也是为什么 `Home` 是一个布尔而不是一个可调的人口曲线参数 —— 人数本身要先被决定，参数才有意义（Q6）。

### R7 — 两类人共存的抽象接口（【推导】，`time-and-schedule.md` 的扩展点）

`time-and-schedule.md` 明确约定对外暴露的是 `OnDuty(h)` / `Present(h)` 两个判定，并规定「其余系统不得自己重算在线窗口」。

本土角色接入时，**这两个判定的定义必须扩展为覆盖两类人**：

```
Present(NativeFolk n, h) = n.Home ∧ n.AwayDays ≤ 0
Present(HeroAgent p, h) = ¬p.Away ∧ p.Online          （time-and-schedule.md R7）
```

**注意 `NativeFolk` 的定义里没有 `h`。** 他的在场**与村庄钟点无关**。这不是「他的作息特殊」，这是「他没有作息」。任何让 `NativeFolk` 依赖 `h` 的实现都是在把地球规则套到一个不属于它的模型上。

因此下游系统（建造 / 任务 / 杂谈）遍历人口时，应当面对一个抽象 `IHabitant`，它至少有 `Name` 和 `Presence(h)`；而**只有 `HeroAgent` 那一侧需要时区知识**。

> **接口约定**：下游系统**不得**通过 `is HeroAgent` 的类型判断来决定一个人的行为规则。这条在只有一类人时无所谓，在两类人并存时会立刻变成一处逻辑分叉。类型分派只能发生在 `Presence` 这一个方法内部。

### R8 — 玩家可见文案（约束，非产出）

**玩家可见文案不得出现系统词**：成功 / 失败 / 获得 / 消耗 / 属性 / 奖励。（本项目硬规则，见 `summoning.md` R9、`time-and-schedule.md`「Player-visible 文案约束」）

**本系统当前不产出任何玩家可见文案。** 花名册上本土人一行显示什么、村民怎么称呼他，全都是剧情/文案决策，尚未裁定（Q7）。

**唯一的规范性结论**：本土人**不得**在文案中被称作 NPC、外来者、村民以外的任何标签，也不得出现「本土人」这三个字 —— 那是系统词，不是村长的语言。村长不认识他们的来处，玩家也不该认识。

### R9 — 本文档明确不做的事（显式否定，防止越界）

以下全部**不在**本系统范围内，且**开发者从未描述过**：

- 任何本土剧情：任务、故事线、冲突、结局、节日、纪念日
- 本土人的姓名生成规则、面孔、身份背景、家庭关系
- 本土人的性格、性格事件、结仇、心情
- 本土人的数值成长 / 战斗 / 死亡
- 本土人与副本、防护罩、试炼塔的任何关系
- 本土人与经济（三层经济的定义见 `game-brief.md`，**全是玩家之间的**）：摆摊、抽成、税率、买店
- 「本土人会不会离开村庄」「会不会背叛」「会不会变成敌人」—— 这是剧情
- 本土人可被玩家招募 / 驯服 / 交易 / 送礼
- 把本土人加进配队系统

## Formulas

> 本节只定义**覆盖合成**这一条数值规则。它是本系统唯一的机械承诺（F-B）。
> **本土人的作息曲线、他们一天干什么、什么时候出门，本文档不定义**（Q8）。

### F1 · 覆盖合成（两类人的在场相加）

```
Coverage(h) = Σ_{p ∈ 花名册(玩家)} IsOnlineAt_p(h)        ← time-and-schedule.md F3
            + Σ_{n ∈ 花名册(本土)} Presence(n, h)          ← 本文档 R7
                　where　Presence(n, h) = n.Home ∧ n.AwayDays ≤ 0
```

| 变量 | 类型 | 范围 | 来源 | 说明 |
|---|---|---|---|---|
| `h` | float | `[0, 24)` | 村庄 `Hour` | 被问的村庄钟点 |
| `IsOnlineAt_p(h)` | bool | — | `time-and-schedule.md` F3 | 玩家侧，含 `AbsentDays` 优先 |
| `Presence(n, h)` | bool | — | 本文档 R7 | 本土侧；**定义中不含 `h`** |
| `Home` | bool | — | `NativeFolk.Home` | 他住在这个村 |
| `AwayDays` | int | `≥ 0` | 事件写入 | 他的事件性缺席天数 |
| `Coverage(h)` | int | `0 .. N_players + N_natives` | 计算 | 该钟点的在场人数 |

**输出范围**：`Coverage(h) ∈ [0, 花名册总长]`。布尔相加，两侧永不为负。

### F2 · 空档与峰值（沿用 `time-and-schedule.md` F4，扩展到两类人）

```
EmptySlots = |{ h ∈ [0,24) ∩ ℤ : Coverage(h) = 0 }|
Peak       = max_{h ∈ [0,24) ∩ ℤ} Coverage(h)
```

诊断量，整数，可直接打印、可直接断言。

### F3 · 不变量（**本系统唯一的机械承诺**）

```
对于任意 h 与任意 AwayDays 变化：  Coverage_with_natives(h) ≥ Coverage_players_only(h)

特别地：EmptySlots_with_natives ≤ EmptySlots_players_only
```

**本土人只会减少空档，永远不会增加。**

推导：本土侧对 `Coverage` 的贡献 `Σ_n (Home ∧ AwayDays ≤ 0)` 恒 `≥ 0`，且它**不读 `h`**，因此不对任何时段产生负贡献。

> **这条不变量是 F-B 的验收形式**，也是判断「本土人是否真的在承重」的**唯一客观标准**：把本土人从花名册里拿掉，空档数必须上升。
>
> **反例诊断**：如果实现了本土角色之后 `EmptySlots` 没变，那么本土人正在走 `IsOnlineAt` —— 他们被当成了玩家。**这是本系统最可能的实现事故**，且症状是「功能看起来接上了但没用」。

### 工作示例（数值为示例，本土人口 N 本身未定 —— 见 Q6）

取 `time-and-schedule.md` 的实测玩家覆盖曲线，假设本土人口 `N_natives = k`：

| k | 玩家 3 人的 `EmptySlots` | 玩家 6 人的 `EmptySlots` | 说明 |
|---|---|---|---|
| 0（现状） | 11 | 3 | 参照实测 |
| 1 | 10 | 2 | 减少 1 |
| 3 | 8 | 0 | 3 个本土人填平 6 人村庄 |
| 4 | 7 | 0 | — |

**注意**：这是**算术**，不是设计意图。`k` 取多少是 Q6，`--selftest` 未来需要增印一行混合覆盖曲线。**在 Q6 裁定之前，这张表不得被当作承诺引用。**

## Edge Cases

| # | 场景 | 期望行为 | 理由 |
|---|---|---|---|
| **E1** | 本土人的 `AwayDays > 0`，且他的缺席覆盖了某个玩家空档 | 该时段 `Coverage` **可能回落到 0**，`EmptySlots` 上升 | **允许，且必须有。** 若本土人永不缺席，F3 会退化成「本土人 = 常驻劳动力」，那就成了一个只会点数的劳动力生成器。本土人的缺席必须与玩家的缺席**性质不同**（事件性 vs 结构性），否则 R3 的整个区分没有意义 |
| **E2** | 玩家人口为 0，本土人口 > 0 | 村庄**不是空村**。时钟照走，本土人的行为照跑，杂谈照记 | F-A 的直接验收。玩家「下线」在数据上就是 `花名册(玩家) = ∅`，此时村庄仍有事发生 |
| **E3** | 下游代码遍历人口时遇到 `NativeFolk`，调用了 `IsOnlineAt` | **不允许**（编译期或断言拦截） | R7。若允许，`IsOnlineAt` 对本土人只能返回一个**恒定的、看起来正确但毫无意义的值**，错误会在下游静默传播 |
| **E4** | 有人给 `NativeFolk` 设了 `Diligence` / `UtcOffset` | 视为违规，不是可配置项 | R3 的三条红线。这些字段在本土人身上没有语义 |
| **E5** | 本土人在村庄里的初始状态 —— 村长认识他吗？ | `Seen` 由 Q1 裁定后决定取值 | 目前是 `Seen` 字段存在但无写入方。这是**已知缺口**，不是疏漏 |
| **E6** | 村民（`VillageLife`）的「陌生人」事件触发，而村庄里已有本土人 | **维持现状**：该事件仍被 `personality.md` 挡在杂谈之外 | R5。若此时放行，系统会写出「没人认得」这样的假话 —— 与 `summoning.md` E12 是同一类错误 |
| **E7** | 本土人的姓名与召来的玩家重名 | 允许 | 重名在玩家侧已经是或然事件（`summoning.md` F8：15 人时 50%）。**本土人不因为「是本地人」就获得命名优先权**，因为这需要一套本地姓名表 = 世界观资产 = Q4 |
| **E8** | 玩家把所有本土人都「用完」（如果将来本土人能派活） | 未定义 | 「本土人是否可被指派工作」是 Q2/Q3。在裁定之前，本土人**不进入**建造 / 配队 / 任务的人口集合 |
| **E9** | 一个 `dt` 内跨了多天（`time-and-schedule.md` E6 的同类情形） | 日事件**当帧只触发一次** | 与 `time-and-schedule.md` E6 同规则。补跑多天会让杂谈一次刷出几十条 |
| **E10** | 本土人试图使用 `PinOnlineAt` | 不适用 | R3 红线：本字段只对 `HeroAgent` 存在 |
| **E11** | 本土人唯一的减项 `AwayDays` 归零但没有触发任何事件 | 不产生杂谈条目 | 「事件必须改状态，不能只是写一句话」的**反面**用法：状态复原同样不该刷屏 |
| **E12** | 玩家打开游戏时村庄里一个人都没有（玩家和本土人都没有在场） | 仍要有一条实话可说的杂谈 | 沿用 `time-and-schedule.md` E9。本土人提高了「有人」的概率，但**没有消除**这种可能 |

## Tuning Knobs

> **当前没有任何可调参数** —— 因为没有任何实现，也没有定下本土人口 / 人口增长 / 活动曲线。
> 下表列出的是**接口形状参数**，取值全部待 Q6 裁定。

| 参数 | 当前值 | 候选范围 | 调高的影响 | 调低的影响 |
|---|---|---|---|---|
| 本土人口 `N_natives` | **未定（Q6）** | 0 – 与玩家同量级 | 空档消失得更快（F3 满足得更强），村庄自主感更强，「村庄不是玩家开的」这句话更可信 | 本土人退化为装饰，F-B 归零 |
| `AwayDays` 的事件发生率 | **未定（E1）** | 0 – 与玩家事件率相当 | 本土人的缺席也是事件性的，与玩家的结构性缺口形成对照 | 变成常驻劳动力，见 E1 反例诊断 |
| `Seen` 初值 | **未定（Q1）** | 全 false / 全 true | 「村长认不认识他」 | 同左 |
| `Role` 枚举 | **不存在（Q4）** | — | — | — |

## Acceptance Criteria

> **本系统的验收项刻意分成两组：接口类必须通过，剧情类必须为空。**
> 「剧情为空」是一条**红线验收** —— 它证明本文档没有越界。

### 接口类

- [ ] **AC-1 — 不是召唤来的**：在 `src/` 中检索 `NativeFolk` 的构造路径，断言**不存在**任何从 `HeroFactory.Summon()` 或六世界原型表出发的分支。构造入口**不能**是玩家操作触发的。
- [ ] **AC-2 — 不是 `HeroAgent` 的子类**：断言 `NativeFolk` 与 `HeroAgent` 之间**没有继承关系**。若将来确需共同接口，用组合（`IHabitant`）而非继承。
- [ ] **AC-3 — 红线字段不存在**：断言 `NativeFolk` 上**不存在** `UtcOffset` / `LocalLoginAt` / `PlayHours` / `PinnedVillageHour` / `Diligence` / `Power` / `Speed` / `Grit` / `WorldName` / `Trait` / `GrudgeWith` 任何一个。**测试用例必须是编译期或反射断言**，不能靠代码评审 —— 靠评审拦不住「顺手加一个」。
- [ ] **AC-4 — 无 `IsOnlineAt`**：断言 `NativeFolk` 上**不存在**名为 `IsOnlineAt` 或等义的方法。若走 `IHabitant` 抽象，则断言其 `Presence(h)` 的实现**不读取 `h`**（可由静态检查或调用两次不同 `h` 后断言状态相同来验证）。
- [ ] **AC-5 — F3 不变量（核心）**：同一固定种子下运行 `--selftest` 两次，(a) 仅玩家时的覆盖串，(b) 玩家 + 本土人的覆盖串。对每个整点 `h` 断言 `Coverage_with(h) ≥ Coverage_players_only(h)`；对整体断言 `EmptySlots_with ≤ EmptySlots_players_only`。
- [ ] **AC-6 — 承重反例诊断**：把本土人全部移出花名册（`N_natives = 0`）后重跑 F3，断言 `EmptySlots` **确实上升**。**若不上升，说明本土人正在走 `IsOnlineAt`，本系统没有在承重 —— 测试必须能失败。**
- [ ] **AC-7 — E2 玩家归零**：把玩家花名册清空、本土人口 > 0，运行一个完整游戏日，断言村庄**时钟照走**（`Day` 递增）、**本土人 `AwayDays` 变化照常推进**、**杂谈有输出**。玩家不在线时村庄不是死的。
- [ ] **AC-8 — 玩家不得接管**：断言村庄推进的更新入口**没有** `InputActive` / `AnyPlayerOnline` 之类的门控条件。
- [ ] **AC-9 — E1 缺席可行**：构造 `Home = true ∧ AwayDays = 1` 的本土人，断言其 `Presence` 为 `false`，且 `Coverage` 在该钟点回落。**这条锁的是「本土人不是永动机」。**
- [ ] **AC-10 — 无系统词**：全项目 grep 玩家可见字符串，零命中 `成功 / 失败 / 获得 / 消耗 / 属性 / 奖励`，**并且**零命中 `本土人` / `NPC` / `外来者`（R8）。
- [ ] **AC-11 — 数据驱动**：`NativeFolk` 上不存在硬编码的姓名表、世界表或数值表；本土人口来自配置。
