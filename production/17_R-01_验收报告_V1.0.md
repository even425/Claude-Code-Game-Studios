## 4. 随机性测试（草案 §5.2）

| # | 验收项 | 结果 | 证据 |
|---|---|---|---|
| 1 | 固定随机种子可重复得到相同分配 | ✅ | `Split_SameSeed_ReproducesSameAllocation` |
| 2 | 剩余物品不分配给不合格者 | ✅ | `Split_AcrossManySeeds_ConservesQuantityAndKeepsRecipientsEligible`（**200 个种子**） |
| 3 | 多件剩余物品总量与发放前一致 | ✅ | 同上（守恒逐次断言） |
| 4 | 随机分配不凭空生成或丢失物品 | ✅ | 同上；另测 `Split_FewerItemsThanParticipants_SomeHeroesGetNothing`（E05） |

**种子派生**：`LootSplit.DeriveSeed` 用 **FNV-1a**，不是 `string.GetHashCode()` ——
.NET 的字符串哈希每个进程都不同，用它派生种子，「读档重放得到同样的结果」当场就废了。

**随机调用次数被钉死**：可整除时**一次都不抽**；余数 N 件就抽 N 次
（`Split_DrawsFromRandomSourceExactlyOncePerRemainderItem` 断言随机源状态与
「手工抽 N 次」完全一致）。调用次数一变，同一个副本的分配结果就变，
而分配结果是**要进背包、要存档**的。

**掉落不插队**：随机走**由副本标识派生的独立子流**，不动战斗与日常共用的全局随机源。

## 5. 状态一致性测试（草案 §5.3）

| # | 验收项 | 结果 | 证据 |
|---|---|---|---|
| 1 | 发放后各英雄背包数量与分配结果一致 | ✅ | 真机「霓绫：石料 0 → 19（应 +19）」；`Grant_ValidBatch_FillsEveryRecipientBag` |
| 2 | 失败结算前后战利品不进背包 | ✅ | 真机失败局：分配 0 条、背包无变化、材料 40 → 40 |
| 3 | 奖励发放异常时不产生部分提交 | ✅ | `Apply_WhenItemsCannotBeGranted_AppliesNothingAtAll`（资源一笔没写、物品一件没发、幂等键不落） |
| 4 | 重复结算同一副本不重复发放 | ✅ | `Apply_SameKeyTwice_GrantsItemsOnlyOnce`；真机「重放同一结算键 → Apply 返回 False」 |
| 5 | 保存和读档后奖励仍属于正确的人 | ✅ | 真机「战利品已入档 = True」；存档版本 **0.4**，未新增字段 |
| 6 | 读档后重复处理同一副本结果不重复发放 | ✅ | `Apply_AfterSaveReload_GrantsNoItemsAgain`（恢复幂等键后重放，物品不再发） |

**半笔账是这一段最贵的风险**：「村庄拿到了、英雄没拿到」比「都没拿到」更难查。
为此物品写入拆成**预检 + 提交**两阶段（`IItemGrantWriter`），
且**预检必须在资源写入之前**（`Apply_ChecksItemsBeforeWritingResources` 断言这一点）。

## 9. 遗留与边界

**本轮未做（有意）**

- 装备 / 不可拆分物品类型（草案 E06）—— 当前领域模型无此类型，需扩 `ItemDefinition`，建议另开任务。
- 货币参与平分（草案 E11）—— 已拍板「只发物品」，金币与材料继续走现有村庄资源结算。
- 掉落率 / 稀有度 / 正式掉落表 —— 属 R-05 / T-007。本轮的占位掉落（石料 × `job.Amt`）
  **正等着被替换**；替换点单一：`ILootProvider` 的实现。
- 正式购买 UI / 摊位库存面板（R-02 / R-04）、自摊规则（R-03）、背包摘要 > 2 种物品（R-06）、
  正式「购物未成」反馈（R-07）—— 沿用 `15` §7 的排期。

**已知限制**

- 正式背包容量为「无限」（`Inventory.Capacity = 0`），所以 E09（背包满）在正式游戏里
  **今天不会真的触发**。规则已钉死并有单测（用有容量上限的背包夹具验证整次回滚），
  将来给背包加上限时无需改规则。
- 副本战利品目前**只在副本成功时**产生；采集任务仍走 `Deposit` 直发村庄材料
  （它没有战斗结果，而 `SettlementKey` 是 `(RunId, BattleResultId)` 复合键）—— 已知缺口，未变。
- 占位战斗胜率 0.5，本轮 12 次真机运行 2 胜 10 负，样本偏斜；不影响两条路径均被验证。

## 10. 结论

**R-01 验收通过。**

副本成功结算 → 战利品按参战快照全队平分 → 余数随机 → 进入英雄个人背包 →
可开摊、可被他人购买 → 存读档后仍归属正确的人，
整条链在**同一次结算**里完成、用**同一把幂等锁**保护、失败时**一律不发**。

**R-02（正式购买 UI）的前置已解锁** —— 物品现在真的会进背包，界面有东西可展示。
