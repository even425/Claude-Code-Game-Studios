## 6. M4：存档一致性（已完成，D-044）

### 决策

- `SaveVersion` 0.3 → **0.4**；旧档**整份拒绝**，不写迁移器（I11 + 既有先例）。
- 摊位入档（推翻 D-029 该条）：`StallSave` = OwnerId / ItemId / Stock / UnitPrice / Status / SimTime / GridX / GridY；**一人一摊**。
- 购买幂等键新增独立字段 `AppliedPurchaseKeys`：**不**复用 `AppliedTradeKeys`（后者是 TradeId 空间，留给尚未接线的英雄↔英雄交易）。
- 每日购物两个状态都落盘：`HeroSave.LastShoppingDay`（成交日）与 `SaveGame.DailyShoppingLastRunDay`（调度闸门）。
- 读档入口：`Stall.Restore`（允许库存 0）、`StallService.Restore`（全有或全无）、`DailyShoppingService.RestoreLastRunDay`。
- 校验器扩十类负例：断引用 / 重复摊主 / 空商品 / 负库存 / 营业中无货 / 负单价 / 未知状态 / 非法时间 / 空购买键 / 非法日号。

### 顺带修复的根因

`Main.OnSummon` 原先在 `_heroes.Add(...)` **之前**给 Agent 取 `_heroes.Count`、
在 **之后**给 HeroDefinition 取同一个表达式，于是两套描述恒差 1（Agent `h-0` /
Definition `h-1`）。M4 之前没有任何路径同时引用两边，直到摊位的 `OwnerId`（来自 Agent）
要在 `heroes[]`（Definition Id）里过引用校验才暴露 —— 首次 `--save` 直接报
`stalls[0].ownerId：摊主「h-0」在英雄列表中不存在`。修法：`OnSummon` 先算一次 `id`，
两处共用；`--save` 自检新增「英雄 Id 对齐（Agent ↔ Definition）」断言。

| `src/Domain/Stall/Stall.cs` | `Stall.Restore(...)`：读档允许 Stock=0，其余防线与公开构造相同 |

### 边界

- `DailyShoppingLastRunDay` 是比设计清单多存的一项：不存它，读档后同一天会对当天还没成交的人再尝试一次。

## 7. M5：可观察性 / 反馈（已完成，D-045）

### 决策

- 只做设计文档「反馈」的三类：交易事件、经济变化、自主行为结果；不做商店动画、经济大盘、正式购买 UI。

- 经济变化放在**现有花名册行尾**（`EconomySummary`：`金95 石料×1`），顶部状态栏加「村金」；行文本变化用 `ItemList.SetItemText` 原地更新，不 `Clear()`，保住滚动位置。
