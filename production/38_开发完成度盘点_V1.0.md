## 2. 当前目标：第四阶段收口 —— 只差数值

第四阶段的实施顺序是「物品来源 → 摆摊与购买 → 英雄自主购物 → 存档幂等 → 可观察性 → **完整验收**」，
前五项**都完成了**；最后一项的前置就是**数值**。

`34` 阶段 5 原文：**评审掉落权重 / 掉落次数 / 基础价格 / 稀有度映射**，
前置条件（D-054 已确认 + 采集显示经济不再停摆）**已满足**。

⇒ 逐项见 `production/37_R-05阶段5_数值评审清单_V1.0.md`（含「现在是什么 / 定了之后我做什么」）。

**最要紧的三个**：基础价格（T-007）· 伤害/命中/冷却公式（T-004）· 队伍人数上限（P-10）。

## 3. 为什么给不出「还差 N 周」

**「开发完成」现在指向哪个集合，还没有定义。**

- 仓库里**没有第五/第六阶段计划** —— 第四阶段是最后一个有计划文档的阶段。
- 开发计划 §六 明确把「完整召唤池 / 完整的城市成长与全部建筑和大事件 /
  大量英雄与多个副本与装备数值 / 完整本土剧情 / 复杂行为链」列为
  「**不进入第一阶段强制验收**」—— 它们**仍是整体设计的一部分**，不是被删除。

⇒ 换句话说：**范围本身待定**。范围一改，工期就改。
⇒ 所以本文给的是**按基线逐模块的完成度**，而不是一个工时承诺。

## 4. 各条线的量级（**按现有节奏：一轮 = 一个系统域的规则 + 实现 + 守卫 + 文档 + 验收**）

| 线 | 还差什么 | 量级 | 备注 |
|---|---|---|---|
| **收口当前目标** | 三个数值 + 一次标定 | **1 轮**（≈ 1–2 天） | 等数值即可 |
| **§8 战斗公式** | 伤害 / 命中 / 冷却 / 状态 / AI **五个维度** | **1–2 轮** | **最大的一块**；输入通道已接好（`CombatantSnapshot`） |
| **§12 九种建筑** | 每栋的**用途**要先写明 | **实现便宜，拍板 9 次** | `05` 禁止实现者自行指定 ⇒ 逐栋问 |
| **§9 行为链** | 纠纷 / 复仇 / PvP | **1–2 轮** | 规则为主 |
| **§10 召唤池** | 概率 / 保底 / 重复 | **1 轮** | 规则 + 数值 |
| **§11 世界与大事件** | 机制 + 内容 | **2+ 轮** | 纯内容最贵 |
| **§6 本土剧情** | 内容 | **按内容量定** | 写起来快，设计起来慢 |

⇒ **量级：合计约 6–10 轮**（不含内容产出），按当前每轮 1–3 天的节奏 ⇒ **约 2–4 周**。
⚠️ 这个数**只对得上「范围 = 基线 18 章」**，且**前提是每轮都能定下方向**。

## 5. 分工：什么不占你的时间

| 我这边（不占你时间） | 你那边（每轮都要） |
|---|---|
| 守卫与变异矩阵、参数台账、文档一致性、CI 与导出、证据留存 | **所有规则、数值、内容**：战斗公式、掉落与价格、稀有度、队伍上限、建筑用途、召唤池、行为链、大事件 |
| 每次改动的编译 / 测试 / 真机自检 / 回归 | 每一轮的方向（做什么、做到什么程度） |
| 把结论写进 `07`（决策落文档）与 `06`（验收计划） | 阶段验收 |

⇒ **最大的杠杆在你那边**：技术侧已就位的部分（输入通道、标定工具、验收断言形态）
都能在**拿到数之后**很快落地；而**规则本身定不出来的时候，代码侧无事可做**。

## 6. §7.2「杂谈十类事件」—— 一张更精确的缺口表

基线 §7.2「记什么——事件驱动」是**【已确认】**级，列了**十类**该进杂谈的事件。
逐类核对代码实况（2026-10-21）：

| # | 基线 §7.2 事件 | 已实现？ | 缺的是**什么** |
|---|---|---|---|
| 1 | 英雄首次完成副本 | ✅ `DungeonSettled` / `DungeonLooted` | — |
| 2 | 某次交易发生纠纷 | ❌ | **「被骗 / 纠纷」的判定规则**（§9.5 R2 说「构造一次被骗事件」，但「被骗」是什么没定）＋ 纠纷如何改变关系 |
| 3 | 两名英雄关系恶化 | ❌ | **恶化的触发经历与变化量**（§9.4 只说「四层可以影响倾向」，没说怎么算恶化） |
| 4 | 某位英雄获得稀有装备 | ❌ | **装备系统整体**（基线 §10.4 提到「装备需求」是已确认概念，但装备本身是【待定】） |
| 5 | 英雄受伤 / 康复 | ❌ | **「受伤」的判定**（⇒ 依赖 T-004 战斗公式）＋ **持续多久 / 如何康复**（⇒ 依赖 §4.4 的状态定义，仍是【待定】） |
| 6 | 建筑建成 / 升级 | ✅ `BuildingCompleted` | — |
| 7 | 村庄日常（采集、摆摊、社交等） | ✅ `VillageDailyWork` / `HeroSocialized` / `TradeCompleted` | — |
| 8 | 大事件的发生与结算 | ✅ `SquadDispatched` / `DungeonEncounterFought` / `DungeonSettled` / `SquadBonded` | — |
| 9 | 召唤到新英雄 | ✅ `HeroSummoned` | — |
| 10 | 本土剧情进展 | ❌ | **内容**（本土剧情本身还没做） |

⇒ **已实现 5 / 10**（1、6、7、8、9）。
🔴 **关键结论**：缺的是 **5 类**（2、3、4、5、10），但它们**并不都挂在 T-004 上** ——
逐个查了基线，依赖是分开的：

| 缺哪类 | 真正卡在哪 | 与 T-004 战斗公式的关系 |
|---|---|---|
| 5 英雄受伤 / 康复 | 受伤的**判定**来自战斗伤害；持续与康复来自 §4.4 状态定义（【待定】） | **直接相关**（只解锁「判定」这一半） |
| 2 某次交易发生纠纷 | §9 行为链：「被骗」是什么、纠纷怎么改变关系，都没定 | **无关**（要 §9 行为链规则） |
| 3 两名英雄关系恶化 | §9 关系规则：恶化的触发经历与变化量没定 | **无关**（要 §9 关系规则） |
| 4 某位英雄获得稀有装备 | 装备系统整体（【待定】） | **间接**（战斗公式只提供掉落载体） |
| 10 本土剧情进展 | 内容本身没做 | 无关 |

⇒ **「T-004 落地 ⇒ §7.2 缺口补齐」是不成立的**：T-004 直接解锁的只有第 5 类的**触发条件**，
其余两类要各自的 §9 规则、一类要装备系统、一类要内容。
⇒ 这同时修正了上一版的连带误判：**已实现是 5 / 10，不是 6 / 10**；
缺 **5 类**（2、3、4、5、10），不是 4 类 —— 上一版把「本土剧情进展」漏在了视野之外。

## 7. 下一轮的排序（按**杠杆**排，不按工作量排）

| 顺位 | 做什么 | 杠杆：它一次解锁了什么 |
|---|---|---|
| **1** | **T-004 战斗公式**（伤害 / 命中 / 冷却 / 状态 / AI） | §8 整个模块 ＋ §7.2「受伤/康复」的**触发判定**（持续与康复仍要 §4.4 定）＋ IT-31（队伍配置影响结果）＋ IT-05 的战斗侧 ＋ 掉落与稀有度的**载体**（现在战斗是固定胜率 0.65 的占位，**没有任何东西能测**） |
| **2** | **数值三件套**（基础价格 T-007 / 掉落权重与数量 / 稀有度映射） | 第四阶段收口 ＋ 阶段 5 正式评审 ＋ 经济闭环的最后一环 |
| **3** | **队伍人数上限**（P-10） | 1 个数 ⇒ IT-05 的正向条件落地 |
| **4** | **行为链与关系规则**（纠纷 / 关系恶化） | §7.2 的 2 类 ＋ §9 的 R2/R3/R4 —— **与战斗公式无关**，要单独立规则 |
| **5** | **九种建筑各自的用途** | §12 与 §9 的建筑部分（**实现便宜，拍板 9 次**） |
| 6 | 召唤池 / 世界与大事件 / 本土剧情 | 内容量最大，**放最后**（它们不阻塞别的） |

> **为什么不是按工作量排**：工作量大的（世界大事件、本土剧情）**不阻塞任何别的东西**，
> 而工作量大、又能**一次解锁一串**的只有 **T-004 战斗公式**。
> ⇒ 先做杠杆最大的，不是先做最费时间的。
