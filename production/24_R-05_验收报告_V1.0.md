## 7. 顺带修掉的一处真实缺陷

`--dungeon` 的「战利品已入档」检查原本在**自检把战利品摆上摊又卖掉之后**才取存档快照，
再查「摊主的存档里还有没有这件战利品」。

卖完之后战利品在**买家**的背包里，摊主的背包已空 —— 查出来自然是「没有」。
**那不是入档失败，是查错了时机。**

R-01 时每次掉落 19 份、卖 1 份还剩 18 份，这个错误**一直被「数量足够多」掩盖**；
R-05 的掉落表让每人只分到 1~2 份，它才暴露。检查已移到**战利品刚落地时**取快照。

> 教训：**一个只在小数值下才暴露的检查错误，会被「数据足够多」长期掩盖。**
> 机制一改（同量级的掉落），它立刻现形。

### 7.1 随机性边界：接缝有测试盯住

抽取（R-05）与分配（R-01）**共用同一条随机子流**，顺序固定为「先抽后分」。
抽取消耗掉的随机次数决定了分配从流的**哪一段**开始 ——
这是整条链里唯一一处「改了一处、另一处跟着变」的地方。

| 关注点 | 覆盖 |
|---|---|
| 同一副本标识 → 同样的掉落 + 同样的分配 | ✅ `Pipeline_SameRunId_ProducesIdenticalResult` |
| 种子派生 / 抽取次数 / 分配起点被钉死 | ✅ `Pipeline_FixedRunId_HasGoldenResult`（黄金值 `h-0\|布匹\|1; h-1\|石料\|1`） |
| 分配若改用新流，结果**确实会变** | ✅ `Pipeline_FreshStreamForSplit_ChangesResult` |
| 抽取侧多抽一次会**连锁**改变分配 | ✅ `Pipeline_ExtraDraw_ShiftsAllocation` |
| 抽取侧单独可复现 | ✅ `LootRollerTests.Roll_FixedSeed_IsReproducible` |
| 分配侧单独可复现 | ✅ `LootSplitTests.Split_SameSeed_ReproducesSameAllocation` |
| 种子派生稳定、跨进程不随机 | ✅ `LootSplitTests.DeriveSeed_IsStablePerBusinessId` / `DeriveSeed_IsNotProcessRandomized` |

**管线抽成了函数**（`LootPipeline.Run`），`Main` 与测试**调的是同一段代码** ——
若在测试里复制一份管线，就盯不住 Main 的接线（Main 里调换了，测试照样全绿）。

> **过程中踩到的一个「假绿」**：接缝测试第一版用「抽 3 次 / 3 个参战者」——
> 恰好整除，**分配侧一次随机都没消耗**，接缝根本没被踩到。
> 那个测试红得莫名其妙（不是该红而红），顺着查才发现是这个原因。
> 改用「抽 2 次 / 3 个参战者」（必有余数）后，接缝才真的被测到。
>
> 教训：**断言失败时先问「它是因为该红而红，还是因为运气而红」。**

| 项 | 结论 |
|---|---|
| 存档版本 | **保持 0.4，未升版**。R-05 **不新增任何持久化字段** |

| 既有行为 | 交易、摆摊、自主购物、存读档、关系、事件管线均未变（见 §5 回归） |

## 9. 遗留与边界

**本轮未做（有意）**

- **第二轮数值**（待办）：各副本掉落池、抽取次数、概率、数量区间、基础价格、稀有度归类。
  首版用**明确标注的占位**。
- **NPC 回收机制**、**动态市场 / 供需定价**、**装备词条 / 品质加成**、**保底机制 / 经济模拟**。
- **物品类型轴**（武器/材料/消耗品）—— 首版无消费方。
- **不可堆叠（不可拆分）物品** —— 要扩 `Inventory`（R-01 的 E06 另开任务）。
- **「英雄自由定价」** —— 明确不采纳（会推翻 D-021）；若将来要做单独立项。
- **分阶段掉落**（每阶段独立掉落池）—— 首版只在整场成功后统一掉落。

**已知限制**

- 稀有度在首版是**数据层**（必填、验证器会查），其**消费方在二轮**（价格分档、掉落池分组、界面标记）。
- 正式背包容量仍是无限，「背包满」几乎不触发。
- 掉落表的**副本名由调用方给**（`DefaultLootTables.For(DungeonName)`）——
  不写死「北境旧堡」，避免副本名散落两处、打不响且**静默不掉东西**。

## 10. 结论

**R-05 第一轮机制验收通过。**

副本产出从「一张占位表」变成了「一张可配置、可验证、可复现的掉落表」：
物品有稀有度、掉落按权重抽、配置错了会**明确报错**而不是静默产出垃圾、
同一副本永远得到同一份掉落、掉落不插队进战斗与日常的随机流。

而**交易链路一行未动** —— 价格仍是 D-021 的全球统一价。
这一步省下的不只是几行代码，更是「同物不同价会不会套利」那个还没人回答的问题。

**下一步是第二轮：定数值。** 那需要游戏内实际跑一段时间的数据，
不是坐在这里能拍出来的。
