# R-05：物品价格、掉落与稀有度规则草案 V1.0

- 项目：异世界村庄经营与英雄冒险游戏
- 所属阶段：第四阶段后续任务
- 任务编号：R-05（`15_第四阶段验收报告_V1.0.md` §7 遗留事项第 5 条）
- 决策状态：**机制已确认 · 已实施**（2026-10-19，`07` **D-050**）
- 依据：开发者提供的本草案；第一轮机制拍板（见 §十一）
- 目标：为副本产出什么、产出多少、这些东西值多少钱，建立统一、可验证、可调节的规则框架。

> **本文分两轮决策。**
> **第一轮（机制）已确认并实施** —— 稀有度分级、掉落模型、结算时机、
> 基础价格与摊位售价的关系、物品可交易性、背包满的处理、配置是否版本化。
> **第二轮（数值）待办** —— 各副本的掉落池、每次抽取次数、具体概率、
> 物品数量、基础价格与售价范围。首版用的是**明确标注的占位数值**。

---

## 一、整体设计方向（已确认）

- **掉落与价格分离。** 掉落概率决定物品是否出现，价格决定物品的经济价值，两者不应直接绑定。
- **稀有度与物品类型分离。** 武器、材料、消耗品等属于物品类型；普通、稀有、史诗等属于稀有度。
- **固定基础价格起步。** 第一版不引入动态供需定价，避免自主交易尚未稳定时就引入复杂经济系统。
- **先保证经济可运行。** 掉落表、价格表和物品定义集中管理，避免价格、稀有度和概率散落在各处业务代码中。
- **随机结果可复现。** 所有掉落随机行为使用项目现有的 `SeededRandom` 机制。
- **数值先可调，不追求一次平衡。** 首版重点是建立可验证的规则框架；正式数值经过游戏内观察后再调整。

## 二、稀有度分级（已确认：五级）

普通（Common）· 优秀（Uncommon）· 稀有（Rare）· 史诗（Epic）· 传说（Legendary）

| 级别 | 定位 |
|---|---|
| 普通 | 基础材料、普通消耗品、基础装备。承担日常交易与基础资源供给 |
| 优秀 | 品质较好的材料或装备，中等价值 |
| 稀有 | 中后期有价值的材料、装备或特殊物品 |
| 史诗 | 低频出现的高价值物品，可成为高阶副本的主要追求之一 |
| 传说 | 极低频的特殊物品，适合后续高阶副本和长期目标 |

### 稀有度规则

- **每件可掉落物品拥有明确的稀有度定义。**（已实施：`ItemDefinition.Rarity` 为**必填**字段，没有默认值 —— 免得「忘了标」静默发生）
- 稀有度**不自动决定物品属性**，是否存在品质加成需要另行设计。
- 稀有度**不自动决定基础价格**，应通过独立价格数据配置。
- 尚未实现的高阶物品可以暂不加入掉落表，**不需要为了填满五级而强行制造物品**。

> **实现落点**：稀有度原本**在代码里完全不存在**（`ItemDefinition` 类注释明写「稀有度…不做」），
> 且 `ItemDefinition` 当时**全仓无实例化**。本轮顺带把它接上 ——
> 新增 `ItemCatalog`（物品注册表），让「这个 Id 是什么、什么稀有度」有一个可查的地方。
> 掉落表的验证器正是靠它把「引用了不存在的物品」变成一条明确的报错。

## 三、副本掉落规则（已确认）

### 3.1 结算时机（已确认：**只有整个副本成功后统一掉落**）

- 副本三个阶段（EncounterOne / EncounterTwo / FinalGoal）**不分别掉落**；
  整场成功后统一生成战利品。
- 这与 R-01 的「副本失败不发放战利品」保持一致，也避免了中途退出与重复结算的问题。
- **与现状一致 —— 不需要改代码。**

### 3.2 掉落流程（已实施）

```
副本最终结果
  ├─ 失败 → 不产生战利品
  └─ 成功 → 查掉落表 → 按权重抽取 → 按 R-01 规则分配给实际参战英雄
```

### 3.3 掉落模型（已确认：**权重抽取**）

每个副本一张掉落表，声明「抽几次 + 池子里有什么 + 各能出几个」，按**权重**抽取。

- **优点**：适合控制一次抽取的结果和稀有度分布；产出**数量固定**（抽 K 次就出 K 件）。
- **代价**：需要定义抽取次数（已在表里声明）。
- **同一条可以被抽中多次**，份数累加 —— 最终合成一条战利品记录。
- **权重归一化**：表内权重之和可以是任意正数（写 60/30/10 与写 6/3/1 等价）。

> **为什么不是「逐件独立概率」**：独立判定**控不住总量** ——
> 三个条目各 30% 概率，可能一次都不出，也可能一次出三样。
> 抽 K 次则产出数量固定，稀有度分布完全由权重决定。
>
> **为什么不是「固定掉落条目 + 有限次权重抽取」的混合**：机制复杂度上去了，
> 而当前只有 3 种物品、1 个副本，混合的收益还看不出来。先把单阶段权重抽取做稳。

## 四、稀有度概率模型（**第二轮：数值待定**）

以下数字仅用于讨论规则形态，**不是经过游戏测试的平衡值**：

| 稀有度 | 示例概率 | 设计用途 |
|---|---|---|
| 普通 | 65% | 主要资源来源 |
| 优秀 | 25% | 提供渐进式价值提升 |
| 稀有 | 8% | 形成中期追求 |
| 史诗 | 1.8% | 低频高价值奖励 |
| 传说 | 0.2% | 极低频特殊奖励 |
| 合计 | 100% | 单次稀有度抽取 |

> **注意**：首版**没有**采用「先抽稀有度、再抽物品」的两阶段模型 ——
> 拍板的是**单阶段权重抽取**（§3.3）。上表因此**不作为首版的实现**，
> 它只说明「稀有度分布最终应该由权重表达」这件事的方向。
>
> **不要把「稀有度概率」和「单件物品掉落率」混为一谈。**

**首版实际使用的占位权重**（`DefaultLootTables.For`）：

| 物品 | 权重 | 数量区间 | 稀有度 |
|---|---|---|---|
| 石料 | 60 | 1~2 | 普通 |
| 木料 | 30 | 1~1 | 普通 |
| 布匹 | 10 | 1~1 | 优秀 |

抽取次数 **3**。抽取次数 3 —— 全部为**占位**，二轮重定。

## 五、物品价格规则

### 5.1 固定基础价格（已确认）

- 基础价格必须 **≥ 0**；0 = 「不卖」（`PriceBook` 的既有语义）。
- 同一物品在相同规则版本下具有一致的基础价格。
- **不允许**在 UI、摊位服务和交易服务中各自硬编码价格。
- 暂不使用根据供需实时变化的市场价格。
- 稀有度与价格**分开配置**，避免价格只由稀有度自动推算。

### 5.2 买卖价格（已确认：**保持 D-021 的「同一物品全球统一价」**）

| 模型 | 说明 | 本轮结论 |
|---|---|---|
| A. 同价交易 | 买入价 = 卖出价 | — |
| B. 系统回收折价 | 系统回收价低于基础价格 | **不引入**（会牵出整套回收系统） |
| C. 英雄自由定价 | 英雄摆摊自行设价 | **不采用**（见下） |

**为什么最终没选模型 C**：D-021 / P2-D03 已拍板「固定价格表；**同一物品全球统一价**」，
理由是避免「同物不同价 + 套利」。而当前架构下**摊主本来就不能定价** ——
`PlaceStall` 没有价格参数，价从 `PriceBook.PriceOf` 取。
改成自由定价要动 `PlaceStall` 签名、`Stall` 校验、摆摊 UI，
还得重新回答「同物不同价会不会套利」。**收益不确定、成本明确 → 保持现状。**

> 也就是说：草案原文推荐模型 C，本轮**明确不采纳**。若将来要做，
> 需先推翻 D-021（并同步处理套利规则），单独立项。

**因此 `PriceBook` 的职责不变**：

- `PriceBook` = **基础参考价**（全局统一）。
- 实际成交价 = 摊位在开摊时锁定的 `Stall.UnitPrice`（读档恢复，不按 PriceBook 重验，与 R-01 一致）。

### 5.3 经济约束（既有，R-05 未放宽）

- 交易价格不得为负数。
- 金额与数量的乘法需要检查溢出。
- 买家余额不足时交易失败，状态保持不变。
- 卖家库存不足时交易失败，状态保持不变。
- 摊位费用继续使用现有 5% 规则（`StallFee.Compute`，残差归卖家），**不因 R-05 改价**。

> **价格上限、初始货币数量、各物品的正式价格**目前没有可靠依据，**未填写为正式数值**。

## 六、数据配置结构（已实施，概念上的三类）

| 配置 | 负责内容 | 本轮落点 |
|---|---|---|
| 物品定义 | 物品 ID、显示名、稀有度 | `ItemDefinition` + `ItemCatalog`（`ItemCatalog.Default`） |
| 价格配置 | 基础价格 | `PriceBook`（**既有，未改**） |
| 掉落配置 | 副本标识、抽取次数、掉落条目、权重、数量区间 | `LootTable` + `LootEntry`（`DefaultLootTables.For`） |

**掉落配置引用已有物品 ID，不复制物品定义。** 某个物品尚未注册时，
**掉落表验证阶段就报错**（`LootTableValidator`），而不是静默忽略或创建未知物品。

> 物品**类型**、**是否可交易**、**是否可堆叠**本轮**不引入** ——
> 前者本轮无消费方；后者要扩 `Inventory`（不可拆分物品 = R-01 的 E06，另开任务）。

## 七、边界情况与处理（已实施）

| 场景 | 处理 | 落点 |
|---|---|---|
| 掉落表为空 | 不发放物品，记录配置问题 | `LootTableValidator` 报错 → provider 不发放 + 记一笔 |
| 掉落表引用不存在的物品 | 验证失败，禁止静默产生未知物品 | 验证器查 `ItemCatalog` |
| 掉落物品在价格表里不可售 | 验证失败（发了也没人买得了、也摆不了摊） | 验证器查 `PriceBook.IsSellable` |
| 掉落数量小于等于零 / 区间倒置 | 配置验证失败 | `LootEntry.IsWellFormed` |
| 所有权重均为零 | 配置验证失败，不执行抽取 | 验证器 + 抽取器双重把关 |
| 权重总和不等于 100 | **允许** —— 权重是归一化的 | 抽取器按总和折算 |
| 高稀有度物品未配置 | 允许该副本暂不掉落该等级物品 | 表里没有就是没有 |
| 副本失败 | 不产生副本战利品 | R-01 既有 |
| 副本重复结算 | 不重复抽取或发放同一笔奖励 | R-01 既有（`SettlementKey` 幂等） |
| 参战人数变化 | 使用 R-01 确认的实际参战名单 | R-01 既有 |
| 英雄背包无法接收奖励 | 按 R-01 已定策略：**整次奖励回滚**，记录结算异常 | R-01 既有 |
| 基础价格缺失 | 明确配置错误，不静默赋予任意价格 | 验证器（不可售）+ `PriceBook` 既有语义 |
| 交易金额溢出 | 拒绝交易且不修改状态 | `StallService.TryBuy` 既有 |

## 八、对现有代码的影响（实测核对后的真实情况）

> 草案原文写的是「预计影响点，需要实施前核对真实调用链」。核对结果如下 ——
> **有两条与草案的假设不同**。

### 8.1 物品定义与价格模型

- `ItemDefinition`：**只有 `Id` + `DisplayName`，且全仓无实例化**（R-05 审计的第一条发现）。
  稀有度不存在，类注释明写「稀有度 / 词缀 / 耐久度 / 制作配方——不做」。
- `PriceBook`：`ItemId → 单价`，未登记 = 0 = 「不卖」；`PriceBook.Default` 三个占位价（石料 5 / 木料 3 / 布匹 8）。
  **价格表不入档**（`SaveGame` 无 Prices 字段）。

### 8.2 副本结算

- `Main.ResolveDungeon` 的成功分支；`Main.ComputeLoot` 走 `ILootProvider`。
- **不重复实现副本成功判定** —— 沿用 `DungeonFlowOutcome.Succeeded`。

### 8.3 随机数

- 复用 `DecisionFlow.SeededRandom`（PCG 风格 LCG，`NextDouble(bound)` 返回 **[0,bound) 的 double**）。
- 种子由**副本实例标识**用 FNV-1a 派生（`LootSplit.DeriveSeed`）——
  掉落抽取与 R-01 的分配**共用这一条子流**，顺序固定（先抽后分）。
  好处：同一副本永远得到同一份掉落与分配，读档重放一致；掉落**不插队**进战斗与日常的全局随机流。

### 8.4 英雄背包

- 复用 `Inventory.TryAdd` 与容量约束；分配仍走 R-01 的 `LootSplit`。
- 发放仍走 `ItemGrantService`（受控入口，物品必须在 `PriceBook` 登记为可售）。

### 8.5 摊位与交易

- **本轮未改**（价格模型保持 D-021）：`StallService` / `Trade` 一行未动。
- 基础价格（`PriceBook`）与成交价（`Stall.UnitPrice`）职责保持分离。

### 8.6 存档与幂等

- 掉落配置是**静态数据**，**不入档**；已生成的奖励结果与结算幂等键照旧落盘
  （`AppliedSettlementKeys`，存档版本仍 **0.4**）。

### 8.7 测试

- 新增掉落表验证、权重抽取、数量守恒、可复现性测试；**未重写**现有交易结算。

### 8.8 架构约束

1. Domain 不得引用 Godot（`DomainLayerPurityTests` 守门，全程通过）。
2. 优先复用现有 Application / Domain 结构。
3. 不为 R-05 重构无关模块。
4. 不把尚未确认的**数值**写死成不可调整的技术约束。

## 九、验收标准（已全部通过）

- [x] 每个可掉落物品都有有效物品定义（含稀有度）。
- [x] 掉落表引用不存在的物品时能够明确报错。
- [x] 随机结果在固定种子下可复现。
- [x] 不会生成负数或非法数量的物品。
- [x] 副本失败时不会产生副本战利品。
- [x] 副本成功后，战利品按 R-01 规则进入参战英雄个人背包。
- [x] 同一副本奖励不会重复发放。
- [x] 价格读取统一，摊位与交易不会各自维护互相冲突的基础价格。
- [x] 非法价格、余额不足、库存不足和金额溢出均不会产生部分交易。
- [x] 现有关系、事件、摊位、存档和副本测试通过。
- [x] 完成至少一次真实副本成功 → 获得物品 → 开摊 → 成交的端到端验证。

## 十、明确不属于 R-05 第一轮的工作

1. **动态市场 / 供需定价**（随交易实时变价）。
2. **NPC 回收机制**（系统回购价）。
3. **装备词条 / 品质加成**。
4. **保底机制 / 完整经济模拟**。
5. **不可堆叠（不可拆分）物品** —— 要扩 `Inventory`（R-01 的 E06 另开任务）。
6. **物品类型轴**（武器/材料/消耗品）—— 首版无消费方。
7. **掉落表的分阶段掉落**（每阶段独立掉落池）—— 首版只在整场成功后统一掉落。
8. **正式数值** —— 见 §四，二轮。
