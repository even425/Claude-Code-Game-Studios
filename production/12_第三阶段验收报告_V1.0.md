## 4. 运行时验收证据

### 4.1 `--relations` 自检（真实游戏路径，非单测替身）

```
RELTEST 初始：h-1→h-2 = 0，h-2→h-1 = 0
RELTEST 一次社交：forward changed=True 0→2；backward changed=True 0→2
RELTEST 重复同一业务键：changed=False（必须 false），当前 h-1→h-2 = 2（必须仍是 2）
RELTEST 关系条数 = 2，幂等键 2 个，杂谈 3 条
RELTEST 目标随队时社交：关系 2→2（必须不变），PASS
RELTEST 副本合作：变化对 1，重复同一 runId 后变化对 0（必须 0），当前 h-1→h-2 = 5
RELTEST BuildSave：版本 0.3，关系 2 条，幂等键 4 个
RELTEST 存盘后扰动：h-1→h-2 = 7（应大于存盘时的 5）
RELTEST 读档后：h-1→h-2 = 5（存盘时 5），h-2→h-1 = 5（存盘时 5），幂等键 4 个
RELTEST PASS 关系存档往返一致
```

## 9. 结论

**第三阶段完成。** 第三阶段的核心命题——「英雄之间确实发生了互动；互动按明确规则改变关系；关系影响后续行为；玩家能从真实事件观察到；保存并重新加载后闭环仍成立」——在代码、自动化测试与真实游戏运行中同时成立。

作废设计未复活（时区作息 / `AbsentDays` / `CohesionOf` / 无向 `GrudgeWith` 均未出现）；关系为有向、由经历产生、可存档、可追溯。
