## Summary

村庄的成长不止是「变大」。村长可以在村庄里**配备功能性建筑**：武器店和服装店让召唤来的村民能来买东西，
试炼塔让他们快速变强，防护罩把村庄护起来。本系统不把这些做成四条互不相干的升级线——
**它做的是一张网**：每栋建筑都在喂另一栋，同时也在偷另一栋的资源，而**试炼塔是双向的那一栋**。

玩家每满足一次「我要变强」，村长就少一次「盖房子」和一次「罩得住」。
本文档把这件事写成一个有名字、有数字的机制：**越强越盖不动**。

> **Quick reference** — Layer: `Feature` · Priority: `Vertical Slice` · Key deps: `村庄建造 #5`、`任务与副本 #6`、`时间与作息 #1`、`性格系统 #3`（+ 被 `经济与摆摊 #8`、`交易/背叛/PvP #9`、`村长升级线 #13` 依赖）

## Overview

村庄基础成长（#5）造出来的东西是**长出来的**：烟囱、水井、围栏、铁匠铺、石板路、旗。
它们让村庄看起来更豪华，但**不改变村长能做的事**——盖完和盖之前，村长能做的还是那几件事。

功能性建筑改的正是这件事。盖完武器店，玩家（村民）可以走进村里买东西；盖完试炼塔，
他们可以快速变强；盖完防护罩，村庄不再裸奔。**每盖一栋，村长的下一步动作就多一个。**

这四栋建筑同时构成一张互相喂、互相偷的网。最关键的一环是**试炼塔**：
它是村庄最快的一个 faucet（让村民变强），也是村庄最快的两个 sink（把劳力从工地抽走、
把防护罩的承载推高）。开发商自己的话是「**试炼塔是村长给自己挖的坑**」，
本文档的任务就是把这个坑挖成一个有公式、有边界、可以被 playtest 证伪的东西。

## Player Fantasy

**你是村长，而村庄里住着的每一个人都是你的劳动力、你的顾客、和你抢人的对手。**

这个系统服务的第一种感觉是 **Discovery**（发现）：
某天你发现工地的架子不动了，你顺着查下去——是试炼塔。你没有做错任何事，
是那座塔让你的人觉得盖房子没意思了。**因果链必须在 10 分钟内被玩家自己走通**，
这是 M3 模块名的验收标准（「盖了试炼塔之后盖房真的变慢」）。

第二种是 **Challenge**，而且是**抉择式**的，不是操作式的。玩家永远不会遇到
「我不会用」——试炼塔就是一个按钮。玩家会遇到的是：
「我的人今天到底该去盖房子、去打副本、还是去塔里练功？」
**这三件事抢的是同一批人。** 游戏的乐趣全在这个分配上。

第三种是 **Fantasy**（印钞机）：武器店开门，村民排队进来，你不用派人出去拼命就有进账。
这是三层经济里唯一不消耗村长的命的那一层（brief：「**唯一的印钞机**」）。
玩家应该**爱**这个系统，然后在某一天发现它把塔撑起来了——爱和悔之间那个转折点，
是这个系统最值钱的 30 秒。

**Feel Reference**：《缺氧》的资源管道——你每接上一根管子，产能上升，
但某个没接上的环节会先炸。《星露谷》的作息——同一批人，24 小时只能分配一次。

**这个系统不能变成什么**：不能是四行互不相干的「建筑 A +30% / 建筑 B +30%」。
没有一行公式只服务于自己，每一栋都必须至少喂一栋、并且被一栋偷。

### 玩家可见文案的硬规矩（沿用全项目规矩）

玩家可见文本（UI + 杂谈）中**不得出现**：成功 / 失败 / 获得 / 消耗 / 属性 / 奖励。

| 不写 | 写 |
|---|---|
| 「试炼塔升级成功！」 | 「塔顶那圈灯亮了一圈」 |
| 「获得铁料 ×20」 | 「他们从北坡抬回来二十筐石料」 |
| 「村庄防御 +15%」 | 「罩子往外推了两步」 |
| 「建造速度 -12%」 | （什么都不写。让他自己去看柱子为什么不长了） |

## Detailed Design

### 节点表（本系统只实现这四栋）

| 节点 | 依据 | 盖完之后村长的下一步动作变了什么 | 喂谁 | 被谁偷 |
|---|---|---|---|---|
| **武器店** `WeaponShop` | B | 村民可以买东西 | 货来自？（**未定，OQ-3**） | 吸走村民的停留时间 |
| **服装店** `ClothShop` | B | 同上 | 同上 | 同上 |
| **试炼塔** `TrialTower` | C | 村民可以**快速变强** | —— | **偷工地劳力 + 抬高防护罩承载** |
| **防护罩** `Aegis` | D | 村庄不再裸奔；**罩内可摆摊**（#8） | —— | 吃材料（维护）+ 吃罩内面积 |

**「等等」的处置**：开发者原话在「防护罩」后面写了「**等等**」，
说明他心里还有别的功能性建筑。**本文件只实现这四栋。**
我不替「等等」猜内容——想加什么，全部走 Open Questions（OQ-1）。

### Core Rules

**R1 · 功能性建筑与村庄基础成长共用同一套材料池和同一个工地。**
村庄建造的 `Cost(t) = 30 + 25t`（#5）与本系统的 F5 扣的是**同一个材料池**。
这意味着两栋建筑**互相抢材料**——这是「偷」的最朴素形式，不需要任何额外机制。

**R2 · 建造复用 #5 的全部规则。** 材料在按下建造键的那一刻扣掉，
扣完由在场的人一寸一寸盖起来，进度按 `Σ WorkRate × dt` 推进，
没人时 `rate = 0` 且**没有任何提示**。
**本系统不重新发明建造流程。** 唯一的新增见 R5。

**R3 · 功能性建筑是独立的一条建设序列**，与村庄 tier 阶梯并行，互不消耗对方的位置。
村庄只有一台工地（#5 Core Rule 1）——**同一时刻只能盖一样东西，包括功能性建筑。**
这意味着「先把村庄盖大」和「先开一家店」之间是**直接的时间竞争**。

**R4 · 试炼塔不是一栋「加了数值的建筑」，它是一个 `TowerAppeal` 标量的来源。**
本系统**只产出这个标量**（F2），村民愿不愿意去塔里、去多少，是性格系统 #3 的事。
本系统不定义任何性格权重、不读取任何性格系数。
> 这条是接口纪律：`#3` 定义「莽为什么去塔」，`#7` 只定义「塔今天有多吸引人」。

**R5 · 塔的代价是两条独立的作用路径，它们可以分别被读出来。**

| 路径 | 作用对象 | 效果 | 玩家能不能看见 |
|---|---|---|---|
| **主动吸引** `TowerAppeal` | 村民 | 人更愿意去塔，去塔就不在工地 | 看得见（杂谈写谁进了塔） |
| **被动抽水** `TowerDrain` | 村庄整体 | 建造速度整体乘以 `(1 − TowerDrain)` | **看不见**（没有任何提示） |

> **被动抽水这一条是本系统最重要也最不友好的设计。**
> 玩家盖了塔，看到工地变慢，找不到原因——因为他**没有漏掉任何操作**。
> 这跟 #5 的停工是同一族读数器：杂谈是唯一的解释渠道。
> 但 #5 的停工至少有「人不在」这个可见原因，塔的抽水没有。
> **是否给它一个可见读数，见 OQ-8**（我倾向不给，但那需要开发者点头）。

**R6 · 防护罩的承载每时每刻都在被村民的总战力压着。**
防护罩不是一个「开了就没事」的开关。它的 `ShieldLoad` 随
**村庄 tier + 村民平均战力 + 试炼塔等级** 三项上升（`Village → MeanPower → Tower`）。
这正是依赖图里 `玩家变强 = 防护罩更费` 那条推导边的落点。

**R7 · 罩不是按在场人数算的，是按名册上的人头算的。**
不在线的、睡着的、生病的，罩都得护着。
理由：防护罩保护的是**村庄**，不是「此刻在屏幕上的这几个人」。

**R8 · 试炼塔的升级同时抬高 ShieldLoad。**
塔每升一级，`TowerLoad +3`（F4）。**这是「村庄自己挖的坑」的第二段**，
第一段是 R5 的抽水，第二段是这一条。两段可以分开读、分开调。

**R9 · 商店是村庄唯一不需要人命的 faucet。**
材料从副本来（#6），人命、时间、失败风险也来自副本（#6）。
商店卖货的进账不消耗任何一个人——所以 brief 叫它「**唯一的印钞机**」。
它的上限受**在线人数**天然约束（R14 / F6）。

**R10 · 商店卖什么，本文件不定义。** 开发者只说了「武器店」「服装店」两个名字。
货品表、价格、购买规则全部属于系统 #8「经济与摆摊」。本文件只定义
「有一个可以走进去的地方」和「它给村庄带来一条不花人命的进账」。

**R11 · 防护罩内可以摆摊，摆摊费归村长。** 依据 brief「玩家会在村内、防护罩内自行摆摊，你收摆摊费」。
这条由 #8 实现。本文件只保证**罩建好之后罩内的空间存在**，
并且摆摊费与 F4 的 `ShieldLoad` 是**两条独立的收入**（见 F4 备注）。

**R12 · 铁匠铺的边界（本文档的表态）。**
**铁匠铺的「出现」属于 #5，「生产」属于 #7。** 判据沿用 #5 已写下的那句话：
> 这个东西盖完，村长的**下一步动作**变了吗？没变 → #5；变了 → #7。

铁匠铺现在是 tier 4、只有外形和炉火、什么都不产出 → 完全属于 #5。
**本文件不改变这个现状。** 它只在依赖图里给铁匠铺留了一个**尚未接线的位置**，
等 OQ-3 拍板。⚠️ **本条是表态，不是决议**——见 OQ-3。

**R13 · 没有硬失败。** 罩被压垮不等于村庄毁灭，工地停摆不等于进度倒退，
商店没货不等于游戏结束。任何一种最坏组合都只是「回到副本」。

### States and Transitions

**节点生命周期**（四栋共用）：

| State | Entry Condition | Exit Condition | Behavior |
|-------|-----------------|----------------|----------|
| **未建** | 初始 | 材料够 且 工地空闲 | 建造键显示名字 + 材料数 |
| **施工中** | 材料在按下时已扣 | `progress ≥ 1.0` | 复用 #5 的工地表现（三段式可见） |
| **停摆**（施工中的子状态） | 施工中但 `rate = 0` | 有人重新满足三条件 | **画面无区别，无提示** |
| **运行中** | 盖成 | 拆除（**是否可拆，见 OQ-9**） | 按节点类型产出/承载 |

**试炼塔的额外状态**：

| State | Entry Condition | Exit Condition | Behavior |
|-------|-----------------|----------------|----------|
| **空转** | 运行中，且此刻无人能打（平均战力低于 `TowerGate`） | 有人战力达标 | `TowerGain = 0`，**但 `TowerDrain` 照旧计算** |

> **空转是这个系统的最坏形态**：塔既不给东西，又在抽水。
> 玩家花了材料、盖了塔、结果它空转。**这是有意的**——
> 它逼玩家在盖塔之前先看一眼村民的战力，而不是无脑盖。
> `TowerGate` 的默认值见 F1 备注。

**防护罩的额外状态**：

| State | Entry Condition | Exit Condition | Behavior |
|-------|-----------------|----------------|----------|
| **稳定** | `Capacity ≥ Load` | —— | 罩生效，罩内可摆摊 |
| **吃紧** | `Capacity / Load < 1.20` | `≥ 1.20` | **无警告**，只是杂谈里开始出现「罩子边缘有点抖」 |
| **过载** | `Capacity / Load < 1.00` | `≥ 1.00` | 罩被打破；**后果由 #9 / #12 决定，本文件只输出「罩破了」这一个事件** |

> **过载的边界必须钉死：本文档不定义「谁打进来的、损失多少、能不能修」。**
> 那属于 #9「交易、背叛与 PvP」和 #12「本土角色」。本文件只负责**算出 Load 并抛出事件**。

## Formulas

> **全部数值均为提案，未拍板。** 本节的作用是把结构钉死、把量级标出来，
> 让开发者能对**结构**表态，而不是对**第 37 行那个 0.06** 表态。
> 每张表都标了安全范围——**范围本身比默认值更值得被 review**。

### F1 · 试炼塔的产出（结构已定，函数体未定）

```
每完成一次试炼:
    TowerYield_i = f(TowerLevel, i 的战力, 参与的试炼难度)     ← 函数体见 OQ-2
    TowerYield_i 施加到 i 的成长上
```

⚠️ **本公式当前无法写出具体形式，原因是既有实现没有留下空间：**

`design/gdd/summoning.md` 规定村民的 `Power / Speed / Grit` 在召唤时
`10 + rand(40)` roll 一次，**上界 49 是个硬天花板，且没有成长曲线**。
「让玩家快速升级」如果意味着抬高 `Power`，那么：

```
村民初始 Power ∈ [10, 30]   (roll 均值)
塔最多能把 Power 推到 49
总成长空间 ≈ 19 点，而这 19 点只需要一间塔
```

**试炼塔会在村庄中期就把现有这条成长线榨干。** 这是我在写本文档时发现的、
比「四栋建筑互相咬合」严重得多的结构问题，三个候选解法与各自的数字见 **OQ-2**。
本文档**不替开发者选**，正文里的一切都按「成长出口存在且上界为 `GrowthCap`」书写。

| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| `TowerLevel` | int | 0 – 3 | 本系统 | 塔等级，等于建成的塔栋数（塔升到 3 为顶） |
| `TowerGate` | float | 0 – 10 | 数据表 | **低于此平均战力的塔判定为空转**。默认 **28** |
| `TowerYield_i` | float | **待定** | **OQ-2** | 一次试炼给 i 的成长量 |
| `GrowthCap` | float | **待定** | **OQ-2** | 成长上限。必须 ≥ 49，否则塔会把现有 roll 空间撑爆 |

**边界情况**：
- `TowerGate` 默认 28 的来历：初始 roll 均值是 20，Top-roll 是 49，
  28 意味着**开局的中位村民打不动塔，要练一阵**。这样塔在村庄早期不是白盖的。
- **空转时 `TowerYield = 0`，但 `TowerDrain` 与 `TowerLoad` 全部照算**（见 Edge Cases E4）。

**算例（结构演示，`TowerYield` 用占位值 3）**：
```
村庄 tier 3，平均战力 26，塔等级 1
26 < TowerGate(28)  →  空转
TowerYield = 0；TowerDrain 仍按 F3 计算；TowerLoad 仍 +3
玩家此时唯一的正确操作是：关掉塔，或者再等两天让他们练上去
```

### F2 · 塔的吸引力（只产出标量，不碰性格）

```
TowerAppeal = AppealBase × TowerLevel × GrowthFactor(MeanPower)
GrowthFactor = clamp(1 + (MeanPower − AppealRef) / AppealSpan, 0.5, 2.0)
```

| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| `AppealBase` | float | 0.5 – 3.0 | 数据表 | 每日吸引力基准。默认 **1.0** |
| `TowerLevel` | int | 0 – 3 | 本系统 | 0–3 |
| `MeanPower` | float | 10 – 49（未来 `GrowthCap`） | #2 召唤 | **名册全员**战力均值，**不含村长** |
| `AppealRef` | int | 20 – 35 | 数据表 | 中位点，默认 **28**（与 `TowerGate` 同值） |
| `AppealSpan` | int | 10 – 40 | 数据表 | 斜率，默认 **20** |
| `TowerAppeal` | float | **0 – 6.0** | 计算 | 交给 #3 作为一个偏好权重 |

**输出范围推导**：
- 最低：`1.0 × 0 × …` = **0**（没塔时恒为 0，公式不参与计算）
- 塔 1 级、平均 28：`1.0 × 1 × 1.0 = ` **1.0**（一个中性单位）
- 塔 3 级、平均 45（强村）：`1.0 × 3 × (1 + 17/20 = 1.85) = ` **5.55**
- 塔 3 级、平均 10（弱村）：`1.0 × 3 × clamp(1 − 18/20 = 0.10, 0.5, 2.0) = 1.5 = ` **1.5**

**边界情况**：
- **`clamp` 的下界 0.5 是本公式唯一的下限保护。** 没有它，一个手气差的村庄
  （平均 10）会让 `TowerAppeal = 3 × 0.10 = 0.3`，塔变成**没人去的地方**——
  空转 + 抽水 = 最坏形态，而玩家对最坏形态没有任何操作空间。
- `TowerAppeal` 只是个标量。**村民去不去、去几个人、去多久，全部由 #3 决定**（R4）。
  本公式不预测任何个人的行为，也不得被 #3 反过来读。
- 村长**不参与** `MeanPower`：他是玩家，不受时区作息约束，
  把他算进去会让「大家变强了」这件事被一个不可控的量污染。

### F3 · 塔的被动抽水（本系统最重要的一条公式）

```
TowerDrain = DrainBase × TowerLevel × (MeanPower / DrainPowerRef)
TowerDrain = min(TowerDrain, DrainMax)

EffectiveBuildRate = BaseBuildRate × (1 − TowerDrain)
```

| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| `DrainBase` | float | 0.00 – 0.15 | 数据表 | 每级塔的抽水基准。默认 **0.06** |
| `TowerLevel` | int | 0 – 3 | 本系统 | |
| `MeanPower` | float | 10 – 49 | F2 | 与 F2 同一个量，不重复计算 |
| `DrainPowerRef` | int | 20 – 40 | 数据表 | 分母。默认 **30**（与初始 roll 均值 20 相比偏高，刻意向「变强后才咬人」倾斜） |
| `DrainMax` | float | 0.10 – 0.60 | 数据表 | **硬上限**。默认 **0.45** |
| `EffectiveBuildRate` | float | ≥ 0.55 × Base | 计算 | 传给 #5 的 `rate` |

**输出范围推导**：

| 情形 | TowerLevel | MeanPower | 计算 | `TowerDrain` | 建造速度 |
|---|---|---|---|---|---|
| 没盖塔 | 0 | 任意 | `0.06 × 0 × …` | **0.000** | 100% |
| 塔 1、村落中庸 | 1 | 30 | `0.06 × 1 × 1.00` | **0.060** | 94% |
| 塔 2、村落中庸 | 2 | 30 | `0.06 × 2 × 1.00` | **0.120** | 88% |
| 塔 3、强村 | 3 | 45 | `0.06 × 3 × 1.50` | **0.270** | 73% |
| 塔 3、极强村 | 3 | 49 | `0.06 × 3 × 1.63` | **0.294** | 71% |
| 封顶保护 | 3 | 49 | 若 `DrainBase` 被调到 0.10 | `min(0.49, 0.45)` | **55%** |

**为什么上限是 0.45**：再高就逼近 #5 的病理下界。
`village-building.md` 的最坏单人 `WorkRate = 0.000665`，161 天盖完一栋。
如果塔再抽掉 50%，一个已经很难的村庄会变成**软锁**。而 brief 明写「没有硬失败」。
**`DrainMax` 是「村庄永远还能盖得动」这条约束的数学表达。**

**边界情况**：
- **取 `min` 必须在 F3 内部完成**，不能依赖 `DrainBase` 调得足够小。
  这是硬保护，不是调参建议。
- `TowerDrain` 是**乘数不是加法**。它与 #5 现有的所有乘数
  （性格 / 投入度 / 状态）**同乘**。所以磨洋工的 0.40 和塔的 0.06 相乘，
  不是相加——这条不能让实现写成 `rate += drain`。
- `MeanPower` 用名册全员，**与 R7 同一个口径**。罩保护全部人，塔也影响全部人。
- **无提示。** 见 R5。

### F4 · 防护罩的承载与容量

```
ShieldLoad = TierLoad × VillageTier
           + PowerLoad × MeanPower
           + TowerLoad × TowerLevel

ShieldCapacity = CapBase × (1 + CapStep × ShieldLevel)

Integrity = ShieldCapacity / ShieldLoad
吃紧 ⟺ Integrity < 1.20        过载 ⟺ Integrity < 1.00
```

| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| `VillageTier` | int | 0 – 5 | #5 | **村庄基础成长等级**（依赖图里「吸收村庄等级」那条边） |
| `TierLoad` | int | 0 – 15 | 数据表 | 村庄越大罩越吃力。默认 **6**（tier 5 → 30） |
| `PowerLoad` | float | 0.00 – 0.50 | 数据表 | **每个战力点的罩负荷**。默认 **0.10** |
| `MeanPower` | float | 10 – 49 | F2/F3 | 全员战力均值 |
| `TowerLevel` | int | 0 – 3 | F2 | **塔每升一级 +3**（R8） |
| `TowerLoad` | int | 0 – 10 | 数据表 | 默认 **3** |
| `ShieldLevel` | int | 0 – 5 | 本系统 | 防护罩等级（= 建成的罩栋数） |
| `CapBase` | int | 5 – 40 | 数据表 | 罩 0 级的基础容量。默认 **15** |
| `CapStep` | float | 0.2 – 1.0 | 数据表 | 每级的容量增幅。默认 **0.50** |

**`ShieldLoad` 取值范围：**
```
最小（tier 0、战力 10、无塔）  = 6×0 + 0.10×10 + 3×0 =  1.0
中位（tier 3、战力 30、塔 2）  = 6×3 + 0.10×30 + 3×2 = 24.0
最大（tier 5、战力 49、塔 3）  = 6×5 + 0.10×49 + 3×3 = 43.9
```

**`ShieldCapacity` 取值范围：** 15 / 22.5 / 30.0 / 37.5 / 45.0 / 52.5（level 0–5）

**四个关键配比（这张表是本公式的验收清单）**：

| 场景 | Load | 需要的罩级 | Capacity | Integrity | 状态 |
|---|---|---|---|---|---|
| 早期：tier 1、战力 25、无塔 | 6.0 + 2.5 = **8.5** | 0 | 15.0 | **1.76** | 稳定，早期罩几乎白给 |
| 中期：tier 3、战力 30、塔 1 | 18 + 3.0 + 3 = **24.0** | 2 | 30.0 | **1.25** | 刚好吃紧 |
| **陷阱：tier 5、战力 49、塔 3，但罩只有 2 级** | 30 + 4.9 + 9 = **43.9** | — | 30.0 | **0.68** | 🔴 **过载** |
| 终局：同上，罩 5 级 | **43.9** | 5 | 52.5 | **1.20** | 恰好不超 |

**这张表就是「村长给自己挖的坑」的完整形状**：
塔升到 3 之后，罩的容量必须跟上，否则村庄裸奔。
而罩要跟上就得继续盖，盖就得有材料，材料要么来自副本（出人命）、
要么来自商店（可是商店要人口，人口是村民，村民都在塔里）。
**闭环收紧到最后必须有人回副本——这就是这张网在咬合。**

**边界情况**：
- **`ShieldLoad > 0` 恒成立**（最小值 1.0），所以 `Integrity` 不会除零。
  即便 `ShieldLevel = 0`，`Capacity = 15` 也 > Load 的常见值，**裸奔只发生在中后期**。
  这是有意的：防护罩在村庄早期是可有可无的（D 只说「保护村庄不被外面攻击」，
  没说他早期就需要它）。
- **`MeanPower` 上升会让罩变贵，而试炼塔正是让 `MeanPower` 上升的原因。**
  F1 → F3 → F4 是**一条链**，不是三个独立的旋钮。
  调 F1 时必须重算 F4。
- **罩的容量是线性的（`CapStep = 0.5`），负荷也是线性的。**
  两条线斜率不同（容量 +7.5/级，负荷最多 +3/级），所以罩是**追得上的**，
  前提是玩家在建塔之后还记得建罩。
- ⚠️ **罩的维护费（另一条独立成本）本文件不公式化。**
  开发者只说了「防护罩，作用是保护村庄不被外面攻击」，没说是要持续花钱的。
  **「罩要维护费」是我从「互相偷」推出来的，需要拍板（OQ-6）。**
  在拍板之前，上表的所有数字**不含任何维护费**。

### F5 · 功能性建筑的成本

```
Cost(node, f) = CostBase + CostStep × f        f = 0..3（已建成的功能建筑数）
```

| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| `CostBase` | int | 25 – 70 | 数据表 | 第一栋。默认 **40** |
| `CostStep` | int | 30 – 60 | 数据表 | 每栋递增。默认 **45** |
| `f` | int | 0 – 3 | 本系统 | 已建成的功能建筑数 |

**成本表**：

| f | 建筑 | Cost | 累计 |
|---|---|---|---|
| 0 | 武器店 | 40 | 40 |
| 1 | 服装店 | 85 | 125 |
| 2 | 试炼塔 | 130 | 255 |
| 3 | 防护罩 | 175 | **430** |

**为什么是 430 这个量级（这是本公式唯一值得 review 的一行）：**
- 村庄基础五级阶梯合计 **400** 材料（#5 F5，已是实测值）。
- 副本一趟带回 4 – 176 材料，典型 40 – 60（#6 F3）。
- 所以 **430 ≈ 一个完整村庄阶梯的 1.08 倍 ≈ 再跑 8–11 趟远征**。
- **论据**：Vertical Slice 的验收标准是「摸到全部四个节点」。
  如果功能建筑合计要两倍村庄阶梯，Vertical Slice 就根本摸不全；
  如果远小于村庄阶梯，这四栋就没有存在感，依赖网建不起来。
- ⚠️ **建造顺序由玩家自己决定**——本表不指定「先盖哪个」。
  「塔在罩前面」这种顺序是玩家的选择，不是系统的规定。

**边界情况**：
- 四栋**建造顺序自由**，但 `TowerLevel` 与 `ShieldLevel` 是**计数器**，
  不是「第几栋」。所以先盖罩后盖塔和反过来盖，得到的等级是一样的。
- 成本扣的是 **R1 的同一个材料池**，扣完就少了，村庄基础升级也得让路。
- **不设建造前置**（「必须先有铁匠铺才能有武器店」这类约束没人提过，见 OQ-3）。

### F6 · 商店进账的上限

```
ShopIncome ≤ OnlineCount × PerCapitaCap × AvgPrice
ShopIncome 全部进入材料总池（按货品对应的 MaterialId 分项入账）
```

| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| `OnlineCount` | int | 0 – 人数 | #1 作息 | **此刻在线**的村民数（不在的不买东西） |
| `PerCapitaCap` | int | 0 – 3 | 数据表 | 每人每次在线的成交上限。默认 **1** |
| `AvgPrice` | float | > 0 | **#8 定义** | 本文件不定义 |
| `ShopIncome` | float | 0 – ∞ | 计算 | 计入材料总池 |

**为什么这是个上限而不是等式**：需求、定价、购买意愿全部属于 #8。
本文件只承诺两件事——**商店是一条不需要人命的 faucet**（R9），
以及**它的产出会被在线人数天然卡住**（farm）。

**这条上限就是防止「印钞机变成无限 faucet」的那道闸。**
如果不做 `OnlineCount` 这个上限，一个村庄只要有一个人上线就能稳定刷钱，
材料会脱离人数线性增长——**副本那条线（村长出人命）就再也无人愿意选**，
三层经济塌成一层。这是本系统最重要的一个防退化约束。

**边界情况**：
- `OnlineCount = 0` → 进账 0。**村庄全睡着时商店不产钱**，符合「保护村庄的是罩，不是店」。
- 进账按 `MaterialId` **分项**入账，沿用 #6 F6 的规则，
  不能一笔糊涂账进 `TotalMaterials`（否则 #6 的缺陷 1 又回来了）。

## Edge Cases

| # | 场景 | 预期行为 | 为什么 |
|---|---|---|---|
| **E1** | **塔盖到 3 级，但平均战力从未达 `TowerGate`** | 塔永久空转：`TowerYield = 0`，`TowerDrain` 与 `TowerLoad` **照算** | 这是本系统设计的最坏形态。有意为之：它让「盖塔之前先看看你的人」成为一个有代价的判断。**可逃离**——见 E2 |
| **E2** | 塔空转，且玩家**不想再被抽水** | **能否拆除塔？当前实现：不能。** | ⚠️ 这是一个真实的软锁候选（钱花了、盖了、没用、又抽水）。**拆除机制见 OQ-9**，本文档不发明它 |
| **E3** | 全村人一瞬间都变强（抽到一批高 roll 的新村民） | `MeanPower` 跳变 → `TowerDrain` 与 `ShieldLoad` **同帧跳变**。若 Load 越过 Capacity，**罩立刻过载** | 罩按名册算（R7），新招的人一进门就压罩。这是有意的——**新人也是要养的** |
| **E4** | 塔 `TowerLevel = 3` 且空转（E1） | 建造速度 ×0.73，防护罩 +9 负荷，产出 0 | 见 E1。**三重惩罚同时生效且全部不可逆**——这是 E1 严重性的来源 |
| **E5** | 村庄升级（tier +1）时正在建功能建筑 | **不允许并行。** #5 只有一台工地（R3）。想盖店就得等村庄那一栋盖完 | 「一次只盖一样」是 #5 已定的简化，本系统不复用也不推翻它 |
| **E6** | 材料只够盖一栋，村庄升级和功能建筑同时想盖 | **玩家自己选。** 本系统不排序、不推荐、不高亮 | 这正是 R3 想制造的竞争。系统替玩家选 = 假选择 |
| **E7** | 玩家把所有人派去副本，工地没人，同时塔也空转 | `rate = 0`，进度冻结，**无提示**（#5 规则），塔无产出，材料照样进账 | 三条线并行，互不阻塞。这是 M0 地「不按键村庄也在变」的一部分 |
| **E8** | 商店没货可卖（货品库存为 0） | 玩家进店看到空的架子；进账 0 | 村庄被迫回到副本那条线（出人命）。**这是设计意图，不是惩罚**——印钞机永远不该是免费的 |
| **E9** | `ShieldLoad > ShieldCapacity`，同时**全村人都在塔里** | 罩破，人在塔里，村庄无人防守 | 🔴 **全局最坏状态。** 本文件只输出「罩破了」这一个事件；后果归 #9 / #12 |
| **E10** | 罩破了之后 `ShieldLevel` 归零还是要重建？ | **待定（OQ-6）。** 当前实现：罩的状态是可恢复的（Load 降回 Capacity 以下即恢复），**建筑本身不消失** | 「罩破了就没了」是硬失败，违反 brief。**但「破了之后要不要花材料修」没人提过** |
| **E11** | 防护罩没建（`ShieldLevel = 0`）但 Load 已经不低 | `Capacity = 15`，Load 到 15 才过载。中期基本裸奔 | 有意的（D 只说保护，没说从哪一级开始需要） |
| **E12** | 玩家在线人数为 0 时塔的吸引力 | `TowerAppeal` 仍按名册计算（不按在线）——它是一个**村庄属性**不是**在线属性**。但没人去打，产出自然为 0 | 与 R7 同口径：**塔和罩都按名册，不按在场** |
| **E13** | 同一时刻两个人同时点建造 | 扣第二次材料的那一帧，`rate` 重算，工地不重置 | #5 已有处理（「已在施工时按 Q → 直接 return」）。本系统不引入并行 |
| **E14** | `MeanPower` 的口径里混进了村长 | **禁止。** 村长是玩家，不受作息约束，Power 不可预测 | 口径一旦不纯，`DrainMax` / `ShieldLoad` 的封顶推理全部失效 |
| **E15** | 材料被塔和罩吃光，村庄连基础升级都做不了 | **不阻止。** brief：「卡住 = 材料不够」 | 「塔和罩要保村庄升级」是**保护性设计**，会消解整个取舍。见 OQ-7 |
| **E16** | `TowerDrain` 被实现成了加法而不是乘数 | 单元测试必须失败（见 Acceptance Criteria A7） | 乘/加的错误会让塔与性格、投入度、状态乘数的组合关系整个崩掉 |

### 边界：本系统 vs 村庄建造 #5

判据沿用 #5 已写下的原句：

> 这个东西盖完，村长的**下一步动作**变了吗？没变 → #5；变了 → #7。

| 归 #5（长出来的） | 归 #7（用得上的） |
|---|---|
| 烟囱、水井、围栏、**铁匠铺（当前形态）**、石板路、旗、更亮的土屋、能种的地 | **武器店、服装店、试炼塔、防护罩** |

**⚠️ 铁匠铺是烫手边界，本文件给出表态但不给出决议：**

- **我的表态**：铁匠铺应该**一分为二**——「它出现」留在 #5（tier 4），
  「它生产」归 #7。因为它一旦开始产武器，村长的下一步动作就变了（多了卖货的可能），
  判据明确指向 #7。
- **我不这么做的理由**：它现在**什么都不产出**（只有外形和炉火）。
  在它真的开始产东西之前划界，等于凭空宣布一个还不存在的能力属于我。
- **未决**：见 **OQ-3**。`village-building.md` OQ-1 与本文档 OQ-3 是**同一个问题的两个副本**，
  需要一次性拍板，不能各写各的。

## Tuning Knobs

> 标 ⚠️ 的属于别的系统，本系统只读不写。

| Parameter | Current | Safe Range | 类别 | 调大会怎样 | 调小会怎样 |
|---|---|---|---|---|---|
| `CostBase` | 40 | 25 – 70 | curve | Vertical Slice 摸不全四栋 | 功能建筑没存在感，依赖网建不起来 |
| `CostStep` | 45 | 30 – 60 | curve | 后期盖第四栋要跑很久 | 后期太松，材料约束消失 |
| `TowerGate` | 28 | 20 – 35 | gate | 塔太晚可用 → E1 空转期拉长 | 塔开局就好用 → R5 的「先看人」判断消失 |
| `AppealBase` | 1.0 | 0.5 – 3.0 | curve | 塔变成黑洞，全村跑去塔里 | 塔没人去，R5 的主动吸引路径形同虚设 |
| `AppealSpan` | 20 | 10 – 40 | curve | 强村吸力拉不开差距 | 「变强了所以更想去塔」的因果变弱 |
| `DrainBase` | 0.06 | 0.00 – 0.15 | curve | 盖塔即慢性自伤，R5 变成陷阱 | 塔近乎免费，M3 模块名的验收标准过不了 |
| `DrainPowerRef` | 30 | 20 – 40 | curve | 前期就开始抽水 | 抽水只在后期咬人，「村庄自己挖的坑」变成立即生效 |
| `DrainMax` | **0.45** | 0.10 – 0.60 | gate | >0.5 逼近 #5 的软锁 | 塔几乎不偷，「坑」不成立 |
| `TowerLoad` | 3 | 0 – 10 | curve | 塔和罩死死咬住，塔一升罩就危险 | 塔白盖（只有 drain 一个代价） |
| `PowerLoad` | 0.10 | 0.00 – 0.50 | curve | 「玩家变强 = 罩更费」这条边变得主导 | 罩只吃村庄等级，玩家变强不要钱 |
| `TierLoad` | 6 | 0 – 15 | curve | 村庄盖大就要付罩钱（村长的两难） | 罩只吃玩家战力那一条边 |
| `CapBase` | 15 | 5 – 40 | curve | 中期裸奔变成常态 | 早期就得建罩，D 变成强制 |
| `CapStep` | 0.50 | 0.2 – 1.0 | curve | 罩追得上，坑的代价温和 | 追不上，E9 过载成为常态 → 无硬失败被破坏 |
| `ShieldLevel` 上限 | 5 | 3 – 8 | gate | 罩成长线拉长（#13 要协同） | 终局容量不够，F4 的陷阱格提前出现 |
| `PerCapitaCap` | 1 | 0 – 3 | curve | 印钞机变强 → 副本那条线无人选 | 商店没存在感，「唯一的印钞机」名不副实 |
| ⚠️ `DayLength` | 75s | 45 – 180 | gate | 见 #5 的同名旋钮，本系统全跟着变 | |
| ⚠️ `WorkRate` 全部系数 | 见 #3 | — | curve | **不要为了塔去调它**。会伤到性格系统的可读性 | |
| ⚠️ `TotalMaterials` 产出速率 | 见 #6 | — | curve | **不要为了商店去调它**。会伤到「副本是唯一人命来源」这条 | |

**调参顺序（重要）：**
1. 先调 `CostStep`（最容易被玩家感觉出来，且不影响任何一条公式的形状）
2. 再调 `DrainMax` + `CapStep` 这一对——**它们一起决定「坑」有多深**，
   必须配着调，单独调任何一边都会让 F4 的四个关键配比全乱
3. 最后才动 `PowerLoad` / `TierLoad`（它们是三条 load 边里最不重要的两条）
4. **`TowerGate` 优先级高于所有数值**——它决定 E1 这个最坏形态会不会常态发生

## Acceptance Criteria

### 功能性（QA 不需要仪表，盯屏幕就能判）

- [ ] **A1 · 建造与 #5 完全同构**：建一栋功能建筑的完整过程（扣料 → 架子 → 三段式可见 → 盖成）
      在视觉上与建一栋村庄建筑**无法区分**。同一时刻只有一个工地，按第二次无效。
- [ ] **A2 · 四栋合计 430 材料**：从零材料开新档，按固定顺序建完四栋，
      顶栏材料数恰好从 `X` 减到 `X − 430`（逐栋核对 40 / 85 / 130 / 175）。
- [ ] **A3 · 抽水是真的（★ 本系统的核心验收）**：建塔前记录一次完整建造耗时 `T₀`
      （从扣料到盖成）。建起 1 级塔之后再建同样一栋，耗时 `T₁`。
      **`T₁ / T₀` 必须在 `[1.06, 1.40]` 之间**——不是 1.00（没抽水），
      也不是 2.0（抽太狠）。塔 3 级时应在 `[1.25, 2.0]`。
      > 这是 M3 模块名「**盖了试炼塔之后盖房真的变慢**」的量化验收。
- [ ] **A4 · 抽水是乘法不是加法**：`TowerDrain` 从 0.06 改到 0.12 时，
      建造耗时的变化**小于 2 倍**（乘法特征）；若接近 2 倍，说明实现写成了加法。
- [ ] **A5 · 塔空转是可见的**：把 `TowerGate` 调到 99，建塔后连续观察 3 天：
      杂谈里出现「塔里空着」类文本，**建造变慢照常发生**，
      顶栏材料**没有**因为塔而增加任何一项。
- [ ] **A6 · 罩承载按名册算（R7）**：让一个高战力村民下线。
      罩的吃紧状态**不应消失**；`MeanPower` 不因为下线而变化。
- [ ] **A7 · F4 四个关键配比可复现**：按 F4 的表逐格构造
      （tier / 战力 / 塔级 / 罩级 四个输入），确认 Load 与 Capacity 逐格命中。
      特别地，「tier 5 + 战力 49 + 塔 3 + 罩 2 级」必须判为**过载**。
- [ ] **A8 · 恢复是可能的**：制造一次过载（罩破），然后让 `MeanPower` 降下来
      （或塔空转使 `TowerLoad` 不再计入），罩**必须回到稳定**。
      **村庄不允许进入不可逆的失败态**（brief：没有硬失败）。
- [ ] **A9 · 商店不花人命**：连续 3 个游戏日**不发布任何任务**，只靠商店，
      材料池仍然净增长（若 F6 的 `PerCapitaCap` 与货品表已由 #8 填好）。
- [ ] **A10 · 商店有上限**：把在线人数降到 1 与 20，商店进账应有可见差异
      （近似 1:20 的量级差，而不是线性无差）。
- [ ] **A11 · 无系统词**：跑 20 个游戏日，全屏文本检索
      「成功 / 失败 / 获得 / 消耗 / 属性 / 奖励」——**0 命中**。
- [ ] **A12 · 无隐藏开关**：`TowerDrain` 生效时，界面上**不出现任何**
      「建造速度 −X%」字样；`Integrity` 不出现在任何面板上。
- [ ] **A13 · 铁匠铺归属未被破坏**：本系统上线后，铁匠铺**仍然只产出外形和炉火**，
      村庄 tier 阶梯仍能走到 tier 4 并显示铁匠铺。**OQ-3 拍板前不许动它。**
- [ ] **A14 · 无硬编码**：全部 15 个旋钮在外部数据文件里；改数值不需要改代码。

### 体验性（playtest，看有没有人被坑到）

- [ ] **B1 · 取舍被发现，不是被告知**：试玩者在 10 分钟内自己说出
      「我把人送去塔里，工地就没人了」——**不需要任何提示**。
- [ ] **B2 · 没人说「BUG」**：盖塔后盖房变慢这件事，试玩者的描述是
      「人都去塔里了」或「我把人都派出去了」，**不是**「BUG」「卡了」「不合理」。
- [ ] **B3 · 坑的形状是预期的**：让试玩者面对「塔 3 级 + 罩 2 级」的局面，
      大部分人会意识到罩扛不住并主动去补——**说明 F4 的配比是可读的**。
- [ ] **B4 · 玩家想盖第二座塔**：至少 50% 试玩者在盖完 1 级塔之后**主动想盖第二级**，
      而不是觉得「够了」。若普遍不想盖，`DrainMax` / `CostStep` 需要下调。
- [ ] **B5 · 试炼塔不是纯负担**：试玩者在提到塔时，**不能只用负面词**
      （坑、亏、偷）。若 100% 是负面，说明 `TowerYield`（OQ-2）给得不够。

### 回归守卫（**这条不许被改掉**）

- [ ] `godot --headless --path . -- --selftest --stalltest` 仍复现
      `design/gdd/village-building.md` Acceptance Criteria 里那组实测：

```
22:28  在村1/3  工地上1人  速度0.0153  进度 4.6%
00:28  在村0/3  工地上0人  速度0.0000  进度 4.7%   ← 人走了
10:35  在村3/3  工地上1人  速度0.0061  进度 4.8%   ← 人回来了
```

**本系统不得改动 `WorkRate` 的任何系数。** 一旦 `0.0061 / 0.0153 ≠ 0.40`，
说明有人为了塔去动了性格或状态的乘数——那条路是禁的（见 Tuning Knobs 最后两行）。
