## Summary

村庄从三间土屋长成王国第一的城，中间隔着五级台阶。玩家按 Q 开工、付材料，剩下的**由还在村里的人一寸一寸盖出来**——架子一天天长高，墙到三分之一才起，梁到七成才上。看不见人，工地就停在原地不动，时间照走。玩家手上唯一能拧的旋钮是：**队伍里的人出去跑任务（那是材料的唯一来源），没派出去的留下盖房子。** 派出去的人越多，盖得越慢；全派出去就没人盖。

> **Quick reference** — Layer: `Core` · Priority: `MVP` · Key deps: `时间与作息`、`性格系统`、`配队与配合`（+ 被 `功能性建筑与依赖网`、`村长升级线` 依赖）

## Overview

玩家面对的是一块 15×10 格的地，开局上面只有三间土屋。村庄不是一个等级条被填满，而是一个每天都在被人推着往前挪的现场——有人扛梁，有人砌墙，有人蹲在工地边上不动因为他去跑任务了。升级不是「扣材料→建筑凭空出现」，是「扣材料→工地上出现一副架子→每天有人来的时候架子高一点」。玩家看村庄长大的方式，是看一张俯视的等距地图上多出一口井、多出一圈围栏、多出一间冒火光的铁匠铺。

这个系统存在的理由是 game-brief 的 Core loop 第 5 条：**「他们真的在建房子，你看得见。」** 它是「你不按键村庄也在变」这个卖点唯一能被眼睛确认的地方——人口涨了会怎样，你得先有一栋会长的房子才知道。

## Player Fantasy

玩家是村长，不是包工头。**你不该看见工地停摆。**

开这个系统想服务的第一种感觉是 **Sensation / Discovery** 的复合：某天你只是打开游戏看了一眼地图，发现井已经在了，围栏已经绕了半圈——而你完全不记得是谁干的、哪一天干的。这就是一个真实的村庄在没人管的时候的样子。

第二种感觉是 **Challenge，但不是战斗那种**：卡住的时候你知道卡在哪。「材料不够」是一种卡法，「能干活的人这会儿正好不在」是另一种，「我昨天把他们全派出去赚材料了，现在工地没人」是最难受的一种。**这三种都要可归因、可预见、不能有隐藏开关**——这直接对应 game-brief 的「没有硬失败」：卡住 = 材料不够，或者能撑这件事的人正好不在。

第三种是 **Fellowship**，但形式很土：两个性格不合的人抬同一根梁，谁也没嫌重。这种「事情就这么成了」的协同感不靠数值面板，靠杂谈里那一行字。

**反面（这个系统不能变成什么样）：** 不能是一个「一键升级、等 10 秒、弹『升级成功』、房子替换成新模型」的菜单项。任何时刻玩家按下升级键之后的第一反应，应该是「工地上怎么来人了」，而不是「菜单里多了一项」。

## Detailed Design

### Core Rules

**1. 村庄只有一台工地，一次只盖一样东西。** 工地固定在地图坐标 `(6.2, 5.6)`（屏幕中心偏下），全局唯一，没有选址，没有并行。

**2. 五级台阶是直线的一条序列。** 现状 tier `t` 只能升到 `t+1`，不能跳，不能回头。

| 现状 tier | 现状名 | 按下 Q 的名字 | 升到 | 升后名 | 材料 |
|---|---|---|---|---|---|
| 0 | 破落户 | 盖第四间屋 | 1 | 冒险者旅舍 | 30 |
| 1 | 冒险者旅舍 | 挖井 | 2 | 有井的村子 | 55 |
| 2 | 有井的村子 | 围起村子 | 3 | 有围墙的村子 | 80 |
| 3 | 有围墙的村子 | 起铁匠铺 | 4 | 铁匠铺 | 105 |
| 4 | 铁匠铺 | 铺石板路、立旗 | 5 | 王国第一的城 | 130 |

**3. 材料在按下 Q 的那一瞬间扣掉，不是盖完再扣。** 付完材料的瞬间，工地出现在村中心，架子的四根柱子高度归零，进度归零。

**4. 开一次工时，当场在村里名单上的所有人被分成两类：**
- **在队伍里的** → `ToSite = false`。他们照常接任务、跑副本、赚材料。
- **不在队伍里的** → `ToSite = true`。他们走到工地 `(6.2, 5.6)` 站住，开始盖。
- 队伍**不因开工而清空**。盖完之后队伍原样还在，下一趟任务照发。

**5. 停工条件是唯一的，而且很硬：进度只在「至少有一个同时满足三个条件的人」时推进。**

三个条件同时成立才计入：
- `ToSite == true`（被派到工地）
- `Away == false`（没跟着队伍出去跑任务）
- 在场（在线且没生病缺席）

一个都不成立 → 本帧 `rate = 0`，**进度一个数都不涨，但世界时钟照常往前走。** 这不是 bug，是这个系统最重要的一条规则。

**6. 时间永远不等人。** 停工不暂停时钟、不冻结任务、不跳过夜间事件。一天过去，第二天早上人回来了，进度从昨天停住的地方接着走。

**7. 盖成的那一刻：** `tier` 前进一级、进度归零、工地收起、所有人的 `ToSite` 清空、队伍不动、杂谈记一笔。地图上多出来的东西由 tier 直接驱动。

**8. tier 到 5 即封顶。** 按钮变成「已是王国第一的城」并永久禁用。

### States and Transitions

工地只有两个状态，判断**一律看 `_buildTarget` 这个整数，不看浮点进度**（浮点在 0 附近会被当成「在盖」）。

| 状态 | 进入条件 | 退出条件 | 行为 |
|-------|---------|---------|------|
| **未开工** | 初始；或盖成；或（见 Edge Cases）无法退出 | 玩家按下 Q 且材料够 | 按钮显示下一级的名字和材料数 |
| **施工中** | 按下 Q 且材料够 | 进度 ≥ 1.0 | 绘制工地；进度可见；消耗在场劳动 |
| **停摆（施工中的子状态）** | 施工中，但当前无人在场 | 有人重新满足三条件 | **画面上没有任何区别**——进度条不动，就这样。这是有意的 |

停摆**不是独立状态**，因为它不需要玩家做任何事就能恢复，也不需要任何提示告诉玩家「你被卡住了」。

### 工地的画法：进度必须看得见

工地是全系统唯一一处「进度条不是 UI，是场景」的地方。

| 阶段 | 触发 | 画出来的东西 |
|---|---|---|
| 地基 | 进度 > 0 | 一块夯土色底板，1.8×1.6 |
| 立柱 | 进度 > 0 | 四角木柱，高度 `8 + progress × 34` 像素，**从 0 长到 42** |
| 墙 | 进度 **> 0.3** | 东西两面墙，高度 `(progress − 0.3) / 0.4 × 30` |
| 梁 | 进度 **> 0.7** | 满跨的横梁，高度 `(progress − 0.7) / 0.3 × 26` |
| 料堆 | 进度 > 0 | 工地旁两坨材料 |

**梁在 0.7 才上、墙在 0.3 才起，这不是美术细节，是读数设计。** 一个只会长大的长方形框看着像 loading；一个「先立柱、起墙、上梁」的三段式看着像有人在那儿干活——哪怕人已经走了，架子停在那儿不动也是这个意思。

**人在工地上要做两件看得见的事：** 走到工地（走过去后 `_working = true`，身体上下小幅度抖），以及站在架子的四个角附近。（当前实现的工地人像没做四角分布，全站在中心，是已知待办，见 Open Questions。）

### 视角

45° 俯视 2:1 等距，世界坐标 `(x, y, z)`：

```
sx = (x − y) × 32
sy = (x + y) × 16 − z
```

即 `+x` 朝右下、`+y` 朝左下、`+z` 朝上。绘制顺序按 `(x + y)` 升序排，所以人会走到建筑前面去、被建筑挡住。全部 `_Draw` 手绘，无美术资源。

## Formulas

> 下面所有数值均为**当前实现的实测值**，不是设计许诺。变更有理由时才改，并回写本节。

### 1. 单人干活速度 `WorkRate`

```
base      = 0.010 + Power × 0.00040 + Grit × 0.00028
WorkRate  = base
          × P(性格)        // 莽 1.35 · 傲 0.60 · 贪 1.00
          × D(投入度)      // 肝 1.30 · 随手 1.00 · 挂机 0.55
          × S(状态)        // 磨洋工 0.40 · 心里不静 0.30 · 正常 1.00（可叠乘）
若 AbsentDays > 0 → WorkRate = 0（直接短路，后面的乘数不再算）
```

| 变量 | 类型 | 范围 | 来源 | 说明 |
|------|------|------|------|------|
| `Power` | int | 10–49 | 召唤 roll（`10 + rand(40)`） | 面板第三个数 |
| `Grit` | int | 10–49 | 同上 | 体力，第二根轴的来源 |
| `Speed` | int | 10–49 | 同上 | **不参与建造速度**，只影响走路快慢 |
| `P(性格)` | float | 0.60–1.35 | 性格系统 #3 | 改的是效率，不是许可 |
| `D(投入度)` | float | 0.55–1.30 | 性格系统 #3 | 第二根轴 |
| `S(状态)` | float | 0.12–1.00 | 村庄日常 | 两个惩罚叠乘：`0.40 × 0.30 = 0.12` |

**`base` 的取值范围：0.0168（Power=Grit=10）到 0.0433（Power=Grit=49）。**
常量 `0.010` 是保底——即使属性全零也还有一点产出，所以工地永远不至于完全无解。

**`WorkRate` 的取值范围：**

| 情形 | 计算 | 结果 |
|---|---|---|
| 最好（莽·肝，属性拉满，无惩罚） | 0.0433 × 1.35 × 1.30 | **0.0760** |
| 最坏（傲·挂机，属性最低，磨洋工 + 心里不静） | 0.0168 × 0.60 × 0.55 × 0.40 × 0.30 | **0.000665** |
| 缺席（生病） | 短路 | **0** |

**边界：**
- 属性下界是 10 不是 0（召唤保底：`pow+spd+grt ≥ 60`，每项 `10 + rand(40)`），所以 `base` 实际取不到 0.0168 以下。
- `S` 是乘不是加。磨洋工和心里不静同一天落在同一个人身上，倍率是 0.12 不是 0.7。
- 负数不会出现：所有乘数 > 0。

**示例计算：**

莽 · 肝，`Power=30, Grit=30`，无惩罚
```
base     = 0.010 + 30×0.00040 + 30×0.00028 = 0.010 + 0.012 + 0.0084 = 0.0304
WorkRate = 0.0304 × 1.35 × 1.30 × 1.00 = 0.05335
```

傲 · 挂机，`Power=10, Grit=10`，磨洋工 + 心里不静
```
base     = 0.010 + 0.0040 + 0.0028 = 0.0168
WorkRate = 0.0168 × 0.60 × 0.55 × 0.40 × 0.30 = 0.000665
```

### 2. 工地总速度 `rate`

```
S = { h ∈ 全部村民 : h.ToSite ∧ ¬h.Away ∧ OnDuty(h) }

rate = Σ WorkRate(h),  h ∈ S
若 rate ≤ 0 → 本帧不推进（停工）
```

| 变量 | 类型 | 范围 | 来源 |
|------|------|------|------|
| `S` | set | 0 – 人数 | 三条件同时成立者 |
| `rate` | float | 0 – ∞（现实中 0–约 0.3） | 求和 |

`rate` **没有上限**——20 个人同时在工地就是 20 倍速。这是「人口越多盖得越快」的全部机制，不需要额外的等级加成。

`rate` 每一帧重算，**不做平滑、不做缓存**。人上下线的瞬间速度就变，这样才看得出因果。

### 3. 进度推进

```
若 rate > 0:  progress ← progress + rate × dt
progress 钳制在 [0, 1]
若 progress ≥ 1 → 盖成
```

| 变量 | 类型 | 范围 | 来源 |
|------|------|------|------|
| `dt` | float | 真实秒 / 帧 | 引擎 delta |
| `progress` | float | 0–1 | 累加，**不得写成累加真实时间再换算** |

**注意 `dt` 是真实秒，不是游戏小时。** 一天 = `DayLength = 75` 真实秒（时间与作息 #1 所有）。换算：游戏 1 小时 = 75/24 = 3.125 真实秒。

### 4. 一天的进度（跨系统换算）

一个人每天在工地上花 `H` 游戏小时（`H = PlayHours`，若他被派去跑任务则为 0）：

```
Δprogress_per_day = rate × DayLength × H / 24
```

**示例 A —— 一个莽·肝（WorkRate 0.0534）每天在线 7 小时：**
```
0.0534 × 75 × 7 / 24 = 0.0534 × 21.875 = 1.168  →  一天盖完
```

**示例 B —— 实测锚点。** `--stalltest` 第一次打印 `速度=0.0153`，即一个 WorkRate 0.0153 的人（典型：贪·随手，中等属性），在线约 5 小时：
```
0.0153 × 75 × 5 / 24 = 0.0153 × 15.625 = 0.239  →  4.2 天盖完
```
第二天同一个人打印 `速度=0.0061`：
```
0.0061 / 0.0153 = 0.399 ≈ 0.40  →  正是磨洋工的倍率
```
**这条实测是公式的验证，不是巧合**：第二天变慢的原因就是 `S = 0.40`，而且玩家没有任何一个 UI 元素告诉他「他昨天磨洋工了」——只能从速度掉到原来的四成自己发现。

**示例 C —— 病理下界。** 一个傲·挂机（WorkRate 0.000665）每天在线 3 小时：
```
0.000665 × 75 × 3 / 24 = 0.00624  →  161 天
```
这是理论上的极端值（属性垫底 + 两种惩罚同一天 + 每天只来 3 小时）。**不会真的发生 161 天**，因为封顶 tier 只需要 5 次建造（见下表），而且玩家随时可以换人、把人放进队伍。列出来是为了标定下界：只要不是这种极端组合，一栋建筑是 1–5 天的事。

**升级到满级需要的总工作量：**
5 次建造，每次进度 1.0，合计 5.0。若全程 3 人同时在工地（rate ≈ 0.06），纯工地时间 ≈ `5.0 / (0.06 × 75) = 1.11` 天。但实际不可能连续——**没人能连续在线超过 9 小时**（`PlayHours` 钳制上界 9），所以真实耗时由在线重叠度决定。

### 5. 升级材料成本

```
cost(t) = 30 + t × 25,  t = 0..4
```

| `t` | cost | 累计 |
|---|---|---|
| 0 | 30 | 30 |
| 1 | 55 | 85 |
| 2 | 80 | 165 |
| 3 | 105 | 270 |
| 4 | 130 | **400** |

**满级村庄总共需要 400 材料，且材料只出不进——本系统是纯粹的消耗端。**

材料只有一条来源：副本任务。单次任务的总量 = `Σ(任务基数 / 成功人数) + Σ Power/8`，其中任务基数 14（采石）到 38（旧堡探查）。粗算：**400 材料需要 10–25 趟任务。**

而每趟任务要占走 3–11 个游戏小时，期间这些人**不盖房子**。这就是取舍的全部数学形状：材料和人力的兑换比是固定的，问题是先换哪一样。

## Edge Cases

| 场景 | 实际行为 | 为什么 |
|------|---------|--------|
| **一个人都不在工地** | `rate = 0`，进度冻结，时钟照走。**没有任何提示、没有任何音效、按钮不闪。** | 核心设计。提示了就等于系统替玩家做了判断，「他为什么在这儿」的问题就废了 |
| **推进到 `progress = 1.0` 的那一帧** | 钳到 1.0，立刻盖成、`ToSite` 全清、工地收起 | 不能多盖一帧 |
| **盖成的那一帧正好有人下线** | 顺序无所谓。`rate` 先算完再判完成，所以这一帧的劳动照算 | |
| **`progress` 卡在 `0.9999` 附近不前进** | 不存在。`rate > 0` 时每帧必加，`rate = 0` 时本来就停 | 判完成用 `>= 1.0`，不用 `== 1.0` |
| **材料不够时按 Q** | 按钮本来就是禁用的；即使绕过检查也只是 `Refresh()` 后返回，**不扣材料、不开工地** | |
| **已在施工时按 Q** | 直接 return。**不排队** | 一次只盖一样。这是有意的简单化，见 Open Questions |
| **全村人都被派进了队伍，然后按 Q** | 扣了材料、工地开着、`rate = 0`，**永久停摆** | ⚠️ 见下方「已知软锁」 |
| **队伍里有人当前不在场（离线/生病），想把他撤出队伍** | **撤不掉。** 点他的名字只会往杂谈写一条「XXX 不在村口」。他上线之后才点得掉 | ⚠️ 已知软锁，见下 |
| **任务进行中（`Expending`）时按 Q** | 允许开工。任务照跑，回来的人照常带回材料 | 队伍和工地是两条并行的线，不互相锁 |
| **盖到一半，有人生病缺席一天** | 剩下的人照盖；**进度不会倒退、不会保质过期** | 没有硬失败 |
| **盖到一半，最后一个能盖的人也病了** | 停工。等他回来或别人上线 | |
| **停工跨天** | 次日 `VillageLife.RunDay` 照常跑（打架、想走、磨洋工的判定照常发生） | 事件必须改状态，不能因为工地停了就跳过 |
| **tier = 5 时按 Q** | 按钮禁用，文本变「已是王国第一的城」 | 封顶 |
| **农场地块和土屋重叠** | tier 2 起 `FarmPlot(3.2, 6.0, 3.6, 2.6)` 与升级土屋 `Hut(3, 6)` 视觉上压在一起；工地 `(6.2, 5.6)` 的东南角也擦到地块边缘 | **已知的美术重叠，不影响规则。** 未修是因为它是纯观感问题，不是设计问题 |
| **深度排序把工地和人分开了** | 工地按 `(6.2 + 5.6) = 11.8` 排序，位置固定在村中心偏下 | 工地永远是村子视觉的中心，这样人走进去/走出来的路径最长、最显眼 |

### ⚠️ 已知软锁：扣了材料但没人能盖

`OnUpgrade` 在扣材料的**那一刻**就把所有非队伍成员标为 `ToSite = true`。如果此时队里正好是全体在线人口（或者在队的这几个人当天都跑任务去了），`rate` 恒为 0。而：

- `_buildTarget >= 0` 挡住再次按 Q（不能退款重开）
- 点花名册撤队，对**不在场的人无效**（会走岔路写一条杂谈就返回）

**唯一解法是等在队的人上线后把他撤出队伍。** 这不是死局（人总会回来），但玩家第一次撞上时，看到的是「材料没了、进度不动、又不能重来」，很像 bug。

**这是当前实现的一个真实缺陷，不是设计意图。** 三条候选修法（不选，写进 Open Questions）：材料在开工时才扣但不返还 / 允许「停工中」取消并全额退款 / 撤队按钮对离线者也生效。

## Dependencies

| 系统 | 方向 | 依赖性质 |
|------|------|---------|
| **时间与作息 #1** | 依赖 | 读 `DayLength`（当前 75s/天）、`Hour`、`AbsoluteHour`。**所有节奏问题的源头**——工地速度按真实秒积分，而在场判定按游戏小时走 |
| **性格系统 #3** | 依赖 | 读 `WorkRate`（性格 × 投入度 × 状态的乘积）。本系统**不定义**其中任何一个乘数，只消费结果 |
| **配队与配合 #4** | 依赖 | 读队伍成员集合。队伍里的人 `ToSite = false`；开一次工时**不重置队伍** |
| **任务与副本 #6** | 双向 | 本系统是任务的**竞争者**：队伍里的人出去跑任务就等于从工地抽走人力。不互相调用函数（接口断开：建造只消耗「在场劳动力」，不关心材料从哪来） |
| **杂谈 #11** | 输出 | 开工 / 盖成 / 停摆各写一条；杂谈是停摆现象唯一的读数器 |
| **功能性建筑与依赖网 #7** | 被依赖 | 本系统的 tier 阶梯**到 5 为止**；武器店/服装店/试炼塔/防护罩不在本文件，见下方边界 |
| **村长升级线 #13** | 被依赖 | 「最终成超大城市，成为游戏里最豪华的城市」——本系统是这个终局的一部分，但视野那条线不在这里 |
| **死亡与复活 #10** | 被依赖 | 缺席一天 → `AbsentDays > 0` → `WorkRate = 0` → 工地停摆 |

### 边界：本系统 vs 功能性建筑（#7）

**本系统（#5，村庄基础成长）——判据是「盖完之后地图上多一样东西，而村长能做的事没变」：**
烟囱、水井、围栏、铁匠铺、石板路、旗、更亮一点的土屋、一块能种的地。

**#7（功能性建筑）——判据是「盖完之后村庄多一条产出线或一条新能力」：**
武器店、服装店、试炼塔、防护罩。

**一句话判据：** 这个东西盖完，村长的**下一步动作**变了吗？没变 → #5；变了 → #7。

**这条线上最烫的一个点是铁匠铺。** 它同时踩在两边：
- 它在开发者原话的村庄线里（「然后有井、有围栏、有铁匠铺」），所以它的**外形与出现**属于 #5，是 tier 4。
- 它在 game-brief 的依赖网里是武器的产出者（`副本 → 铁匠铺 → 武器 → 武器店`），一旦它开始**生产东西**，那部分属于 #7。

**当前状态：** 铁匠铺只有外形和炉火，**不产出任何东西**，所以完全属于 #5。分工在 #7 开始动它的那天之前不会越界。这条线写在这里，是为了防止两边各自把它当成自己的。

## Tuning Knobs

> 标 ⚠️ 的属于别的系统，本系统只读不写；改了它要回写对应 GDD。

| 参数 | 当前值 | 安全范围 | 类别 | 调大会怎样 | 调小会怎样 |
|------|--------|---------|------|-----------|-----------|
| `work_base` | 0.010 | 0.005–0.015 | curve | 弱属性的人也有产出，傲·挂机不再那么绝望 | 保底没了，属性差的人精确停工 |
| `work_power` | 0.00040 | 0.0003–0.0006 | curve | 属性更重要，人与人差距更明显 | 人与人拉平，村庄变成平均速度 |
| `work_grit` | 0.00028 | 0.0002–0.0004 | curve | 同上，且更偏向「肝」优先的人占便宜 | |
| `cost_base` | 30 | 20–50 | curve | 开局第一栋变慢，第一次「看得见」的等待变长 | 开局几乎立刻能盖，第一次正反馈来得太早 |
| `cost_step` | 25 | 15–35 | curve | 后期材料压力陡增，400 变 550 | 后期太平，五级台阶失去分量 |
| ⚠️ `slack_mult` | 0.40 | 0.25–0.6 | curve | 磨洋工惩罚变轻，「速度掉四成」这个读数变钝 | 惩罚接近停工，玩家会觉得被阴了 |
| ⚠️ `restless_mult` | 0.30 | 0.2–0.5 | curve | | 与 `slack` 叠乘到 0.09 就基本等于除十 |
| ⚠️ `day_length` | 75 s | 45–180 | gate | 一天变长，工地推进的绝对速度不变（`rate` 按真实秒），但**在线重叠窗口变多** → 实际上盖得更快 | |
| 墙的出现阈值 | 0.30 | 0.20–0.40 | feel | 架子光秃秃的时间更长 | 墙起得太早，「先立柱」那一段没戏 |
| 梁的出现阈值 | 0.70 | 0.60–0.80 | feel | 封顶前的悬停变长 | 上梁太早，工地早早看着像盖好了 |
| 立柱高度 | `8 + p × 34`（→42px） | 30–55px | feel | 长高更醒目，一天的进展一眼看得出 | 进度变化太细微，等于没有进度条 |
| 墙高度系数 | 30 px | 20–40 | feel | | |
| 梁高度系数 | 26 px | 18–34 | feel | | |
| 网格尺寸 `TW` / `TH` | 64 / 32（严格 2:1） | 不可改 | feel | — | 改了就**不是等距**了。这是投影约定，不是旋钮 |
| 工地坐标 | `(6.2, 5.6)` | 不建议动 | feel | | 移到角落会破坏「村子中心有人干活」这个构图 |

**调参的优先级：** 先调 `cost_step`（影响节奏感，最容易感觉出来），再调 `day_length`（影响体感快慢），最后才动 `work_*`（动它会伤到性格系统的可读性）。

## Game Feel

### Feel Reference

《星露谷物语》里**一天只有一小段**能下矿、天黑了就得回家那段时间的手感——不是动作游戏的爽，是「我还有两下没盖完，得赶回去」的紧迫感。**不是**手游放置游戏的「点一下，数字 +1，弹出奖励」。

### 核心感受：延迟回报，但是看得见的延迟

这个系统的反馈周期长（一栋建筑 1–5 天），所以每一步的小反馈必须**密到能撑住**。当前实现里，一天几十秒里唯一在动的是那四根柱子——这是对的，它是这个系统唯一的微反馈源。

- **Weight**：重。工地不是一个可以来回点的菜单，是一件要等的事。
- **Player control**：低，但是**可归因**的低。玩家控制不了「谁今天上线」，但完全控制「谁去工地」这个分配。归因链必须闭合：**速度掉 → 想到有人在磨洋工 → 想到昨天派了谁出去 → 下次留一个人。** 链条断一环，游戏就变成「随机数卡我」。
- **Snap quality**：进度是模拟的、连续的、模拟的——不是二元的。这一点上它故意是 analog。
- **Acceleration model**：完全模拟制。速度没有缓动，人上下线瞬间变化。
- **Failure texture**：**不惩罚。** 停工没有任何代价，除了进度没涨。这一点必须守住——一旦停工有负反馈（扣钱、扣心情、变红），玩家就会开始「囤人不用」，而这个系统存在的全部理由是「他们的劳动看得见」。

### Feel Acceptance Criteria

- [ ] 试玩者看到工地停住时，会说「没人了」而不是「游戏卡了」
- [ ] 试玩者能自己说出「昨天我把人都派出去赚材料了」——**取舍是被发现的，不是被告知的**
- [ ] 试玩者在盖成的瞬间会盯着新建筑看，而不是看一眼数值面板
- [ ] 没有任何试玩者用了「卡了」「卡住」「BUG」这类词描述停工
- [ ] 试玩者不会说出「升级」「建造」「解锁」以外的按钮反馈词——他们会说「井出来了」「旗立起来了」

### 玩家可见文案的硬规矩

**玩家可见文本里不得出现这些词：成功 / 失败 / 获得 / 消耗 / 属性 / 奖励。**

玩家读到的是**事情**，不是**状态**：

| 不写 | 写 |
|------|------|
| 「升级成功！」 | 「盖第四间屋盖成了」 |
| 「获得石料 ×20」 | 「他们从北坡抬回来二十筐石料」 |
| 「建造速度 +15%」 | （什么都不写，让他自己去看柱子长高了没有） |
| 「属性：力量 32」 | 「塞恩 莽 肝 32/18/44」 |

杂谈的样板句（house style）：

> 「盖第四间屋开工了。两个人抬一根梁，谁也没嫌重。」
> 「石板路铺到了村口，旗立起来了」
> 「最后一个也走了。村里静下来。」

杂谈是停摆唯一的读数器。如果杂谈只写氛围不写事实，停工就彻底不可察觉了。

## Acceptance Criteria

### 功能性

- [ ] 按下 Q 且材料足够：材料**立即**扣除，`_buildTarget` 置为 `tier + 1`，地图中心出现工地（地基 + 四根短柱 + 料堆），按钮变为 `正在盖 <名字> NN%` 且禁用
- [ ] 按下 Q 且材料不足 / 已在施工 / 已满级：不扣材料、不开工地、状态不变
- [ ] 开一次工时：队伍成员的 `ToSite` 为 `false`，非队伍成员为 `true`，**队伍本身不被清空**
- [ ] 存在同时满足 `ToSite ∧ ¬Away ∧ 在场` 的人时，进度以 `Σ WorkRate × dt` 推进
- [ ] 不存在这样的人时，`rate = 0`，**进度一个数都不涨**，且世界时钟、天数、任务倒计时、村庄日常全部照常推进
- [ ] 进度达到 1.0 时：tier 前进一级、工地消失、所有 `ToSite` 清空、队伍不变、杂谈新增一条
- [ ] tier 5 时升级按钮永久禁用，文本为「已是王国第一的城」
- [ ] 五个 tier 对应的地图元素全部按 Detailed Design 的表出现，位置正确

### 视觉（可截图核对）

- [ ] `progress = 0.15` 时只有地基 + 四根矮柱，**没有墙**
- [ ] `progress = 0.35` 时出现半高墙
- [ ] `progress = 0.50` 时墙满高，**没有梁**
- [ ] `progress = 0.85` 时出现梁
- [ ] 停工时工地保持在上一个进度的样子，**不闪、不变红、不消失**
- [ ] 招到第一个人之前没有烟囱；招到之后有烟囱；在场时冒烟、离场时烟停
- [ ] 铁匠铺盖成后炉火可见脉动
- [ ] 玩家走动的路线穿过建筑时按 `(x+y)` 正确遮挡

### 体验性（playtest）

- [ ] 试玩者看到停工时第一反应是「人不在」，不是「卡了」
- [ ] 试玩者能自己发现「派出去的人不盖房子」这条取舍，且是在 10 分钟内
- [ ] 盖成的一瞬间，试玩者的注意力在**地图上的新建筑**，不在数值面板
- [ ] 没有任何试玩者要求在停工时给一个提示
- [ ] 试玩者对进度变化的描述是「架子长高了」，不是「进度条涨了」

### 回归守卫（**这条不许被改掉**）

- [ ] `godot --headless --path . -- --selftest --stalltest` 的输出必须复现 game-brief 记录的那组实测：

```
22:28  在村1/3  工地上1人  速度0.0153  进度 4.6%
00:28  在村0/3  工地上0人  速度0.0000  进度 4.7%   ← 人走了
...（冻结）
10:35  在村3/3  工地上1人  速度0.0061  进度 4.8%   ← 人回来了
```

game-brief 的原话：**「M0 已验证的行为：`工地上0人 速度0.0000 进度冻结9小时` 是真的，不是描述。下次改动不要把它改回「不在线也照盖」。」**

- [ ] `0.0061 / 0.0153 ≈ 0.40`，即第二天变慢的原因确实是磨洋工的 `S` 倍率。**若这个比值不再等于 0.40，说明状态乘数被改坏了**

### 通用

- [ ] 所有数值（`0.010` / `0.00040` / `0.00028` / `30` / `25` / 三个阶段阈值 / 高度系数）都在外部数据文件中，无硬编码
- [ ] `TickBuild` 的更新耗时 < 0.2 ms（N 人规模）
- [ ] 工地绘制 < 0.5 ms
- [ ] `SiteX / SiteY`、`MaxTier`、升级名列表是唯一的定义点，`VillageView` 与 `Main` 之间没有重复的常量
