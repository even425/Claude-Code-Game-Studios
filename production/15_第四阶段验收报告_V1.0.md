## 6. 兼容性 / 存档风险

| 项 | 结论 |
|---|---|
| 存档版本 | 0.3 → **0.4**；0.3 及更早**整份拒绝**，不写迁移器（沿用 I11 与项目惯例）。未测试「0.4 档被旧版本读取」（项目不支持降级） |
| 原子性 | 存档写入走 `SavePort` 临时文件 + `File.Move`；读档先 `SaveValidator` 全量校验，任一失败整份拒绝，不做部分恢复 |
| 幂等键空间 | `AppliedPurchaseKeys` 与 `AppliedTradeKeys` **分开**；后者留给尚未接线的英雄↔英雄交易，当前恒为空 |
| 价格表变更 | 读档恢复摊位单价，**不**按 `PriceBook` 重验；价格表变化不会让旧档整份失败 |
| 每日购物闸门 | `DailyShoppingLastRunDay` 比设计清单多存一项：不存它，读档后同一天会对未成交者再试一次 |

## 7. 遗留事项（待开发者确认后转任务）

| # | 事项 | 影响 |
|---|---|---|
| R-01 | 正式物品来源（副本战利品）与奖励归属规则未定 | 当前只有 `--grant` 与 `--shop` 的测试配给；正常游戏里没有物品进入英雄背包 |
| R-02 | 无正式购买 UI / 摊位库存面板 | 玩家只能看花名册金币与背包；买卖仍由自主购物驱动，手动交易只有 `--trade` 调试入口 |
| R-03 | 英雄可能抽到自己的摊位（v1 允许抽，`BuyFromStall` 以 `SameHero` 拒绝） | M5 只补了调试原因，未改抽摊规则；价高且村抽 &gt; 0 时自买自卖会损失村抽 |
| R-04 | 摊位库存/单价不在界面显示 | 核查库存仍靠 `--shop` / `--save` 输出；设计文档明确本轮**不**做经济大盘 |
| R-05 | 价格 / 掉落 / 稀有度仍是占位（T-007） | `PriceBook.Default` 3 个价格与 5% 村抽均为占位；单价 &lt; 20 时村抽为 0，界面显示「得全款」 |
| R-06 | 背包摘要最多显示 2 种物品 | 左栏 248 像素；更多种类只显示 `+N`，长物品名可能被裁 |
| R-07 | `--econlog` / `--shop` 明细是调试输出 | 不进杂谈（避免 37 人/天刷屏）；正式反馈若需要「购物未成」提示，需另定设计 |
