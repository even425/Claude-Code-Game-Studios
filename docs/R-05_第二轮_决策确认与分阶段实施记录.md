## 2. 需要写入决策记录的数值边界

### 2.1 战斗成功率

当前副本要求连续赢得 3 场战斗，单场胜率为 `p` 时，理论副本成功率为 `p³`。本轮采用 `p = 0.65`，理论成功率为：

`0.65³ = 0.274625`，约为 27.46%。

战斗与日常活动目前共享全局随机数流，因此调整该参数会改变后续随机调用序列。此影响必须列入回归说明；不要把该调整描述成仅影响战斗而不影响其他模拟结果。

### 2.2 村庄税额余数

每笔交易税额按 5% 计算，并将不足 1 金币的部分以整数余数累计。建议使用整数最小单位，避免浮点累计：

```text
taxUnits    = totalAmount × 5
accumulated = carry + taxUnits
villageCut  = accumulated / 100
newCarry    = accumulated % 100
sellerNet   = totalAmount - villageCut
```

该计算表达的是 5% 税额的百分之一金币单位；实现时必须先确认 `totalAmount` 的单位与范围，使用 checked 运算或等效的显式溢出检查。每笔交易应满足 `sellerNet + villageCut == totalAmount`；累计税款与余数应满足守恒关系。

**结算原子性要求：** 幂等请求被拒绝时不得改变余数；任何溢出或结算失败不得留下只写入金库、却未完成交易的部分状态。提交顺序应结合现有交易写入路径设计并测试，不能只依赖“某一步通常不会抛异常”的假设。

### 2.3 存档迁移边界

- 新版本使用 `SaveVersion 0.5`，保存村庄税额余数。
- 旧 `v0.4` 存档按已确认方案拒绝读取；错误信息应清晰说明版本不受支持。
- 不通过复用 `Resources` 等无关字段藏放余数。
- 增加 v0.5 保存/加载往返、边界余数、交易后存档读档、幂等重放以及 v0.4 拒绝读取测试。
