## 0. 结论摘要

> ### 一句话：**金币是一个「只有入口、没有出口」的封闭系统，每笔交易漏 5% 进一个花不掉的池子。**
>
> - 金币**创建**只有一处：开局每人 100 金（`Main.cs:521-525`），此后**再无任何来源**
> - 金币**转移**只有一条路径：摊位交易（`StallService.TryBuy`），**每笔强制抽 5% 进村庄金库**
> - 金币**销毁**：**零处** —— 没有摊税之外的金币消失路径
> - 村庄金库**支出**：**零处** —— 已实现的升级玩法扣的是**材料**（`OnUpgrade`），不是金币
>
> **⇒ 守恒律**（恒成立，可作回归断言）：
>
> ```
> Σ(英雄金币) + 村金库余额 + 税额余数 = 初始池（开局英雄数 × 100）
> ```
>
> 这不是「经济会慢慢失衡」，而是**算术上必然**：没有新钱进来，钱只会从可流通池挪进不可流通池。

## 2. 已实现机制清单

### 2.1 金币的**创建**（2 处，其中只有 1 处是「新增」）

| # | 位置 | 内容 | 状态 |
|---|---|---|---|
| 1 | `src/Main.cs:521-525` | `foreach (var h in _heroes) h.TryAddResource(gold, 100);` —— 开局每人 100 金 | ✅ 已实现（**唯一真实来源**） |
| 2 | `src/Application/StallService.cs:328` | `sellerHero.Wallet.TryAdd(Gold, sellerNet)` —— 卖家收款 | ✅ 已实现（**转移**，不是创造：见 §2.2） |

> **副本奖励不是金币。** `Main.cs:1415` `_pendingRewardResource = MaterialsId.Value` ——
> 副本成功发的是**村庄材料桶** + **英雄个人战利品物品**（`RewardsFor`，`Main.cs:259-281`）。
> **没有任何一条路径给英雄发金币。**
>
> **采集任务也不是金币。** `Main.cs:1220` `Deposit(total)` → `MaterialsId`（村庄材料池）。

### 2.2 金币的**转移**（1 条路径）

`src/Application/StallService.cs:328-350`（I15 四步提交）：

```
买家钱包  −totalAmount
摊主钱包  +sellerNet
村金库    +villageCut          （villageCut + sellerNet == totalAmount）
```

**⇒ 英雄之间的每一次价值转移，95% 在英雄之间移动、5% 永久离开流通池。**

> **M2 的「英雄 ↔ 英雄」直接交易路径是预留未接线的死代码**：
> `src/Domain/Trade/Trade.cs:242` 的 `Trade.Apply` 在生产路径上**无调用方**
> （`StallService` 明确不走它 —— 见 `StallService.cs:247-251` 的说明；
> `Settlement.ApplyTrade` 需要 `ITradeSettler`，而它是 `null` —— `Settlement.cs:160/199-203`）。
>
> **⇒ 不存在「绕过摊位、不交 5%」的交易路径。** 每一笔英雄间的价值转移**必须**过摊位。

### 2.3 金币的**沉淀**（1 处，唯一写点）

`src/Application/StallService.cs:344-347`：

```csharp
if (villageCut > 0) { _village.Add(Gold, villageCut); }
```

`Main.VillageGold` 的属性注释也写明「**唯一写者**是 `StallService.BuyFromStall` 的村抽结算」
（`Main.cs:366-375`）。**读档恢复**（`Main.cs:3376-3388`）是「找回」不是「新增」。

### 2.4 金币的**销毁**：**零处**；村庄金库的**支出**：**零处**

全仓 `Village.TrySpend` 的写点只有 4 个，**没有一个花的是金币**：

| 位置 | 扣的是什么 | 是不是生产路径 |
|---|---|---|
| `Main.cs:323`（`ApplyWrites`） | 结算增量的资源（**材料**） | ✅ 是 |
| `Main.cs:1542`（`OnUpgrade`） | **`MaterialsId`（材料）** | ✅ 是 |
| `Main.cs:3381/3388`（读档恢复） | 按存档差额 | ✅ 是 |
| `Main.cs:3645`（`--save` 自检） | 材料 | ❌ 仅自检 |

> ⚠️ **`OnUpgrade` 的注释有误导性**：`Main.cs:1541` 写着「**钱变材料**，剩下的由人去干」，
> 但它扣的是 **`MaterialsId`（材料）**，**不是金币**。
> **村庄升级花的是材料，金币一分没花。**
> → **金库里的钱在当前已实现的玩法里花不出去。**
>
> 🔴 这一点与 R-05 二轮的表述「村库的钱只有玩家手动升级村庄才花得出去」**不符** ——
> 升级花的是**材料**。D-052 §6 与 `28` §5.2 的那处表述**需要更正**（见 §7 遗留 B）。

### 2.5 物品 → 金币的间接路径：**断在第一环**

理论上的回流链是「工作/副本产出材料 → 进背包 → 摆摊 → 卖 → 得到金币」。逐环核对：

| 环 | 代码 | 状态 |
|---|---|---|
| ① 工作产出材料 → 英雄背包 | `Main.cs:1171-1220`：`total += q` → `Deposit(total)` → **村庄材料池**；`q` **不进任何英雄的背包** | 🔴 **断** |
| ①' 工作中的「私吞」 | `Main.cs:1178-1194`：`q -= kept; h.Pocketed += kept;` —— 只加一个 **int 计数器**，材料**既不给村庄也不给英雄**（**凭空销毁**） | 🔴 **断**（且材料被销毁） |
| ② 副本产出 → 英雄背包 | `RewardsFor` → `AddItemGrant` → `ItemGrantService` → 英雄个人背包 | ✅ 通（**唯一的物品来源**） |
| ③ 背包 → 摊位 | `StallService.PlaceStall` | ✅ 通 |
| ④ 摊位 → 金币 | `StallService.TryBuy` | ✅ 通（**但抽 5%**） |

> **⇒ 英雄背包里只有两样东西：副本战利品（②）与买来的（④）。**
> 而④要花钱买，②要靠副本掉 —— **「赚钱」的唯一路径就是「卖掉副本掉的东西」**。
>
> **这条链是有可能构成循环的**（副本 → 材料 → 卖 → 钱 → 买更多材料 → …），
> 但它被**两个机制**卡住：
> ① **材料供给受副本成功率限制**（27.7%），且**材料桶归村庄**、不进背包；
> ② 每转手一次抽 5%，而**没有任何金币来源能补回抽走的 5%**。

### 2.6 交易决策：钱不够 → **直接放弃**（无替代来源）

`src/Application/HeroBehaviorService.cs`（D-053 后）：

```
买量 = min(摊位库存, 余额 ÷ 单价, 背包余量)
买不成 → SkipReason.NotEnoughGold → 当天不成交、不写 LastShoppingDay
```

实测占比 **83.0%**（R-05 三轮，两样本合并 2109 条未成记录）——
**钱不够是压倒性的未成原因**，且**没有任何机制能让英雄重新有钱**（§2.1）。

## 3. 资金流向图

```
                        ┌──────────────────────────────────────────┐
                        │  开局：Main.cs:521-525  每人 100 金       │
                        │  （3 英雄 = 300 金；无差异、无后续来源）    │
                        └───────────────┬──────────────────────────┘
                                        │
                                        ▼
   ┌────────────────────────────────────────────────────────────────────┐
   │  可流通池：Σ(英雄钱包)                                              │
   └───────┬────────────────────────────────────────────┬───────────────┘
           │                                            │
           │ ① 摆摊卖材料（物品来自副本战利品）           │ ② 买摊
           │    货物进摊位库存                            │    货物进买家背包
           │                                            │
           │                            ③ StallService.TryBuy（唯一转移路径）│
           │                                 │                          │
           │                                 ├─ 摊主 +sellerNet (95%) ───┘ (回可流通池)
           │                                 │
           │                                 └─ 村金库 +villageCut (5%)
           ▼                                                    ▼
   ┌──────────────────────────┐            ┌──────────────────────────────────┐
   │ 副本战利品（唯一物品源） │            │  村庄金库（不可流通）              │
   │ 材料桶 → 归村庄，不进背包│            │  支出路径：0 处                   │
   │ 「私吞」材料 → 凭空销毁  │            │  唯一写点：StallService.cs:346    │
   └──────────────────────────┘            └──────────────────────────────────┘
                                                    │
                                                    ▼
                                          💸 永久沉淀（无出口）
```

**读图要点**

- **左边没有箭头指回右边** —— 没有任何机制给**英雄**补金币。
- **右边的箭头只进不出** —— 村庄金库是**终点**，不是中转站。
- **「金币在英雄之间转移」≠「金币进入了新的经济循环」**：
  95% 的转移只是**换了个持有人**（同一池子里的钱换位置），
  只有 5% 真正离开了池子，而那 5% 去了一个**花不掉**的地方。
- **「金币进入村庄金库」≠「金币已经回流」**：
  回流要求**金库 → 某个可流通池**有一条**已实现**的路径。**当前没有。**

## 4. 守恒律与实测：300 金都去哪了

### 4.1 守恒律

由 §2.1–§2.4 可推出（每一笔交易 `total = sellerNet + villageCut`，无销毁路径）：

```
Σ(英雄金币) + 村金库余额 + 税额余数 = 初始池 = 英雄数 × 100
```

**⇒ 村金库余额就是「已经从可流通池抽走的钱」。** 这条式子可以直接当回归断言用。

### 4.2 四份采集样本的实测（各 1000 模拟天）

| 样本 | 成交金额 | 村金库 | 税额余数 | **第 1000 天英雄合计** | 最后一笔成交 |
|---|---|---|---|---|---|
| **N1（新代码）** | 5880 金 | 294 金 | 0 | **6.00 金** | **第 219 天** |
| **N2（新代码）** | 5961 金 | 298 金 | 0.05 金 | **1.95 金** | **第 261 天** |
| O1（旧代码） | 3280 金 | 164 金 | 0 | 136.00 金 | 第 990 天 |
| O2（旧代码） | 1422 金 | 71 金 | 0.10 金 | 228.90 金 | 第 998 天 |

> **N2 的 1.95 金**：3 个英雄合计不到 2 金 —— **连一次木料（3 金）都买不起**。
> 经济不是「放缓」，是**死亡**。
>
> **旧代码也没好到哪去**：O1 结束时英雄还剩 136 金，但成交笔数已经长期低迷
> （第 100 天后只有 10–70 笔/百天），且最后一笔在第 990 天 —— **同样没有退出机制**。
> **货币沉淀在旧代码里就存在**，D-053 只是把它**提前**了。

### 4.3 停摆的因果链（可逐环核对）

```
村抽 5% 单向沉淀 → 英雄可流通池逐日减少
    → 余额 ÷ 单价 能买的份数减少（钱不够占未成 83.0%）
    → 成交额下降 → 但每次成交仍抽 5%
    → 池子见底 → 成交归零 → 此后再无新钱 → 永久停摆
```

**关键点**：停摆后**没有任何东西能让它恢复** —— 因为恢复需要**新增金币**，
而 §2.1 证明**新增金币的路径不存在**。
