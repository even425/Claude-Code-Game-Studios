## 2. 当前目标：第四阶段收口 —— 只差数值

第四阶段的实施顺序是「物品来源 → 摆摊与购买 → 英雄自主购物 → 存档幂等 → 可观察性 → **完整验收**」，
前五项**都完成了**；最后一项的前置就是**数值**。

`34` 阶段 5 原文：**评审掉落权重 / 掉落次数 / 基础价格 / 稀有度映射**，
前置条件（D-054 已确认 + 采集显示经济不再停摆）**已满足**。

⇒ 逐项见 `production/37_R-05阶段5_数值评审清单_V1.0.md`（含「现在是什么 / 定了之后我做什么」）。

**最要紧的三个**：基础价格（P-14）· 伤害/命中/冷却公式（T-004）· 队伍人数上限（P-10）。

## 3. 为什么给不出「还差 N 周」

**「开发完成」现在指向哪个集合，还没有定义。**

- 仓库里**没有第五/第六阶段计划** —— 第四阶段是最后一个有计划文档的阶段。
- 开发计划 §六 明确把「完整召唤池 / 完整的城市成长与全部建筑和大事件 /
  大量英雄与多个副本与装备数值 / 完整本土剧情 / 复杂行为链」列为
  「**不进入第一阶段强制验收**」—— 它们**仍是整体设计的一部分**，不是被删除。

⇒ 换句话说：**范围本身待定**。范围一改，工期就改。
⇒ 所以本文给的是**按基线逐模块的完成度**，而不是一个工时承诺。

## 5. 分工：什么不占你的时间

| 我这边（不占你时间） | 你那边（每轮都要） |
|---|---|
| 守卫与变异矩阵、参数台账、文档一致性、CI 与导出、证据留存 | **所有规则、数值、内容**：战斗公式、掉落与价格、稀有度、队伍上限、建筑用途、召唤池、行为链、大事件 |
| 每次改动的编译 / 测试 / 真机自检 / 回归 | 每一轮的方向（做什么、做到什么程度） |
| 把结论写进 `07`（决策落文档）与 `06`（验收计划） | 阶段验收 |

⇒ **最大的杠杆在你那边**：技术侧已就位的部分（输入通道、标定工具、验收断言形态）
都能在**拿到数之后**很快落地；而**规则本身定不出来的时候，代码侧无事可做**。

📌 **要拍板的东西已经打包好了**：`production/39_待拍板事项打包_V1.0.md`
把**卡得最狠的三个规则域**（T-004 战斗公式的五个子决定 / 九种建筑 / §9 行为链）
压成**能一次答完**的表，并给出「**最小可回答集**」—— 只答 4 个数就能开工一轮。
